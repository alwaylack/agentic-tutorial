# 第 02 章 · 模型接入与字符串路由

使用模型的章节需要自备支持工具调用的模型服务与 API Key（可为任意 OpenAI 兼容端点），运行会产生费用。

## 机制与设计选择

`create_deep_agent` 的 model 可以是聊天模型实例，也可以是 "provider:model" 字符串，由 LangChain 的 init_chat_model 路由。Deep Agents 官方文档示例常用字符串写法（如 openai:gpt-5.5），实际项目里显式传入模型对象更可控（超时、重试、tag）。

## 示例

```python
import os
from langchain_openai import ChatOpenAI

model = ChatOpenAI(
    model=os.environ["MODEL_ID"],
    api_key=os.environ["DEEPAGENT_API_KEY"],
    base_url=os.environ.get("DEEPAGENT_BASE_URL", "https://api.openai.com/v1"),
)

from deepagents import create_deep_agent

agent = create_deep_agent(
    model=model,
    system_prompt="Answer in one short paragraph.",
)
result = agent.invoke({"messages": [{"role": "user", "content": "Say exactly: ready"}]})
print(result["messages"][-1].content)
```

### 运行与验收

配置三个环境变量后运行。验收：输出是一句简短确认；没有文件写入与外部副作用。字符串路由需要对应 Provider 包已安装；对象形式只需要该 Provider 客户端。

## 容易踩的坑

不要在生产里写死模型名：升级与回滚都应通过配置切换。字符串路由的错误往往发生在调用时刻，排查时要同时检查环境变量与 Provider 客户端版本。
