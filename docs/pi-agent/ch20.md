# 第 20 章 · 综合实战：生产级 Agent 服务

> 本章目标：把编码助手封装成 HTTP 服务，补齐错误恢复、日志监控、成本控制等生产要素，形成可部署的完整方案。

## 20.1 生产级服务的差距清单

第 19 章的 REPL 是单用户玩具。变成生产服务还差这些：

| 缺口 | 方案 |
|---|---|
| 并发隔离 | 每请求独立 Agent 实例 + sessionId |
| 错误恢复 | stopReason 检查 + continue() 重试 |
| 可观测 | 结构化日志、事件埋点 |
| 成本控制 | token 用量统计与限额 |
| 部署形态 | 常驻进程 / Serverless 权衡 |

## 20.2 HTTP 服务封装

用 Express 把 Agent 暴露为 API，SSE 流式返回：

```typescript
import express from 'express';
import { Agent } from '@earendil-works/pi-agent-core';

const app = express();
app.use(express.json());

app.post('/api/chat', async (req, res) => {
  const { sessionId, message } = req.body as { sessionId: string; message: string };
  if (!sessionId || !message) {
    return res.status(400).json({ error: 'sessionId 与 message 必填' });
  }

  // 每个会话一个 Agent：并发互不干扰
  const agent = await getOrCreateAgent(sessionId);

  // SSE 头：流式推送
  res.setHeader('Content-Type', 'text/event-stream');
  res.setHeader('Cache-Control', 'no-cache');

  const unsubscribe = agent.subscribe((event) => {
    if (event.type === 'message_update' &&
        event.assistantMessageEvent.type === 'text_delta') {
      res.write(`data: ${JSON.stringify({ delta: event.assistantMessageEvent.delta })}\n\n`);
    }
    if (event.type === 'agent_end') {
      res.write('data: [DONE]\n\n');
      res.end();
    }
  });

  try {
    await agent.prompt(message);
  } finally {
    unsubscribe();
    if (!res.writableEnded) res.end(); // 兜底关闭
  }
});

app.listen(3000);
```

## 20.3 错误恢复策略

利用第 13 章的知识做三层防御：

```typescript
// 第一层：可重试错误自动 continue()
async function promptWithRetry(agent: Agent, msg: string, maxRetry = 2) {
  for (let i = 0; ; i++) {
    if (i === 0) await agent.prompt(msg);
    else {
      console.warn(`第 ${i} 次重试（continue）`);
      await agent.continue(); // 从当前状态恢复，不重复计费整段上下文
    }

    const last = lastAssistant(agent.state.messages)!;
    if (last.stopReason !== 'error') return last;   // 成功
    if (i >= maxRetry) throw new Error(last.errorMessage); // 放弃
    await sleep(1000 * 2 ** i); // 指数退避：1s, 2s
  }
}

// 第二层：beforeToolCall 拦截危险操作，失败不污染上下文
// 第三层：全局 uncaughtException/unhandledRejection 记录后优雅退出
process.on('unhandledRejection', (err) => {
  logger.error({ err }, 'unhandled rejection');
});
```

## 20.4 日志与监控

结构化日志记录关键事件，而非散落各处的 console.log：

```typescript
import pino from 'pino';
const logger = pino({ level: 'info' });

agent.subscribe((event) => {
  switch (event.type) {
    case 'turn_end':
      // usage 含输入/输出 token 数，是成本统计的原始数据
      logger.info({
        sessionId: agent.sessionId,
        stopReason: event.message?.stopReason,
        usage: event.message?.usage,
      }, 'turn completed');
      break;
    case 'tool_execution_end':
      logger.info({ toolCallId: event.toolCallId }, 'tool done');
      break;
    case 'error':
      logger.error({ reason: (event as any).reason }, 'stream error');
      break;
  }
});
```

监控指标建议至少覆盖四个黄金信号：**请求成功率**（按 stopReason 分类）、**P95 延迟**（首 token + 总时长）、**每请求 token 成本**、**工具调用失败率**。

## 20.5 部署要点

最后是部署形态的选择：

- **常驻容器（推荐起步）**——Docker 里跑 Node 进程，内存中的 Agent 会话天然可用；配合 SQLite 后端实现重启恢复；
- **Serverless 注意事项**——函数实例可能随时回收，必须把 Context 序列化到外部存储（第 18 章），每次冷启动重建 Agent；
- **优雅停机**——收到 SIGTERM 后停止接新请求，`await Promise.all(runningAgents.map(a => a.waitForIdle()))` 再退出；
- **密钥管理**——API Key 走平台的 secret 管理（环境变量注入），绝不进代码仓库；
- **限流**——在网关层按 sessionId 限流，防止单个用户打爆预算。

```typescript
// 优雅停机示例
const inflight = new Set<Agent>();
process.on('SIGTERM', async () => {
  server.close(); // 停止接受新连接
  await Promise.all([...inflight].map((a) => a.waitForIdle()));
  process.exit(0);
});
```

## 本章小结

- 并发隔离 = 每会话独立 Agent + 统一 sessionId；
- 错误恢复三层：指数退避 continue() 重试 → beforeToolCall 风控 → 全局兜底；
- 结构化日志以 turn_end 的 usage/stopReason 为核心数据源；
- 四个必监控指标：成功率、P95 延迟、token 成本、工具失败率；
- 部署首选常驻容器；Serverless 必须外置序列化上下文；优雅停机靠 waitForIdle()。
