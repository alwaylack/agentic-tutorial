# 第 22 章 · 可观测性：Telemetry 与 Span 追踪

> 本章目标：掌握 `@earendil-works/pi-telemetry` 的核心概念——span、attribute、event、status、context，学会在 Agent 代码中插桩并桥接 OpenTelemetry/Sentry，让每一次模型调用与工具执行都清晰可查。

## 22.1 为什么 Agent 需要可观测性

传统后端服务有日志和指标，但 Agent 系统引入了新的可观测性挑战：

- **非确定性**：同样的输入可能产生不同的工具调用序列；
- **长链路**：一次对话可能跨越多个 span（模型调用 → 工具执行 → 子代理委派）；
- **成本敏感**：每个 span 对应真实 token 消耗，需要按 span 追踪花费。

`@earendil-works/pi-telemetry` 提供了一套供应商中性的可观测性契约，让你用同一套接口对接 OpenTelemetry、Sentry、日志系统或内存快照。

## 22.2 核心概念：Span 树

一个 `Span` 代表一次有边界的操作，从开始到结束记录时间戳。Span 之间可以嵌套形成树：

```typescript
// 概念示意：span 树结构
example.session.start                      ← 会话开始
├─ example.model.call (duration: 1200ms)   ← LLM 调用
│  ├─ attributes: { model: "claude-sonnet", tokens: 500 }
│  └─ event: example.model.cache_hit=false
├─ example.tool.execute (duration: 340ms)   ← 工具执行
│  └─ attributes: { tool: "query_db", rows: 12 }
└─ example.session.end                      ← 会话结束
```

核心概念速查：

| 概念 | 说明 |
|---|---|
| **Span** | 一次操作的时间记录，可嵌套 |
| **Attribute** | 附加在 span 上的命名事实（`provider: "openai"`） |
| **Event** | span 内的时间点标记（`retry.scheduled`） |
| **Status** | 操作结果：`ok` 或 `error { name, message }` |
| **Context** | 携带当前 span 引用，用于创建子 span |

## 22.3 核心 API：TelemetryContext

所有可观测性操作都通过 `TelemetryContext` 发起。`startSpan` 是核心方法：

```typescript
import {
  NOOP_TELEMETRY_CONTEXT,
  type TelemetryContext,
} from '@earendil-works/pi-telemetry'

async function runAgent(
  prompt: string,
  telemetryContext: TelemetryContext = NOOP_TELEMETRY_CONTEXT,
) {
  // 开启一个根 span 包裹整个调用
  return telemetryContext.startSpan(
    { name: 'agent.run' },
    async (span) => {
      span.setAttributes({ 'input.length': prompt.length })
      
      // 子 span：模型调用
      const result = await span.startSpan(
        { name: 'agent.llm.call' },
        async (llmSpan) => {
          llmSpan.setAttributes({ model: 'claude-sonnet-4-6' })
          // ... 实际模型调用
          return { text: '响应文本' }
        }
      )
      
      // 子 span：工具执行
      const toolResult = await span.startSpan(
        { name: 'agent.tool.execute' },
        async (toolSpan) => {
          toolSpan.addEvent('tool.started', { tool: 'search' })
          // ... 工具调用
          toolSpan.setAttributes({ rows_fetched: 12 })
          return { ok: true }
        }
      )
      
      span.setStatus({ status: 'ok' })
      return { result, toolResult }
    }
  )
}
```

关键点：
- `NOOP_TELEMETRY_CONTEXT` 是无副作用的空实现，适合关闭遥测的生产环境；
- `startSpan` 接收 callback，callback 内的 `span` 自动成为子 span 的父上下文；
- `setAttributes` 记录事实，`addEvent` 记录时刻，`setStatus` 标记结果。

## 22.4 InMemoryTelemetryContext：本地诊断

开发调试时，使用 `InMemoryTelemetryContext` 把 span 收集到内存数组，断言内容而非依赖外部后端：

```typescript
import { InMemoryTelemetryContext } from '@earendil-works/pi-telemetry'

const ctx = new InMemoryTelemetryContext()

await runAgent('查询订单 #12345', ctx)

// 获取所有 span
const spans = ctx.getSpans()
console.log(spans[0].name)        // 'agent.run'
console.log(spans[1].attributes)  // { model: 'claude-sonnet-4-6' }
console.log(spans[2].status)      // { status: 'ok' }

// 断言
expect(spans.some(s => s.name === 'agent.llm.call')).toBe(true)
expect(spans.find(s => s.name === 'agent.tool.execute')?.attributes)
  .toMatchObject({ tool: 'search', rows_fetched: 12 })
```

`InMemoryTelemetryContext` 不提供导出器，仅做本地诊断与单元测试。

## 22.5 适配器模式：桥接到 OpenTelemetry

生产环境需要把 span 导出到后端。定义一个适配器实现 `TelemetryContext` 接口：

```typescript
import { tracer, SpanStatusCode } from '@opentelemetry/api'
import { type TelemetryContext, type TelemetrySpan } from '@earendil-works/pi-telemetry'

class OtelTelemetryAdapter implements TelemetryContext {
  private parentSpan?: import('@opentelemetry/api').Span

  constructor(parentSpan?: import('@opentelemetry/api').Span) {
    this.parentSpan = parentSpan
  }

  async startSpan<T>(
    options: { name: string; attributes?: Record<string, unknown> },
    callback: (span: TelemetrySpan) => Promise<T>,
  ): Promise<T> {
    const otelSpan = this.parentSpan
      ? this.parentSpan.startSpan(options.name)
      : tracer.startSpan(options.name)

    if (options.attributes) {
      otelSpan.setAttributes(options.attributes)
    }

    // 包装为 pi-telemetry 风格的 span
    const piSpan: TelemetrySpan = {
      startSpan: async (subOpts, subCb) => {
        const adapter = new OtelTelemetryAdapter(otelSpan)
        return callback(adapter as any)
      },
      addEvent: (name, attrs) => otelSpan.addEvent(name, attrs ?? {}),
      setAttributes: (attrs) => otelSpan.setAttributes(attrs),
      setStatus: (status) => {
        if (status.status === 'error') {
          otelSpan.setStatus({
            code: SpanStatusCode.ERROR,
            message: status.error?.message,
          })
        }
      },
    }

    try {
      const result = await callback(piSpan)
      otelSpan.end()
      return result
    } catch (err) {
      otelSpan.recordException(err as Error)
      otelSpan.setStatus({ code: SpanStatusCode.ERROR, message: (err as Error).message })
      otelSpan.end()
      throw err
    }
  }
}
```

同一份 Agent 代码，切换适配器即可：

```typescript
// 本地调试
const ctx = new InMemoryTelemetryContext()
// 生产环境
const ctx = new OtelTelemetryAdapter(rootSpan)
```

## 22.6 Typed Schemas：类型安全的数据契约

`startAttributes` 和 `endAttributes` 允许定义带类型的 schema，TypeScript 会推断精确类型：

```typescript
import { defineSchema, type InferredAttributes } from '@earendil-works/pi-telemetry'

const modelCallSchema = defineSchema({
  startAttributes: {
    model: { type: 'string', description: 'LLM 模型标识' },
    provider: { type: 'string', enum: ['openai', 'anthropic', 'deepseek'] },
    maxTokens: { type: 'number' },
  },
  endAttributes: {
    status: { type: 'string', enum: ['ok', 'error', 'timeout'] },
    tokensUsed: { type: 'number' },
    durationMs: { type: 'number' },
  },
})

type ModelCallAttrs = InferredAttributes<typeof modelCallSchema>
//   ^? { model: string; provider: 'openai'|'anthropic'|'deepseek'; ... }
```

Typed Schema 让 span 内容自文档化，且避免拼写错误。

## 22.7 实战：在 Agent 中插桩

以第 20 章的测试智能体为例，在三个关键节点插入 span：

```typescript
import { Agent } from '@earendil-works/pi-agent-core'
import { createModels } from '@earendil-works/pi-ai'
import { NOOP_TELEMETRY_CONTEXT, InMemoryTelemetryContext } from '@earendil-works/pi-telemetry'
import { anthropicProvider } from '@earendil-works/pi-ai/providers/anthropic'

// 创建带遥测的 agent
const telemetry = new InMemoryTelemetryContext()

const agent = new Agent({
  initialState: {
    systemPrompt: '你是一个测试分析助手',
    model: createModels().getModel('anthropic', 'claude-sonnet-4-6')!,
    streamFn: createModels().streamSimple.bind(createModels()),
  },
  telemetryContext: telemetry,
})

// 订阅事件流
agent.subscribe((event) => {
  if (event.type === 'message_update' && event.assistantMessageEvent?.type === 'text_delta') {
    process.stdout.write(event.assistantMessageEvent.delta)
  }
})

// 运行并收集遥测
const result = await agent.prompt('分析这份测试报告')

// 检查 span 树
const spans = telemetry.getSpans()
for (const span of spans) {
  console.log(`- ${span.name}`, span.attributes, span.status)
}
```

运行后你会看到类似输出：

```
- agent.prompt { input_length: 280 } { status: 'ok' }
- agent.llm.stream { model: 'claude-sonnet-4-6', tokens_estimated: 1200 } { status: 'ok' }
- agent.tool.execute { tool: 'read_file' } { status: 'ok', rows: 42 }
- agent.llm.stream { model: 'claude-sonnet-4-6', tokens_estimated: 800 } { status: 'ok' }
```

## 本章小结

- Span 是可观测性的基本单元，形成树形结构；
- `TelemetryContext` 抽象了后端差异，`NOOP` 适配关闭遥测，`InMemory` 适配本地诊断；
- Typed Schema 让属性类型安全、自文档化；
- 插桩只需在关键路径调用 `startSpan`，不改变业务逻辑。
