# 第 19 章 · 实战：构建编码助手 CLI

> 本章目标：综合运用工具、流式输出与会话持久化，从零实现一个可交互的迷你编码助手 REPL。

## 19.1 目标与架构

我们要做的助手具备：读文件、写文件两个工具；流式渲染回复；多轮对话记忆。整体架构：

```text
┌─────────────┐   prompt    ┌────────┐  streamSimple ┌─────────┐
│  REPL 循环   │───────────▶│ Agent  │──────────────▶│ pi-ai   │
│ (readline)  │◀───────────│        │◀──────────────│ Provider│
└─────────────┘   events    └───┬────┘               └─────────┘
                                │ tool_execution
                          ┌─────▼─────┐
                          │ read/write│  ← 工具真正执行处
                          └───────────┘
```

## 19.2 定义文件工具

用 TypeBox schema 声明参数，实现函数读写工作区内的文件：

```typescript
import { Type } from '@sinclair/typebox';
import { readFileSync, writeFileSync } from 'fs';
import path from 'path';

const WORKSPACE = process.cwd(); // 限制在工作目录内

const readTool = {
  name: 'read_file',
  label: '读取文件',
  description: '读取工作区内指定路径的文本文件内容',
  parameters: Type.Object({
    path: Type.String({ description: '相对工作区的文件路径' }),
  }),
  execute: async (_id: string, args: { path: string }) => {
    // 安全检查：禁止路径穿越
    const full = path.resolve(WORKSPACE, args.path);
    if (!full.startsWith(WORKSPACE)) {
      throw new Error('拒绝访问工作区外的路径');
    }
    return { content: [{ type: 'text', text: readFileSync(full, 'utf8') }] };
  },
};

const writeTool = {
  name: 'write_file',
  label: '写入文件',
  description: '把文本内容写入工作区内的指定文件（覆盖）',
  parameters: Type.Object({
    path: Type.String(),
    content: Type.String(),
  }),
  execute: async (_id: string, args: { path: string; content: string }) => {
    const full = path.resolve(WORKSPACE, args.path);
    if (!full.startsWith(WORKSPACE)) throw new Error('拒绝访问工作区外的路径');
    writeFileSync(full, args.content, 'utf8');
    return { content: [{ type: 'text', text: `已写入 ${args.path}` }] };
  },
};
```

## 19.3 组装 Agent 与流式渲染

注册两个工具，订阅事件流做打字机效果：

```typescript
import { Agent } from '@earendil-works/pi-agent-core';
import { createModels } from '@earendil-works/pi-ai';

const models = createModels();
const model = models.getModel('anthropic', 'claude-sonnet-4-5')!;

const agent = new Agent({
  initialState: {
    systemPrompt:
      '你是一个谨慎的编码助手。修改文件前先 read_file 确认现有内容；' +
      '所有文件操作仅限当前项目目录。',
    model,
    tools: [readTool, writeTool],
    messages: [],
  },
  streamFn: models.streamSimple.bind(models),
});

// 流式渲染：文本增量直接打印
agent.subscribe((event) => {
  if (event.type === 'message_update' &&
      event.assistantMessageEvent.type === 'text_delta') {
    process.stdout.write(event.assistantMessageEvent.delta);
  }
  if (event.type === 'tool_execution_start') {
    console.log(`\n🔧 执行工具: ${event.toolName ?? event.toolCall?.name}`);
  }
});
```

## 19.4 REPL 主循环

用 readline 实现交互循环，Ctrl+C 中止当前生成而不是退出程序：

```typescript
import * as readline from 'readline';

const rl = readline.createInterface({ input: process.stdin, output: process.stdout });
const ask = (q: string) => new Promise<string>((r) => rl.question(q, r));

async function main() {
  console.log('迷你编码助手（输入 /exit 退出，/abort 中止当前生成）');
  while (true) {
    const input = await ask('\n你> ');
    if (input === '/exit') break;
    if (input === '/abort') { agent.abort(); continue; } // 中止不退出
    if (!input.trim()) continue;

    process.stdout.write('助手> ');
    await agent.prompt(input);       // 整个循环：生成→工具→再生成
    await agent.waitForIdle();        // 确保完全落定
  }
  rl.close();
}

main();
```

运行效果：

```text
你> 把 README.md 的标题改成"我的项目"
🔧 执行工具: read_file
🔧 执行工具: write_file
助手> 已将标题改为「我的项目」。
```

## 19.5 升级方向

这个 100 行的骨架还有清晰的进化路线：

1. **会话持久化**——结合第 17 章 SQLite 后端，重启后恢复对话；
2. **更多工具**——`list_dir`、`grep_search`、`run_command`（记得加白名单）；
3. **beforeToolCall 风控**——对 write_file 增加人工确认或 diff 预览；
4. **模型路由**——简单问答走便宜模型，代码修改走强模型（第 16 章 handoff）；
5. **Faux 测试**——第 15 章的剧本测试覆盖"读→改→写"完整链路。

其中风控钩子只需十几行就能落地——写入前强制人工确认：

```typescript
// 升级示例：write_file 触发人工确认
agent.beforeToolCall = async ({ toolCall }) => {
  if (toolCall.name !== 'write_file') return; // 只拦截写操作
  const answer = await ask(`确认写入 ${toolCall.arguments.path}？(y/N) `);
  if (answer.trim().toLowerCase() !== 'y') {
    return { block: true, reason: '用户拒绝写入', terminate: false };
  }
};
```

## 本章小结

- 工具定义四件套：name + description + TypeBox parameters + execute；
- 路径穿越检查是文件类工具的安全底线；
- `subscribe` 里区分 message_update 与 tool_execution_* 两类事件分别渲染；
- `/abort` 用 agent.abort() 实现"中止不退出"，体验远好于强杀进程；
- 五条升级路线：持久化、扩工具、风控钩子、模型路由、Faux 测试。
