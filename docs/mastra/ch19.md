# 第 19 章 · 生产最佳实践

> 本章目标：建立成本、安全、质量三条生产红线：模型分级路由、密钥管理、评估迭代闭环。

## 19.1 成本控制：模型分级路由

不是每个环节都需要旗舰模型。按任务复杂度分配：

```typescript
// src/mastra/agents/routed.ts
import { Agent } from '@mastra/core/agent'

// 前台闲聊/简单意图识别 → 便宜的小模型
export const triageAgent = new Agent({
  id: 'triage',
  name: 'Triage',
  instructions: '判断用户意图并路由，回答保持一句话。',
  model: 'openai/gpt-5-mini',          // 低成本档
})

// 复杂推理/长文写作才升级大模型
export const expertAgent = new Agent({
  id: 'expert',
  name: 'Expert',
  instructions: '处理复杂技术问题，给出结构化方案。',
  model: 'anthropic/claude-sonnet-4-5', // 高能力档
})
```

配合 workflow 用 `branch()` 做智能分流（第 8 章），90% 流量走小模型是常见收益。

其他省钱手段：
- RAG 精准检索减少注入 token；
- Observational Memory 压缩历史而非无限追加；
- 为 Scorer/OM 等辅助调用指定廉价模型。

## 19.2 安全：密钥与数据

```typescript
// ❌ 永远不要这样做
const agent = new Agent({
  model: { apiKey: 'sk-abc123...' }, // 硬编码 = 迟早泄漏
})

// ✅ 一律走环境变量 / 密钥管理服务
const agent = new Agent({
  model: 'openai/gpt-5-mini', // SDK 自动读 OPENAI_API_KEY
})
```

清单：
- `.env` 进 `.gitignore`，CI 用平台 secrets 注入；
- 用户输入在进入 prompt 前过一遍注入检测（Processor 层）；
- 工具执行做最小权限：只读工具不给写库凭据；
- 日志脱敏：手机号/邮箱等 PII 落盘前打码。

### 敏感信息脱敏 Processor

用户消息进入 prompt 前打码手机号等 PII：

```typescript
// src/mastra/processors/mask.ts
import { Processor } from '@mastra/core/processors'

export const maskPii: Processor<'maskPii'> = {
  name: 'maskPii',
  processInput: ({ messages }) => {
    // 中国大陆手机号脱敏：保留前三位与后四位
    return messages.map((m) => ({
      ...m,
      content: typeof m.content === 'string'
        ? m.content.replace(/(1[3-9]\d)\d{4}(\d{4})/g, '$1****$2')
        : m.content,
    }))
  },
}
```

### Workflow 分流实现分级路由

```typescript
// src/mastra/workflows/router.ts —— 意图分流让 90% 流量走小模型
import { createWorkflow } from '@mastra/core/workflows'

export const routerFlow = createWorkflow({
  id: 'router',
  inputSchema: z.object({ question: z.string() }),
  outputSchema: z.object({ answer: z.string() }),
})
  .branch([
    // 简单问题走便宜模型，复杂问题升级旗舰模型
    [async ({ inputData }) => isSimple(inputData.question), cheapAgentStep],
    [async () => true, expertAgentStep],
  ])
  .commit()
```

## 19.3 质量：评估迭代闭环

生产级 Agent 不是"写完就完"，而是持续闭环：

```text
收集线上样本 → 补充评估用例 → 改提示词/模型 → CI 跑 Evals → 观测上线指标
      ▲                                                    │
      └────────────────── 回归发现退化 ◀──────────────────┘
```

落地三件事：
1. **每次提示词改动必须过 CI 评估**（第 15 章）；
2. **线上负反馈回流**为新的测试用例（接第 16 章 feedback 数据）；
3. **版本化提示词**——像代码一样 review 与回滚。

## 19.4 上线检查单

- [ ] 存储外置且已备份策略
- [ ] 密钥全部来自环境/密管，仓库无泄漏（git log 扫一遍）
- [ ] 关键路径有 trace 与告警（P95 延迟、错误率）
- [ ] CI 评估通过率达标
- [ ] 有灰度/回滚方案

## 本章小结

- 成本靠分级路由 + 上下文瘦身，多数流量应跑在小模型上；
- 密钥零硬编码、PII 脱敏、工具最小权限是安全底线；
- 评估不是一次性动作而是迭代闭环：样本→用例→CI→观测；
- 上线前逐项过检查单，别靠运气。
