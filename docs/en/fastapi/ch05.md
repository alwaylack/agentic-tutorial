# Chapter 5 · Advanced Parameter Validation and Annotated

> Chapter goals: master the officially recommended Annotated declarative validation pattern, fluently use numeric/length/regex constraints and custom validators, and be able to read 422 error responses.

## 5.1 Annotated: The Official Recommended Pattern

Starting from version 0.95.0, FastAPI officially recommends using Python's standard library `Annotated` to declare parameter metadata:

```python
from typing import Annotated
from fastapi import FastAPI, Query

app = FastAPI()


@app.get("/items/")
def read_items(
    q: Annotated[str | None, Query(max_length=50)] = None,
    #     type ───────────────┘        └── validation metadata
):
    # GET /items/?q=hello works; q over 50 chars returns 422
    return {"q": q}
```

The structure is `Annotated[actual_type, metadata1, metadata2, ...]`, with the default value still written after the parameter's `=`. Comparing with the old style:

```python
# ❌ Old style (before 0.95.0): Query occupied the default value position
def read_items(q: str | None = Query(default=None, max_length=50)): ...

# ✅ New style: default value returns to its natural position, validation info goes into Annotated
def read_items(q: Annotated[str | None, Query(max_length=50)] = None): ...
```

Official advantages of Annotated:

- **Default value semantics not polluted**: calling this function directly (without FastAPI), the parameter is a plain parameter, you won't get a `QueryInfo` object;
- **Reusable**: `Annotated` types can be extracted as aliases shared across multiple interfaces;
- **Compatible with other tools**: the same function can be used by Typer and other libraries based on Annotated.

::: warning Can't use Query(default=...) inside Annotated
`Annotated[str, Query(default="rick")] = "morty"` will error. Inside Annotated, `Query()` doesn't accept the default parameter — the default value only goes after the parameter `=`.
:::

## 5.2 String Constraints: Length and Regex

`Query`/`Path`/`Body`/`Field` share the same constraint parameters:

```python
from typing import Annotated
from fastapi import FastAPI, Query

app = FastAPI()


@app.get("/search/")
def search(
    q: Annotated[
        str,
        Query(
            min_length=3,                      # at least 3 characters
            max_length=50,                     # at most 50 characters
            pattern=r"^[\w\u4e00-\u9fa5 ]+$",  # only allow letters, digits, underscores, Chinese, spaces
            title="Search Keyword",
            description="Length 3-50, only Chinese/English letters, digits, and spaces",
        ),
    ],
):
    return {"q": q}
```

`pattern` uses regex to constrain format, e.g., forcing `^fixedquery$` is exact match. `title`/`description` don't participate in validation but display in the OpenAPI document.

## 5.3 Numeric Constraints: gt / ge / lt / le

Path parameters can also validate, using `Path`:

```python
from typing import Annotated
from fastapi import FastAPI, Path

app = FastAPI()


@app.get("/items/{item_id}")
def read_item(
    item_id: Annotated[int, Path(title="Item ID", gt=0, lt=10000)],
    size: Annotated[float, Query(ge=0.1, le=10)] = 1.0,
):
    # item_id must be an integer 1..9999 (gt=0 excludes 0 and negatives)
    # size must be between 0.1 and 10 (inclusive, ge/le are >= and <=)
    return {"item_id": item_id, "size": size}
```

Four abbreviations' meanings must be clear: `gt`=greater than (strict), `ge`=greater or equal, `lt`=less than, `le`=less or equal. To express "must be positive but can be less than 1," only `gt=0` works; `ge=1` would incorrectly exclude 0.5.

## 5.4 Pydantic Model Field Validation: Field

Request body fields use `Field`, parameter names identical to Query/Path:

```python
from pydantic import BaseModel, Field
from fastapi import FastAPI

app = FastAPI()


class Product(BaseModel):
    name: str = Field(min_length=1, max_length=100, examples=["Mechanical Keyboard"])
    price: float = Field(gt=0, description="Unit price, must be greater than 0")
    stock: int = Field(default=0, ge=0)
    sku: str = Field(pattern=r"^[A-Z]{3}-\d{4}$")   # like ABC-1234


@app.post("/products/")
def create(p: Product):
    return p.model_dump()
```

## 5.5 Custom Validators

When built-in constraints aren't enough, Pydantic v2 provides `field_validator` (single field) and `model_validator` (entire model):

```python
from pydantic import BaseModel, field_validator, model_validator


class Registration(BaseModel):
    username: str
    password: str
    password_confirm: str

    @field_validator("username")
    @classmethod
    def username_alphanumeric(cls, v: str) -> str:
        if not v.isalnum():
            raise ValueError("Username can only contain letters and digits")
        return v.lower()   # can also normalize

    @model_validator(mode="after")
    def passwords_match(self) -> "Registration":
        # mode="after": runs after all field validations pass, can access all fields of self
        if self.password != self.password_confirm:
            raise ValueError("Passwords do not match")
        return self
```

`ValueError` thrown on validation failure gets caught by Pydantic and enters the 422 response detail list; users see friendly errors rather than stack traces.

## 5.6 Reading 422 Error Responses

A failed request's response body:

```json
{
  "detail": [
    {
      "type": "greater_than",
      "loc": ["body", "price"],
      "msg": "Input should be greater than 0",
      "input": "-5",
      "ctx": { "gt": 0 }
    }
  ]
}
```

- **loc**: error location array. `["path","item_id"]` is a path parameter, `["query","q"]` is a query parameter, `["body","price"]` is a request body field; nested models give the full path like `["body","items",0,"url"]`;
- **type**: machine-readable error type (int_parsing, string_too_long, greater_than...);
- **ctx**: error context (the violated constraint value).

Frontends can precisely locate form controls by `loc` — this is the validation system's greatest contribution to full-stack experience.

## 5.7 Chapter Summary

- New code uniformly uses `Annotated[type, Query(...)]` style, defaults回归 `=`; can't use `default=` inside Annotated;
- String constraints `min_length/max_length/pattern`, numeric constraints `gt/ge/lt/le`, Query/Path/Body/Field share;
- Custom validation uses `field_validator` (single field) and `model_validator(mode="after")` (cross-field);
- 422 response's `loc/type/msg/ctx` precisely locate each error, even for nested models.
