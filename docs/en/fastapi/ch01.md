# Chapter 1 · FastAPI Introduction and Environment Setup

> Chapter goals: understand what FastAPI is, its relationship with Starlette/Pydantic, set up the development environment, and run the first minimal app with hot reload.

## 1.1 What is FastAPI

FastAPI is a modern, high-performance Python web framework designed specifically for building APIs. The key to understanding it is seeing the three-layer structure:

- **Starlette**: the underlying ASGI framework, responsible for routing, request/response, middleware, WebSocket — these web infrastructure pieces. FastAPI's async capability and performance come directly from it;
- **Pydantic**: data validation and serialization library (v2 core written in Rust), responsible for turning JSON from requests into Python objects with type validation;
- **FastAPI itself**: the "type-driven" glue layer binding the two — you write type annotations on function signatures, and it automatically completes parameter parsing, validation, serialization, and documentation generation.

```python
# A minimal FastAPI application: main.py
from fastapi import FastAPI

app = FastAPI()  # create app instance, all routes registered on it


@app.get("/")
def read_root():
    return {"message": "Hello World"}  # returning dict auto-serializes to JSON
```

::: tip Why are type annotations "core"
FastAPI's entire magic entry point is the type annotations on function signatures: parameters typed `int` gets parsed and validated from path/query strings; parameters that are Pydantic models get read from the request body; return values with model annotations get filtered and serialized. **The more accurate your annotations, the more the framework does for you** — which is why this tutorial repeatedly emphasizes the `Annotated` pattern.
:::

## 1.2 Installation

Recommended to install the full package with standard dependencies:

```bash
python -m venv .venv && source .venv/bin/activate
pip install "fastapi[standard]"
```

`fastapi[standard]` additionally includes:

- **uvicorn**: high-performance ASGI server (this is what actually runs your application);
- **fastapi-cli**: provides `fastapi dev` / `fastapi run` command-line tools;
- Common optional dependencies (`email-validator`, `httpx`, `jinja2`, etc.) used in later chapters.

Verify installation:

```bash
$ fastapi --version
# FastAPI 0.141.x
```

## 1.3 Startup and Hot Reload

Save the 1.1 code as `main.py`, then:

```bash
$ fastapi dev main.py
 INFO    Will watch for changes in these directories: [...]
 INFO    Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
 INFO    Started reloader process [383138] using WatchFiles
 INFO    Application startup complete.
```

Open <http://127.0.0.1:8000> and you'll see `{"message":"Hello World"}`.

Regarding the relationship between these commands, beginners most easily confused:

| Command | Purpose | Characteristics |
|---|---|---|
| `fastapi dev main.py` | Development mode | Auto-discovers app, auto-restarts on file changes |
| `fastapi run main.py` | Production mode | Doesn't watch file changes, starts per production config |
| `uvicorn main:app --reload` | Manual development | `fastapi dev` internally wraps uvicorn |

::: warning Use different commands for dev/production
`fastapi dev`'s reloader watches the entire directory — wasteful and a security risk in production. Use `fastapi run` or directly uvicorn/gunicorn when deploying (Chapter 22 covers in detail).
:::

If not using the CLI, you can also start completely manually:

```python
# run_dev.py —— programmatic equivalent of fastapi dev
import uvicorn

if __name__ == "__main__":
    uvicorn.run("main:app", host="127.0.0.1", port=8000, reload=True)
    # Note the first parameter is the string "main:app" not the app object
    # because hot reload needs to re-import the application via import string in subprocess
```

## 1.4 ASGI and the First Look at Sync/Async

FastAPI is an ASGI framework. ASGI (Asynchronous Server Gateway Interface) is the async successor to WSGI: servers and applications communicate via async messages, naturally supporting WebSocket and long connections.

You only need to establish an intuition now (deep dive in Chapter 16):

- `async def` path functions execute in the event loop, suitable for async IO using `await` internally;
- Plain `def` path functions get dispatched to a thread pool, won't block other requests.

```python
from fastapi import FastAPI
import time

app = FastAPI()


@app.get("/sync-slow")
def sync_slow():
    # Plain def: runs in thread pool, time.sleep won't block the event loop
    time.sleep(1)
    return {"mode": "sync"}


@app.get("/async-fast")
async def async_fast():
    # async def: runs in event loop, must pair with async IO to be meaningful
    import asyncio
    await asyncio.sleep(1)
    return {"mode": "async"}
```

❌ The most common pitfall is writing blocking calls in `async def` (like `time.sleep`, synchronous `requests.get`): this freezes the entire event loop, making all concurrent requests queue up.

One more multi-route example to feel the "just write function signatures, let the framework handle the rest" style:

```python
# main.py append two routes
from fastapi import FastAPI

app = FastAPI()


@app.get("/ping")
def ping():
    return {"pong": True}            # health check: simplest interface form


@app.get("/greet/{name}")
def greet(name: str):
    # name extracted from path and injected into function, no manual URL parsing needed
    return {"message": f"Hello, {name}"}
```

Run with `fastapi dev` and visit `/greet/GX`, you'll see `{"message":"Hello, GX"}` — path parameter parsing, JSON serialization, documentation generation all automatic.

## 1.5 Project Layout Suggestions

This chapter establishes the simplest single-file structure first, later chapters will gradually evolve:

```text
myapi/
├── main.py              # application entry point
```
