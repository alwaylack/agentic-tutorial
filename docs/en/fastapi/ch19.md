# Chapter 19 · Large Project Structure Split

> Chapter goals: learn to use `APIRouter` to split a single-file application into a maintainable multi-module project; understand the officially recommended directory structure and dependency-sharing approaches.

## 19.1 Why You Need APIRouter

When writing real projects, it's impossible to pile all path operations in one `main.py`. FastAPI's answer is `APIRouter` — think of it as a "mini FastAPI": it supports the exact same parameters as the `FastAPI` class (`dependencies`, `tags`, `responses`, etc.). Declare routes in their own modules first, then uniformly "plug them back" into the main application. If you've used Flask, it's equivalent to Blueprint.

## 19.2 Officially Recommended Project Structure

```
.
├── app
│   ├── __init__.py      # makes app a Python package
│   ├── main.py          # main module, assembles all routers
│   ├── dependencies.py  # cross-router shared dependencies
│   ├── routers          # routing sub-package
│   │   ├── __init__.py
│   │   ├── items.py     # /items related path operations
│   │   └── users.py     # /users related path operations
│   └── internal         # internal sub-packages (e.g., admin interfaces)
│       ├── __init__.py
│       └── admin.py
```

Key points:

- Every directory needs an `__init__.py` to make it a Python package, enabling mutual imports;
- `app/main.py` is the assembly point; after dispersing business logic into modules it becomes very thin;
- Shared dependencies go in `app/dependencies.py`, not scattered across individual router files.

## 19.3 Writing a Router Module

`app/routers/users.py` — only cares about user routes:

```python
from fastapi import APIRouter, Depends, HTTPException
# Single dot: look in the current package (app/routers/); here dependencies.py doesn't exist
# Two dots: go up to the parent package app/ to find app/dependencies.py ✅
from ..dependencies import get_token_header

# prefix is prepended to all paths in this router; tags are used for docs grouping
router = APIRouter(prefix="/users", tags=["users"])


@router.get("/")
async def read_users():
    return [{"username": "alice"}, {"username": "bob"}]


@router.get("/me")
async def read_current_user(token: str = Depends(get_token_header)):
    return {"token": token}
```

`app/routers/items.py` — demonstrating router-level public configuration:

```python
from fastapi import APIRouter, Depends, HTTPException
from ..dependencies import get_token_header, get_query_token

router = APIRouter(
    prefix="/items",                # note: cannot end with /
    tags=["items"],
    dependencies=[Depends(get_token_header)],  # all routes in this group require X-Token
    responses={404: {"description": "Not found"}},  # predefined responses go into docs
)


@router.get("/")          # actual path /items/
async def read_items():
    return [{"item_id": "Foo"}]


@router.get("/{item_id}")  # actual path /items/{item_id}
async def read_item(item_id: str):
    return {"item_id": item_id}
```

::: tip prefix details
Each path operation's path must start with `/`, so `prefix` **cannot** end with `/` (writing `/items` without `/items/`). Router-level `dependencies` apply to the entire group of routes and execute before route-level dependencies — a typical use is batch-adding authentication to an entire group of endpoints.
:::

## 19.4 Assembling in the Main Application

`app/main.py` only handles assembly:

```python
from fastapi import Depends, FastAPI
from .routers import items, users
from .dependencies import get_query_token

# Global dependencies stack with each router's dependencies
app = FastAPI(dependencies=[Depends(get_query_token)])


app.include_router(items.router)
app.include_router(users.router)


@app.get("/", tags=["root"])
async def root():
    return {"message": "Hello Bigger Applications!"}
```

The run method is unchanged:

```bash
uv run fastapi dev app/main.py
```

`include_router()` can also temporarily override configuration:

```python
# Mount the same router again under a different prefix, appending tags
app.include_router(items.router, prefix="/v1", tags=["v1"])
```

The same router can be included multiple times (e.g., exposing both `/items` and `/v1/items`); each specific path operation can still叠加 additional `tags` and `responses` (the final tags are a merge result).

## 19.5 Relative Imports and Circular Imports

### Relative Import Rules

- `from .dependencies import ...`: look in the **current package** (for `app/routers/items.py` that's `app/routers/` — you usually won't find the file you want);
- `from ..dependencies import ...`: go up one package to `app/` to find `app/dependencies.py` ✅;
- `from ...xxx import ...`: go up two levels, which exits the `app` package and errors directly.

### Avoiding Circular Imports

The most common crash after splitting into multiple files is circular imports: `main.py → routers/users.py → main.py`. Mitigation strategies:

1. **Dependency sinking**: move shared dependencies, models, and utility functions that multiple routers depend on into independent modules (`dependencies.py`, `models.py`); whoever needs it imports it — never reverse-import `main.py`;
2. **Routers don't import app**: router modules only create their own `APIRouter`; assembly happens only in `main.py`;
3. **Deferred type hint imports**: when you do need to reference the main application object, put the `import` inside the function body, or use a `TYPE_CHECKING` block.

```python
# app/routers/users.py —— wrong example (don't do this)
# from ..main import app   # ❌ main imports this module → circular import

# Correct approach: only export the router, let main handle include
router = APIRouter(prefix="/users")
```

## 19.6 Chapter Summary

- `APIRouter` is a "mini FastAPI" supporting the full suite of `prefix/tags/dependencies/responses` parameters;
- Official structure: `main.py` for assembly + `routers/` for routes + `dependencies.py` for shared dependencies + `__init__.py` in each directory;
- `prefix` cannot end with `/`; router-level dependencies apply to the entire group and execute before route-level dependencies;
- The same router can be included multiple times under different prefixes via `include_router`;
- Use "sink dependencies into independent modules + routers don't reverse-import the main app" to avoid circular imports.
