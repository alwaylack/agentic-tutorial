> Chapter goals: Master Claude Code's deep integration with Git — auto-generating commit messages, branch operations, creating PRs via GitHub CLI, and leveraging Claude to assist code reviews.

## 8.1 Auto Commit Messages

One of Claude Code's most commonly used Git features is auto-generating meaningful commit messages based on staged changes:

```bash
# In interactive mode
> Help me commit these changes

# Claude will:
# 1. Run git diff --cached to view staged内容
# 2. Analyze the change semantics (new feature/bug fix/refactor)
# 3. Generate a message conforming to Conventional Commits
# 4. Execute git commit
```

Typical output:

```text
Claude detected modifications to 3 files:

  src/auth/login.ts    | 42 +++++---
  src/auth/types.ts    | 12 ++++
  tests/auth.test.ts   | 28 +++++++

Suggested commit message:

  feat(auth): add OAuth2 login flow with refresh token

  - Implement OAuth2 authorization code flow
  - Add token refresh mechanism with auto-retry
  - Update TypeScript interfaces for auth types
  - Include unit tests for login and refresh paths

Confirm commit? (y/n)
```

::: tip Conventional Commits Convention
Convent the commit format in CLAUDE.md; Claude will自动 follow:

```markdown
## Git Conventions
- Use Conventional Commits: feat/fix/docs/refactor/test/chore
- scope uses module name: auth, api, ui
- description in English, first line under 72 chars
```
:::

## 8.2 Branch Operations

```bash
# Create a feature branch and switch to it
> Create a feature/user-profile branch

# Merge and handle conflicts
> Merge the latest main code into the current branch; help me resolve any conflicts

# How Claude handles conflicts:
# 1. git merge main → detects conflicts
# 2. Reads each conflicted file one by one
# 3. Analyzes the modification intent on both sides
# 4. Gives merge suggestions or resolves directly
# 5. Marks resolved and completes the merge commit
```

### Rebase Operations

```bash
> Rebase my branch onto main

# Claude checks for unpushed commits,
# executes git pull --rebase origin main,
# and handles possible conflicts.
```

::: warning Proceed with Caution on Dangerous Operations
Operations like `git reset --hard`, `git push --force`, and `git rebase` irreversibly修改 history. Claude Code默认 requires you to confirm these operations. It's recommended to add additional protection in settings.json:

```json
{
  "permissions": {
    "deny": [
      "Bash(git push --force:*)",
      "Bash(git reset --hard:*)"
    ]
  }
}
```
:::

## 8.3 Creating PRs with GitHub CLI

After installing the `gh` CLI, Claude can完成 a full PR workflow:

```bash
# Prerequisite: install and authenticate gh CLI
brew install gh
gh auth login

# Have Claude create a PR
> Push the current branch and create a PR to main
```

Claude's execution流程:

```text
1. git push -u origin feature/user-profile
2. gh pr create --title "..." --body "..."
   ├── Title extracted from commit messages
   └── Body auto-includes:
       - Change summary
       - Test status
       - Related issue (if mentioned)
3. Returns the PR link
```

### Custom PR Templates

```markdown

Use the following template structure when creating PRs:
### Changes / ### Tests / ### Screenshots (if UI changes) / ### Checklist
```

## 8.4 Code Review Assistance

Claude Code is a powerful review assistant — it can读 context, not just diffs.

### Reviewing Uncommitted Code

```bash
> Review my current changes, focusing on security issues and performance hazards

# Claude will:
# 1. git diff to view changes
# 2. Read relevant files for full context
# 3. Analyze from security, performance, and maintainability dimensions
# 4. Output findings sorted by severity
```

Output example:

```text
📋 Code Review Results

🔴 High Risk
├── src/auth/login.ts:45 — Plaintext password stored in session
│   Suggestion: hash with bcrypt before storing

🟡 Medium
├── src/api/users.ts:78 — N+1 query problem
│   Suggestion: use join or eager loading

🟢 Suggestion
├── src/utils/format.ts:12 — Can be提取 as a shared function
```

### Reviewing Others' PRs

```bash
> Review the code quality of PR #42

# Claude获取s PR info via gh commands
gh pr view 42
gh pr diff 42

# Then analyzes file by file and gives review comments
```

## 8.5 Diff Reading Tips

When Claude展示s大量 changes, learn to quickly locate关键信息:

```bash
# Only view statistics
> How many files did this branch modify?

# Focus on特定 type of changes
> List all newly added API endpoints

# Compare two versions
> Compare the差异 between v1.0 and v2.0 tags; summarize the main changes
```

For大型 diffs, having Claude先 give an overview before diving into details is more efficient than reading everything at once:

```text
You: What did this PR change?
Claude: This PR包含 3 major changes:
        1. New user preferences API (4 files)
        2. Refactored database connection pool (2 files)
        3. Fixed a timezone bug (1 file)
        Which part should I dive deeper into?

You: Focus on the database connection pool refactor
Claude: [深入分析...]
```
