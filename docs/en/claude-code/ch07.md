# Chapter 7 · Multi-turn Sessions and Context Management

> Chapter goals: Master Claude Code's session persistence mechanism, understand context window limits and compaction strategy, learn to use --continue/--resume to restore history, and formulate context management strategies for long tasks.

## 7.1 Session Lifecycle

Every interaction in Claude Code is a **session**. Understanding its lifecycle is prerequisite for efficient use:

```text
New session starts
   │
   ├── Load CLAUDE.md → inject project context
   ├── Load settings.json → apply permission rules
   ├── Scan directory structure → build code map
   │
   ▼
User input ──→ Claude thinks ──→ Tool calls ──→ Result feedback
   │                                          │
   │         (loop until task completes)       │
   │                                          │
   ▼                                          ▼
User continues conversation          Session ends (auto-saved)
```

Each session is automatically saved to the local `~/.claude/projects/` directory and can be restored even if the terminal closes.

## 7.2 --continue and --resume

```bash
# Method 1: --continue to resume the most recent session
claude --continue

# Shorthand -c
claude -c

# Append a new instruction to the resumed session
claude --continue "Was that bug fixed?"

# Method 2: --resume to select a specific historical session
claude --resume

# Restore a specific session ID directly
claude --resume <session-id>
```

| Flag | Behavior |
|---|---|
| `-c` / `--continue` | Opens the most recent session when no argument is given |
| `-c "instruction"` | Opens the most recent session and immediately executes the new instruction |
| `-r` / `--resume` | Shows a session list for selection |
| `-r <id>` | Restores the session with the specified ID |

::: tip Use Cases
- **Cross-day work**: half-done yesterday, `claude -c` to continue today;
- **Multi-task switching**: switch between sessions for different projects with `--resume`;
- **Code review tracing**: find previous discussion records with `--resume`.
:::

## 7.3 Context Window and Compaction

Claude's context window is finite (about 200K tokens). During long conversations, when approaching the limit, **compaction** is triggered:

```text
Context usage
│
│ ████████████████████████░░░░░░░░░░ 75% ← Normal working区
│
│ ██████████████████████████████░░░░ 90% ← Compaction begins
│    ↑
│    Claude automatically summarizes early messages,
│    preserving key decisions and current state,
│    freeing space for subsequent operations.
```

Compaction behavior:
1. Compresses early messages into a **structured summary**;
2. Preserves the original text of recent messages;
3. Maintains a "current task state" snapshot.

### Manual Trigger Compaction

```bash
# In interactive mode
> /compact

# With custom summary focus
> /compact Focus on: database schema changes, API interface design decisions, unfinished TODO list
```

## 7.4 Strategies for Long Conversations

For complex tasks spanning multiple days, compaction alone is insufficient. The following strategies are recommended:

### Strategy 1: Externize Progress to Files

Have Claude write key information to disk files instead of relying on conversation memory:

```markdown
<!-- PROGRESS.md -->
# Task Progress

## Done
- [x] Database schema design (see docs/schema.md)
- [x] User auth module (commit abc123)

## In Progress
- [ ] Orders API: CRUD done, pending payment callback

## Decision Log
- ORM choice: SQLAlchemy 2.0 (team vote)
- No Redis cache introduced (current traffic doesn't need it)
```

Convent in CLAUDE.md:

```markdown
## Workflow Convention
Read PROGRESS.md at the start of each session to understand current state.
Update PROGRESS.md before the end of each session.
Write important architecture decisions to DECISIONS.md with rationale.
```

### Strategy 2: Task Decomposition and Session Isolation

```bash
# Don't do everything in one session
# ❌ claude "Refactor the entire project"

# ✅ Split into independent sessions
claude -p "Analyze test coverage of the auth module"
claude -p "Write unit tests for utils/date.py"
claude -p "Fix the memory leak mentioned in issue #42"
```

One small task per session; avoid performance degradation from context bloat in a single ultra-long conversation.

### Strategy 3: Use Git as a State Anchor

```bash
# Have Claude commit at key checkpoints
> Please commit current progress; message: "WIP: user auth module 80% done"
```

Git commits are the most reliable "checkpoint" — even if the session is lost, the code state is not.

## 7.5 Diagnosing Context Issues

```bash
# Check current context usage
> /cost

# Output example:
# Total cost: $0.45
# Context used: 45,230 / 200,000 tokens (22.6%)
```

Common problems and remedies:

| Symptom | Cause | Solution |
|---|---|---|
| Replies slow down | Context too large | `/compact` or open a new session |
| Forgets previous decisions | Compaction lost details | Externize with progress files |
| Re-does already-done work | New session has no memory | CLAUDE.md + PROGRESS.md |
| Cost spikes | Long conversation accumulates tokens | Periodically open new sessions |

## Chapter Summary

- `claude -c` quickly resumes the last conversation; `--resume` selects from a list;
- Compaction auto-compresses early conversations, preserving recent content and task snapshots;
- Complex tasks use PROGRESS.md + DECISIONS.md to externize key information;
- Small tasks split into independent sessions are more efficient than one ultra-long conversation;
- Git commits are the most reliable progress anchor.
