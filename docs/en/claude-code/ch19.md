# Chapter 19 · Team Collaboration Norms

> Chapter goals: Establish team-level Claude Code usage norms — shared CLAUDE.md templates, code review flows, MCP/Skills configuration management, and new member onboarding — so the whole team "collaborates with AI in the same way."

## 19.1 Team CLAUDE.md Template

Personal CLAUDE.md can be随心所欲, but the version committed to the repo is the **team's contract** — it determines行为一致性 for every member (and agents in CI).

A battle-tested team template:

```markdown
# CLAUDE.md

## Project Overview
E-commerce backend, Node 20 + TypeScript + PostgreSQL 15.

## Environment and Commands
- Install: pnpm install
- Tests: pnpm test (single file: pnpm vitest run <path>)
- Build: pnpm build
- Lint: pnpm lint && pnpm format

## Code Norms
- Functions over classes; exported functions must have JSDoc
- DB operations always go through the repository layer in src/db/
- API error responses统一 use the AppError class
- No `any` type; `unknown` must be narrowed before use

## Git Conventions
- Branch names: feat/<ticket> / fix/<ticket>
- Commit messages use Conventional Commits
- PR title = commit subject

## Notes
- Do not modify already-applied migrations under migrations/
- .env.local contains local secrets; never read or modify it
```

::: warning Version Control Strategy
Commit CLAUDE.md and `.claude/settings.json` to git; add `.claude/settings.local.json` and `.claude/credentials` to `.gitignore`. The former is the team contract; the latter is personal preference.
:::

### Multi-Layer CLAUDE.md

In a monorepo, place additional CLAUDE.md files in subdirectories:

```text
repo/
├── CLAUDE.md                  # Global norms
├── packages/api/CLAUDE.md     # API-specific conventions
└── packages/web/CLAUDE.md     # Frontend-specific conventions
```

Claude自动 loads all CLAUDE.md files from the current working directory and its ancestors,实现 "global norms + local overrides."

## 19.2 Code Review Process Integration

### PR Review Assistance

One of Claude Code's most valuable team scenarios: automated preliminary review:

```bash
# On the feature branch, generate a change summary for reviewers
claude -p "Compare with the main branch; summarize what this PR changes and what潜在 risks exist" \
  --allowedTools "Read" "Bash(git diff*)" \
  > pr-summary.md
```

### GitHub Actions Automated Review

Integrate Claude into CI for a first-round review:

```yaml
# .github/workflows/claude-review.yml
name: Claude Code Review
on:
  pull_request:
    types: [opened, synchronize]

jobs:
  review:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pull-requests: write
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - name: Claude Review
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: |
          npm install -g @anthropic-ai/claude-code
          claude -p "Review this PR's code changes. Focus on: security issues, logic errors, performance hazards.
                   Output discovered issues and their severity as a markdown list." \
            --allowedTools "Read" "Bash(git diff*)" \
            --output-format text >> review-comment.md
      - name: Post Comment
        uses: actions/github-script@v7
        with:
          script: |
            const fs = require('fs');
            const body = fs.readFileSync('review-comment.md', 'utf8');
            await github.rest.issues.createComment({
              ...context.repo,
              issue_number: context.issue.number,
              body
            });
```

::: tip Positioning
AI review is初筛 not终审 — it catches format violations, obvious bugs, and missing tests, but architecture decisions仍需 human judgment. The team should明确标注 "Claude reviewed" to避免重复劳动.
:::

## 19.3 Shared MCP and Skills Configuration

### Project-Level MCP Config

Write MCP server configs into `.mcp.json` at the repo root and commit:

```json
{
  "mcpServers": {
    "database": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres"],
      "env": {
        "DATABASE_URL": "${DATABASE_URL}"
      }
    },
    "figma": {
      "command": "npx",
      "args": ["-y", "@anthropic/mcp-figma"]
    }
  }
}
```

After cloning, team members run `claude mcp list` and immediately see all预配置 servers — zero-config onboarding.

### Team Skills Directory

Place commonly used skills in `.claude/skills/` and distribute with the repo:

```text
.claude/skills/
├── deploy-checklist/SKILL.md    # Release checklist流程
├── db-migration/SKILL.md        # Migration file writing norms
└── api-endpoint/SKILL.md        # New endpoint scaffolding
```

Any member's agent自动 loads these skills when matching relevant tasks, ensuring output follows the same流程.

## 19.4 New Member Onboarding

Traditional onboarding takes 1–2 weeks; with thorough Claude Code configuration, compress to days:

```text
Day 1: Clone repo → start claude → agent自动 loads CLAUDE.md
       Ask Claude: "What is this project's architecture? What is the core business flow?"
       (Much faster than reading Wiki — the agent directly reads code to answer)

Day 2: Use /init or manually完善 CLAUDE.md (newbie perspectives常能发现文档盲区)
       Tackle the first good-first-issue, pair with Claude全程

Day 3+: Submit a PR → trigger Claude Review → learn the team's code review standards
```

Key insight: **the process of a new member improving CLAUDE.md is itself the most efficient learning process** — to explain clearly to AI, you must first clarify your own understanding.

## 19.5 Team Anti-Patterns Checklist

| Anti-Pattern | Consequence | Remedy |
|---|---|---|
| Each person maintains their own CLAUDE.md without sharing | Inconsistent behavior, high reviewcost | Unify into git; personal prefs go to local |
| Committing keys into settings.json | Keyleak | Keys via env vars or apiKeyHelper |
| Blindly accepting AI review without human复核 | Hallucinated suggestions merged | AI标注 as "建议"; merge decided by humans |
| Skills/MCP configs散落各人文档 | Non-reproducible | Converge all into `.claude/` and `.mcp.json` |

## Chapter Summary

- CLAUDE.md is the team contract: commit to git, personal prefs in `settings.local.json`;
- Monorepos leverage multi-layer CLAUDE.md for "global + local" rule叠加;
- GitHub Actions + `claude -p`搭建 automated preliminary review pipelines;
- `.mcp.json` and `.claude/skills/`让 tools and knowledge distribute with the repo;
- New memberscomplete the most efficient onboarding by "reading and improving CLAUDE.md."
