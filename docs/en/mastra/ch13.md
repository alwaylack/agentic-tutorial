# Chapter 13 · Storage Layer

> Chapter goals: Understand Mastra's storage domain model, learn to选择 LibSQL/Postgres and other adapters for different scenarios, and persist workflow state.

## 13.1 What Is Storage

Storage is Mastra runtime's **persistent layer**. Data that survives进程重启 is managed by it:

- **Memory**: message history, threads, resources, working memory;
- **Workflows**: persistence snapshots required for suspend/resume;
- **Observability**: traces, spans, metrics, logs, feedback;
- **Evals**: scores, datasets, experiment results;
- **Background tasks & schedules**: background tasks, schedules, threadState.

::: warning Default is in-memory storage
When not configured, Mastra uses an in-memory store — suitable for testing and short-term experiments, but **data is lost on进程 exit**.
:::

## 13.2 Domain Model

Storage is organized by domain; each adapter implements one or more domains:

| Domain | What It Stores |
|---|---|
| `memory` | Threads, messages, resources, working memory |
| `workflows` | Workflow suspend/resume snapshots |
| `observability` | Traces, metrics, logs |
| `scores` / `datasets` / `experiments` | Evaluation-related data |
| `backgroundTasks` / `schedules` / `threadState` | Background task and schedule state |

Selection principle:高频 transactional reads/writes like memory → choose LibSQL/PostgreSQL; analytical queries → columnar or specialized backends.

## 13.3 Configuring LibSQL (Development and Small Production)

```typescript
// src/mastra/index.ts
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    // Local file; swap to libsql:// remote instance (Turso) for production
    url: process.env.NODE_ENV === 'production'
      ? process.env.LIBSQL_URL!
      : 'file:./mastra.db',
    authToken: process.env.LIBSQL_AUTH_TOKEN, // Required for remote instances
  }),
  agents: { support: supportAgent },
  workflows: { refundFlow },
})
```

## 13.4 Configuring Postgres (Large-Scale Production)

```typescript
// src/mastra/storage.ts
import { MastraStorage } from '@mastra/core/storage'
import { PgStore } from '@mastra/pg'

export const storage: MastraStorage = new PgStore({
  id: 'main-storage',
  connectionString: process.env.DATABASE_URL,
  // Optional: specify schema name for multi-env isolation
  schemaName: 'mastra_prod',
})
```

## 13.5 In-Memory Storage for Tests

No persistence needed for unit tests — explicitly声明内存存储, discard after each run:

```typescript
// tests/setup.ts
import { Mastra } from '@mastra/core'
import { InMemoryStore } from '@mastra/core/storage'

export const testMastra = new Mastra({
  // Isolated and zero residue; each test instance互不干扰
  storage: new InMemoryStore(),
  agents: { support: supportAgent },
})
```

## 13.7 Chapter Summary

- Storage is the unified persistent layer for memory/workflows/observability/evals;
- Default in-memory storage is test-only; production必须配置持久适配器;
- LibSQL (local file or Turso) suits development and small-scale; Postgres suits large-scale;
- Workflow suspend/resume依赖存储快照; seamlessly恢复 after restart.
