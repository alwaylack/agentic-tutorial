# Chapter 09 · Subagents and context isolation

The built-in task tool lets the main agent spawn subagents: each subtask gets a fresh context and returns one report. Use it for context-bloating scenarios like heavy retrieval or heavy file reads.

## Mechanics and design choices

Subagents are ephemeral and stateless: they return once, no back-and-forth. A general-purpose default exists; custom definitions are also possible. Context isolation is the core value, not a parallel compute framework.

## Example

```python
import os
from langchain_openai import ChatOpenAI

model = ChatOpenAI(
    model=os.environ["MODEL_ID"],
    api_key=os.environ["DEEPAGENT_API_KEY"],
    base_url=os.environ.get("DEEPAGENT_BASE_URL", "https://api.openai.com/v1"),
)

from deepagents import create_deep_agent

research = {
    "name": "research-agent",
    "description": "Research tasks with focused searches",
    "system_prompt": "You are a focused researcher. Return findings as a short report.",
}
agent = create_deep_agent(
    model=model,
    subagents=[research],
    system_prompt="Delegate research subtasks to the research-agent subagent.",
)
result = agent.invoke(
    {"messages": [
        {"role": "user", "content": "Research: why do we isolate subtasks in their own context?"},
    ]
}, config={"configurable": {"thread_id": "ch09"}})
print(result["messages"][-1].content)
```

### Run and verify

API key required. Acceptance: the trace shows a subagent call; the main agent receives the conclusion report only.

## Pitfalls

Subagents solve context hygiene, not “smarter results.” Delegation must state acceptance criteria and boundaries, otherwise you only hide complexity.
