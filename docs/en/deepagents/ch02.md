# Chapter 02 · Model routing and provider strings

Chapters that use a model need a tool-calling model service and API key (any OpenAI-compatible endpoint); running incurs cost.

## Mechanics and design choices

The model argument accepts a chat model instance or a "provider:model" string routed through init_chat_model. The Deep Agents docs favor strings; in real projects an explicit model object gives more control over timeouts, retries, and tags.

## Example

```python
import os
from langchain_openai import ChatOpenAI

model = ChatOpenAI(
    model=os.environ["MODEL_ID"],
    api_key=os.environ["DEEPAGENT_API_KEY"],
    base_url=os.environ.get("DEEPAGENT_BASE_URL", "https://api.openai.com/v1"),
)

from deepagents import create_deep_agent

agent = create_deep_agent(
    model=model,
    system_prompt="Answer in one short paragraph.",
)
result = agent.invoke({"messages": [{"role": "user", "content": "Say exactly: ready"}]})
print(result["messages"][-1].content)
```

### Run and verify

Run after configuring the three variables. Acceptance: a short confirmation and no side effects. String routing needs the provider package installed; the object form only needs its client.

## Pitfalls

Do not hard-code model names in production: switching and rollbacks belong in configuration. String-routing errors surface at call time, so check environment variables and provider client versions together.
