## 2.1 Why We Needmessage queue

在previous chapter中我们用 FastAPI 的 `BackgroundTasks` process轻量background task（参见 [FastAPI ch16](/fastapi/ch16.md)）。但当task需要：

- cross-processexecute（主servicecrash不affectqueue）
- persistence（Worker restart后task不lost）
- retry与failure隔离（单个taskfailure不affectothertask）
- horizontal scaling（多个 Worker parallel consumption）

`BackgroundTasks` 就不够用了。message queue是production-grade Agent service的essentialinfrastructure。

```
客户端 ──HTTP──▶ FastAPI service ──enqueue──▶ Redis Queue ──dequeue──▶ Celery Worker
                                         （persistence、retry、concurrency）
```

## 2.2 Redis queueprimitive

Redis 是最常用的message queue后端。它的核心queue操作只有三个：

| command | 作用 | blocking版 |
|---|---|---|
| `RPUSH queue item` | 从右侧推入元素（producer） | — |
| `LPUSH queue item` | 从左侧推入元素 | — |
| `RPOP queue` | 从右侧弹出元素（consumer） | `BRPOP` |
| `LRANGE queue 0 -1` | viewqueue全部内容 | — |

### 2.2.1 blocking弹出：BRPOP

`RPOP` 在queue为空时会立即返回 `nil`，导致consumer必须不断polling（**忙polling浪费 CPU**）。`BRPOP` 是blockingversion：当queue为空时，客户端挂起等待，直到有新元素入队或超时。

```python
import redis

r = redis.Redis(host='localhost', port=6379, db=0)

# producer：推入task
r.rpush('tasks', 'task_001')
r.rpush('tasks', 'task_002')

# consumer：blocking等待（最多等 5 秒）
item = r.brpop('tasks', timeout=5)
# item 形如 (b'tasks', b'task_001')
if item:
    queue_name, task_id = item
    print(f'Got task: {task_id.decode()}')
else:
    print('No tasks in queue')
```

### 2.2.2 多queue广播：BRPOPLPUSH

一个常见需求是"优先级queue"：将低优先级task从普通queue搬到降级queue，等主queue清空后再process。

```python
# 将task从 'high' queue移到 'low' queue（原子操作）
result = r.brpoplpush('high', 'low', timeout=5)
```

## 2.3 Celery Introduction：configuration与 Task 定义

Celery 是一个distributedtaskqueue框架，支持多种 Broker（Redis、RabbitMQ、Amazon SQS 等）。我们用 Redis 作为 Broker。

### 2.3.1 安装

```bash
pip install -U celery[redis] redis
```

启动 Redis service（使用 Docker 最简单）：

```bash
docker run -d --name redis-queue -p 6379:6379 redis:7-alpine
```

### 2.3.2 定义 Celery App 和 Task

```python
# app.py
from celery import Celery

app = Celery(
    'agent_worker',
    broker='redis://localhost:6379/0',
    backend='redis://localhost:6379/1',
)

# 设置时区与序列化
app.conf.update(
    task_serializer='json',
    result_serializer='json',
    accept_content=['json'],
    timezone='Asia/Shanghai',
    enable_utc=True,
)
```

### 2.3.3 定义一个简单 Task

```python
# tasks.py
from app import app
import time

@app.task(bind=True, max_retries=3)
def call_llm(self, prompt: str, model: str = "gpt-4o-mini") -> dict:
    """模拟 LLM 调用（实际项目中替换为真实 API 调用）"""
    try:
        # 模拟 API 调用延迟
        time.sleep(2)
        return {
            "model": model,
            "response": f"这是针对 '{prompt}' 的模拟回复",
            "tokens": 42,
        }
    except Exception as exc:
        # 自动retry，指数退避
        raise self.retry(exc=exc, countdown=2 ** self.request.retries)
```

### 2.3.4 启动 Worker

```bash
# 在终端 1 启动 Worker（监听 redis queue）
celery -A tasks worker --loglevel=info --concurrency=4
```

### 2.3.5 submittask

```python
# 同步submit，立即返回 AsyncResult
result = call_llm.delay("什么是大语言模型？", model="gpt-4o")
print(f"task ID: {result.id}")

# blocking等待result（不推荐在生产中使用，会占用连接）
# response = result.get(timeout=30)

# non-blocking：定期检查状态
import time
while not result.ready():
    time.sleep(1)
print(f"complete！result: {result.get()}")
```

## 2.4 Agent asynctask模式：LLM 调用入队

在 Agent service中，LLM 调用通常是**最慢的环节**（网络延迟 + 生成时间）。把它放入queue可以让 FastAPI 立即返回task ID，客户端通过polling或 WebSocket 获取result。

```python
# agent_tasks.py
from app import app
from openai import AsyncOpenAI
import asyncio

client = AsyncOpenAI(api_key="sk-...")

@app.task(bind=True, max_retries=5, retry_backoff=True)
def generate_agent_response(
    self,
    messages: list[dict],
    tools: list[dict] | None = None,
) -> dict:
    """
    Agent 核心推理task：
    - 将多轮对话送入 LLM
    - 解析 tool_calls 并execute（由 Worker 内部complete）
    - 返回final文本响应
    """
    try:
        # 调用 LLM（此处用 OpenAI SDK，可替换为任意 Provider）
        response = asyncio.run(
            client.chat.completions.create(
                model="gpt-4o",
                messages=messages,
                tools=tools or [],
            )
        )
        choice = response.choices[0]
        return {
            "role": choice.message.role,
            "content": choice.message.content,
            "tool_calls": [
                {
                    "id": tc.id,
                    "function": {
                        "name": tc.function.name,
                        "arguments": tc.function.arguments,
                    },
                }
                for tc in choice.message.tool_calls or []
            ],
        }
    except Exception as exc:
        # retry_backoff=True 时 Celery 自动指数退避retry
        raise self.retry(exc=exc)
```

### 2.4.1 FastAPI endpoint：submittask并立即返回

```python
# main.py
from fastapi import FastAPI, HTTPException
from agent_tasks import generate_agent_response

app = FastAPI(title="Agent asyncservice")

@app.post("/chat")
async def chat_endpoint(prompt: str, model: str = "gpt-4o"):
    """
    submit对话task，立即返回 task_id。
    客户端用 task_id pollingresult。
    """
    task = generate_agent_response.delay(
        messages=[{"role": "user", "content": prompt}],
        model=model,
    )
    return {"task_id": task.id, "status": "queued"}

@app.get("/chat/{task_id}")
async def get_result(task_id: str):
    """pollingtaskresult"""
    from celery.result import AsyncResult
    result = AsyncResult(task_id)

    if result.state == "PENDING":
        return {"status": "pending"}
    if result.state == "STARTED":
        return {"status": "processing"}
    if result.state == "FAILURE":
        raise HTTPException(status_code=500, detail=str(result.result))
    if result.state == "SUCCESS":
        return {"status": "done", "result": result.result}
    return {"status": result.state}
```

## 2.5 retrystrategy详解

生产环境中 LLM API 经常遇到rate limiting（429）或超时。Celery 提供两种retry机制：

### 2.5.1 task级别retry（bind=True）

```python
@app.task(bind=True, max_retries=5, retry_backoff=True)
def robust_llm_call(self, prompt: str):
    try:
        return do_api_call(prompt)
    except RateLimitError:
        # retry_backoff=True：第1次等1s，第2次等2s，第3次等4s...
        raise self.retry(exc=self.__class__.exc, countdown=2 ** self.request.retries)
    except ConnectionError:
        # ConnectionError 立即retry，不等
        raise self.retry(exc=self.__class__.exc, max_retries=10)
```

### 2.5.2 全局默认configuration

```python
app.conf.update(
    # 所有 task 默认最多retry 3 次
    task_default_max_retries = 3,
    # 启用指数退避（需要 bind=True）
    task_default_retry_backoff = True,
    # 退避基准（秒）
    task_default_retry_backoff_base = 2,
    # task超时（硬超时，Worker 内强制 kill）
    task_soft_time_limit = 120,   # 软超时：引发 SoftTimeLimitExceeded
    task_time_limit = 180,        # 硬超时：直接 kill Worker 子进程
)
```

## 本章Summary

1. **Redis queueprimitive**：`RPUSH`/`LPOP` Implement FIFO，`BRPOP` Implementblocking消费，avoid忙polling；
2. **Celery configuration**：`broker`（task来源）和 `backend`（result存储）都指向 Redis 的不同数据库；
3. **Task 定义**：用 `@app.task` 装饰函数，`bind=True` 可获得 `self` 以调用retry；
4. **延迟submit**：`task.delay(...)` 返回 `AsyncResult`，不blocking FastAPI 请求；
5. **pollingresult**：通过 `/chat/{task_id}` 接口查询 `AsyncResult.state`，process PENDING/STARTED/SUCCESS/FAILURE 四种状态；
6. **retrystrategy**：`retry_backoff=True` 启用指数退避，`max_retries` 限制最大尝试次数。

> 📌 更高级的async交互模式（WebSocket 实时推送result、Server-Sent Events）在 [LangGraph ch08](./ch08.md) 中讲解，本章先Masterpolling模式即可。
