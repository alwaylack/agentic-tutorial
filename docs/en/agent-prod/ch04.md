## 4.1 Why Do We Need LangGraph?

LangChain agents provide out-of-the-box architectures (such as ReAct, Plan-and-Execute), but lack fine-grained control over execution flow. LangGraph fills this gap:

> LangGraph is a low-level orchestration framework and runtime for building, managing, and deploying long-running stateful Agents. It allows you to mix deterministic logic with LLM-driven decisions in the same graph.

Core differences:

| Feature | LangChain Agents | LangGraph |
|---|---|---|
| Abstraction level | High-level | Low-level |
| Flow control | Black-box loop | Explicit graph structure |
| State persistence | Limited | Built-in Checkpointer |
| Human-in-the-loop | Not supported | Native support |
| Debugging | Difficult | LangSmith visualization |

## 4.2 Minimal Hello World

```python
from langgraph.graph import StateGraph, MessagesState, START, END

# Define node: simple LLM call
def mock_llm(state: MessagesState) -> dict:
    return {
        "messages": [
            {"role": "assistant", "content": "Hello from LangGraph!"}
        ]
    }

# Build graph
graph = StateGraph(MessagesState)
graph.add_node("llm", mock_llm)
graph.add_edge(START, "llm")
graph.add_edge("llm", END)
compiled = graph.compile()

# Execute
result = compiled.invoke({
    "messages": [{"role": "user", "content": "hi!"}]
})
print(result["messages"][-1]["content"])
```

## 4.3 StateGraph Core Concepts

```python
from langgraph.graph import StateGraph, MessagesState, START, END
from typing import TypedDict

# Custom state: extend MessagesState with metadata
class AgentState(MessagesState):
    context: list[str]  # Retrieved context
    step_count: int     # Number of executed steps
    final_answer: str   # Final answer

# Node functions
def search_node(state: AgentState) -> dict:
    """Retrieve relevant documents"""
    return {
        "context": ["Document A content", "Document B content"],
        "step_count": state.get("step_count", 0) + 1
    }

def llm_node(state: AgentState) -> dict:
    """Call LLM to generate answer"""
    context = " ".join(state.get("context", []))
    return {
        "messages": [{"role": "assistant", "content": f"Based on context: {context}"}],
        "step_count": state["step_count"] + 1
    }

# Build graph
workflow = StateGraph(AgentState)
workflow.add_node("search", search_node)
workflow.add_node("llm", llm_node)
workflow.add_edge(START, "search")
workflow.add_edge("search", "llm")
workflow.add_edge("llm", END)

graph = workflow.compile()
```

## 4.4 Relationship with LangChain Agents

```python
# LangGraph can be combined with LangChain components
from langchain.chat_models import ChatOpenAI
from langchain.tools import tool

@tool
def get_weather(city: str) -> str:
    """Get city weather"""
    return f"{city} is sunny today, 25°C"

# Use LangChain's LLM + LangGraph's graph orchestration
llm = ChatOpenAI(model="gpt-4o-mini")
# ... Encapsulate LLM call as graph node
```

## 4.5 Compilation and Execution Modes

```python
# Synchronous execution
result = graph.invoke({"messages": [...]})

# Streaming execution (see Chapter 8)
for event in graph.stream({"messages": [...]}):
    print(event)

# Async execution
async_result = await graph.ainvoke({"messages": [...]})
```

## Chapter Summary

- LangGraph is a low-level orchestration runtime providing fine-grained graph structure control
- `StateGraph` + `MessagesState` is the minimal starting unit
- Custom state extends `MessagesState` with additional fields
- Can be mixed with LangChain components
