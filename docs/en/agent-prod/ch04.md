## 4.1 Why Do We Need LangGraph?

LangChain agents provide out-of-the-box architectures (ReAct, Plan-and-Execute), but lack control over execution flow. For production Agent systems, we need:

- **Explicit control flow**: Conditional routing based on state
- **Cycles and loops**: Agent can iteratively refine responses
- **Persistence**: Checkpoint and restore execution state
- **Human-in-the-loop**: Pause for approval before action

LangGraph addresses these needs as a **state machine** for Agent orchestration.

---

## 4.2 StateGraph: The Core Abstraction

A LangGraph graph consists of:
- **State**: A typed dictionary carrying information through the graph
- **Nodes**: Functions that transform state
- **Edges**: Transitions between nodes (conditional or normal)

### 4.2.1 Minimal Example

```python
from langgraph.graph import StateGraph, MessagesState, START, END
from langchain_core.messages import HumanMessage, AIMessage

# Define state
class GraphState(MessagesState):
    next_step: str = ""

# Define nodes
def chatbot(state: GraphState) -> dict:
    # Simple LLM call
    response = "Hello! How can I help?"
    return {"messages": [AIMessage(content=response)]}

def classifier(state: GraphState) -> dict:
    last_msg = state["messages"][-1]
    if "bye" in last_msg.content.lower():
        return {"next_step": "end"}
    return {"next_step": "chatbot"}

# Build graph
workflow = StateGraph(GraphState)
workflow.add_node("chatbot", chatbot)
workflow.add_node("classifier", classifier)

workflow.add_edge(START, "classifier")
workflow.add_conditional_edges(
    "classifier",
    lambda x: x["next_step"],
    {"chatbot": "chatbot", "end": END}
)

graph = workflow.compile()
```

### 4.2.2 Execution Flow

```
START → classifier → chatbot → classifier → ... → END
              ↑                              │
              └────────── loop ──────────────┘
```

## 4.3 MessagesState: Built-in State Type

`MessagesState` is LangGraph's built-in state type, containing `messages` field:

```python
from langgraph.graph import MessagesState

# State schema (automatically handled)
{
    "messages": [
        {"role": "user", "content": "Hello"},
        {"role": "assistant", "content": "Hi!"},
    ]
}
```

### 4.3.1 Why MessagesState?

- Automatic message appending
- Compatible with LangChain's message format
- Supports streaming updates

## 4.4 Custom State Types

Extend `TypedDict` for custom state:

```python
from typing import TypedDict, Annotated
import operator

class AgentState(TypedDict):
    # Messages (auto-appended)
    messages: Annotated[list, operator.add]
    
    # Custom fields
    user_id: str
    context: dict
    tool_calls: list
```

### 4.4.1 Annotation Types

| Annotation | Behavior |
|---|---|
| `operator.add` | Append to list (messages) |
| `lambda a, b: b` | Override (last wins) |
| `lambda a, b: a + b` | Concatenate strings |

## 4.5 LangGraph Runtime vs Deep Agents Harness

| Feature | LangGraph Runtime | Deep Agents Harness |
|---|---|---|
| Level | Low-level orchestration | High-level Agent framework |
| Control | Full control over state/flow | Simplified API |
| Learning Curve | Steeper | Gentler |
| Use Case | Custom Agent workflows | Quick prototyping |

> 📌 **Deep Agents** (covered in Chapter 9) builds on LangGraph, providing simplified abstractions for common patterns.

---

## Chapter Summary

1. **Why LangGraph**: Need explicit control flow, cycles, persistence, human-in-the-loop;
2. **StateGraph**: Nodes transform state, edges define transitions;
3. **MessagesState**: Built-in state with automatic message handling;
4. **Custom State**: Extend TypedDict with annotations for list/override behavior;
5. **Runtime vs Harness**: LangGraph is low-level, Deep Agents is high-level abstraction.
