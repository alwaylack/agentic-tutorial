## 3.1 distributedlock：preventduplicate consumption

当多个 Celery Worker 同时监听同 aqueue时，可能出现「 atask be多个 Worker 抢走」 of情况。use Redis  of `SET NX EX` Implementatomicitymutual exclusionlock：

```python
# services/agent/redis_lock.py
import redis
import uuid
from contextlib import contextmanager

r = redis.from_url("redis://redis:6379/0")


@contextmanager
def distributed_lock(lock_name: str, ttl: int = 30):
    """
    use Redis SET NX EX Implement可重入distributedlock。

    - NX：键不存in才设置（mutual exclusion）
    - EX：过期时间（prevent Worker 崩溃后lock永不过期）
    - unique token：保证只有持lock者能释放lock
    """
    token = str(uuid.uuid4())
    acquired = r.set(lock_name, token, nx=True, ex=ttl)
    if not acquired:
        raise RuntimeError(f"无法获取lock: {lock_name}")
    try:
        yield
    finally:
        # Lua 脚本保证「检查 token + 删除」的atomicity
        lua = """
        if redis.call("get", KEYS[1]) == ARGV[1] then
            return redis.call("del", KEYS[1])
        else
            return 0
        end
        """
        r.eval(lua, 1, lock_name, token)
```

### in Celery task中使use

```python
# services/agent/tasks.py
from celery import shared_task
from .redis_lock import distributed_lock


@shared_task(bind=True, max_retries=3)
def process_agent_task(self, task_id: str, user_input: str):
    """
    usedistributedlock确保同一 task_id in同一时刻只被一个 Worker handle。
    """
    lock_name = f"agent:task:{task_id}"
    with distributed_lock(lock_name, ttl=60):
        # 业务逻辑：调use LangGraph 图
        result = run_agent_graph(user_input)
        return {"task_id": task_id, "result": result}
```

** for whatuse Lua 脚本释放lock？**

 such as果只use `GET` + `DEL` 两步，存inrace condition条件：Worker A 拿 tolock后崩溃，Worker B in过期前检查 tolock存in就会跳过，直 to TTL  to期。而「检查 token + 删除」use Lua 脚本保证atomicity，avoid误删他人持有 oflock。

## 3.2 idempotency设计：uniquetask ID  anddeduplication

distributed环境下task可能重复投递（网络抖动、Worker 重试）。解决方案：

1. **客户端生成unique task_id**（UUID v7，含timestamp可sort）
2. **task开始前查deduplication表**，已handle则直接returnscacheresult
3. **taskcomplete后写入result表**

```python
# services/agent/idempotency.py
import uuid
from datetime import datetime
import redis

r = redis.from_url("redis://redis:6379/0")


def generate_task_id() -> str:
    """生成 UUID v7，便于时间sort和index。"""
    return str(uuid.uuid7())


def check_duplicate(task_id: str) -> bool:
    """
    检查 task_id 是否已被processed。
    Redis SET NX atomic operation：首次returns True（未handle），重复returns False。
    """
    key = f"idempotent:{task_id}"
    return bool(r.set(key, "1", nx=True, ex=3600))  # 1 小时过期


def cache_result(task_id: str, result: dict) -> None:
    """cache任务结果，供重复请求直接returns。"""
    r.setex(f"result:{task_id}", 300, str(result))  # 5 分钟 TTL
```

```python
# services/agent/tasks.py
from .idempotency import generate_task_id, check_duplicate, cache_result


@shared_task
def handle_agent_request(user_input: str):
    task_id = generate_task_id()

    if not check_duplicate(task_id):
        return {"task_id": task_id, "status": "duplicate", "note": "任务已handle"}

    # 执行 Agent 逻辑...
    result = {"response": "Agent 输出...", "task_id": task_id}
    cache_result(task_id, result)
    return result
```

> 💡 **生产建议**：high frequencyscenario下use Postgres deduplication表replace Redis，utilize `INSERT ... ON CONFLICT DO NOTHING` Implementstrong consistencydeduplication。详见 [FastAPI 课程第 13 章](/fastapi/ch13)。

## 3.3 Docker 多stage构建：optimize Python image

Python image默认带完整 GCC 和development headers，volume可达 1GB。多stage构建 can大幅缩小：

```dockerfile
# services/agent/Dockerfile
FROM python:3.12-slim AS base

# stage 1：Installation系统dependency
FROM base AS builder
RUN apt-get update && apt-get install -y --no-install-recommends \
    gcc libpq-dev && \
    rm -rf /var/lib/apt/lists/*

# 复制dependency文件并Installation Python 包
COPY requirements.txt .
RUN pip install --no-cache-dir --prefix=/install -r requirements.txt

# stage 2：minimalfinalimage
FROM base
WORKDIR /app
COPY --from=builder /install /usr/local
COPY . .

# non-root use户Run
RUN useradd -m agentuser && chown -R agentuser /app
USER agentuser

EXPOSE 8000
CMD ["uvicorn", "services.agent.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

**关键optimize点**：

| optimize项 | 效果 |
|---|---|
| `python:3.12-slim` | 基础image from 1GB 降 to ~150MB |
| `--no-install-recommends` | avoidInstallation不必要 of推荐包 |
| `--no-cache-dir` | pip 不cachewheel，减少imagevolume |
| non-root use户 | securitybest practice，preventcontainer escape |

## 3.4 docker-compose.yml：orchestrate多容器service

 a生产 Agent service通常包含：FastAPI gateway、Celery Worker、Redis、Postgres。use `docker-compose.yml` start with one click：

```yaml
# docker-compose.yml
services:
  api:
    build:
      context: .
      dockerfile: services/agent/Dockerfile
    ports:
      - "8000:8000"
    environment:
      - REDIS_URL=redis://redis:6379/0
      - DATABASE_URL=postgresql://agent:agent@postgres:5432/agentdb
      - CELERY_BROKER_URL=redis://redis:6379/1
      - CELERY_RESULT_BACKEND=redis://redis:6379/2
    depends_on:
      redis: { condition: service_healthy }
      postgres: { condition: service_healthy }
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/health"]
      interval: 30s
      timeout: 10s
      retries: 3

  worker:
    build:
      context: .
      dockerfile: services/agent/Dockerfile
    command: celery -A services.agent.celery_app worker --loglevel=info
    environment:
      - REDIS_URL=redis://redis:6379/0
      - DATABASE_URL=postgresql://agent:agent@postgres:5432/agentdb
      - CELERY_BROKER_URL=redis://redis:6379/1
    depends_on:
      redis: { condition: service_healthy }
      postgres: { condition: service_healthy }

  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"
    volumes:
      - redis_data:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 5s
      retries: 5

  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: agent
      POSTGRES_PASSWORD: agent
      POSTGRES_DB: agentdb
    ports:
      - "5432:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U agent"]
      interval: 10s
      timeout: 5s
      retries: 5

volumes:
  redis_data:
  postgres_data:
```

> 📌 **health check**：`depends_on.condition: service_healthy` 确保dependencyservicetrulyavailable后才启动，avoidrace condition。

## 3.5 health check andgraceful shutdown

### FastAPI 健康endpoint

```python
# services/agent/main.py
from fastapi import FastAPI
from redis import Redis
import psycopg2

app = FastAPI()


@app.get("/health")
async def health_check():
    checks = {}

    # Redis connectivity
    try:
        r = Redis.from_url("redis://redis:6379/0")
        checks["redis"] = r.ping()
    except Exception as e:
        checks["redis"] = False

    # Postgres connectivity
    try:
        conn = psycopg2.connect("postgresql://agent:agent@postgres:5432/agentdb")
        conn.close()
        checks["postgres"] = True
    except Exception:
        checks["postgres"] = False

    healthy = all(checks.values())
    status_code = 200 if healthy else 503
    return {"status": "healthy" if healthy else "unhealthy", "checks": checks}, status_code
```

### Celery Worker graceful shutdown

```python
# services/agent/celery_app.py
from celery import Celery
import signal
import sys

app = Celery("agent", broker="redis://redis:6379/1")
app.conf.update(
    task_serializer="json",
    result_serializer="json",
    accept_content=["json"],
    timezone="UTC",
    enable_utc=True,
)


def graceful_shutdown(signum, frame):
    print("收到退出signal，completecurrent任务后stop...")
    sys.exit(0)


signal.signal(signal.SIGTERM, graceful_shutdown)
signal.signal(signal.SIGINT, graceful_shutdown)
```

> 💡 **Docker signalpass**：in Dockerfile 中添加 `ENTRYPOINT ["tini", "--"]` 确保进程能correctlyreceive SIGTERM signal。
