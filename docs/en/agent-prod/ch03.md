## 3.1 Distributed Lock: Preventing Duplicate Consumption

When multiple Celery Workers listen to the same queue simultaneously, "one task being grabbed by multiple Workers" may occur. Implement atomic mutual exclusion lock using Redis `SET NX EX`:

```python
# services/agent/redis_lock.py
import redis
import uuid
from contextlib import contextmanager

r = redis.from_url("redis://redis:6379/0")


@contextmanager
def distributed_lock(lock_name: str, ttl: int = 30):
    """
    Implement reentrant distributed lock using Redis SET NX EX.

    - NX: Set only if key doesn't exist (mutual exclusion)
    - EX: Expiration time (prevent lock from never expiring after Worker crash)
    - Unique token: Ensure only the lock holder can release the lock
    """
    token = str(uuid.uuid4())
    acquired = r.set(lock_name, token, nx=True, ex=ttl)
    if not acquired:
        raise RuntimeError(f"Cannot acquire lock: {lock_name}")
    try:
        yield
    finally:
        # Lua script ensures atomicity of "check token + delete"
        lua = """
        if redis.call("get", KEYS[1]) == ARGV[1] then
            return redis.call("del", KEYS[1])
        else
            return 0
        end
        """
        r.eval(lua, 1, lock_name, token)
```

### Using in Celery Task

```python
# services/agent/tasks.py
from celery import shared_task
from .redis_lock import distributed_lock


@shared_task(bind=True, max_retries=3)
def process_agent_task(self, task_id: str, user_input: str):
    """
    Use distributed lock to ensure same task_id is processed by only one Worker at a time.
    """
    lock_name = f"agent:task:{task_id}"
    with distributed_lock(lock_name, ttl=60):
        # Business logic: call LangGraph graph
        result = run_agent_graph(user_input)
        return {"task_id": task_id, "result": result}
```

**Why use Lua script to release lock?**

If only using `GET` + `DEL` two steps, there's a race condition: after Worker A gets the lock and crashes, Worker B checks and sees the lock exists before TTL expires, so it skips until TTL expires. "Check token + delete" using Lua script ensures atomicity, preventing accidental deletion of locks held by others.

## 3.2 Idempotency Design: Unique Task ID and Deduplication

In distributed environments, tasks may be delivered repeatedly (network jitter, Worker retry). Solution:

1. **Client generates unique task_id** (UUID v7, timestamp-sortable)
2. **Check dedup table before task starts**, if already processed, return cached result directly
3. **Write result table after task completes**

```python
# services/agent/idempotency.py
import uuid
from datetime import datetime
import redis

r = redis.from_url("redis://redis:6379/0")


def generate_task_id() -> str:
    """Generate UUID v7,便于 time sorting and indexing."""
    return str(uuid.uuid7())


def check_duplicate(task_id: str) -> bool:
    """
    Check if task_id has been processed.
    Redis SET NX atomic operation: returns True first time (not processed), False on duplicate.
    """
    key = f"idempotent:{task_id}"
    return bool(r.set(key, "1", nx=True, ex=3600))  # 1 hour expiry


def cache_result(task_id: str, result: dict) -> None:
    """Cache task result for direct return on duplicate requests."""
    r.setex(f"result:{task_id}", 300, str(result))  # 5 minute TTL
```

```python
# services/agent/tasks.py
from .idempotency import generate_task_id, check_duplicate, cache_result


@shared_task
def handle_agent_request(user_input: str):
    task_id = generate_task_id()

    if not check_duplicate(task_id):
        return {"task_id": task_id, "status": "duplicate", "note": "Task already processed"}

    # Execute Agent logic...
    result = {"response": "Agent output...", "task_id": task_id}
    cache_result(task_id, result)
    return result
```

> 💡 **Production tip**: For high-frequency scenarios, use Postgres dedup table instead of Redis, leveraging `INSERT ... ON CONFLICT DO NOTHING` for strong consistency dedup. See [FastAPI Chapter 13](/fastapi/ch13).

## 3.3 Docker Multi-Stage Build: Optimizing Python Image

Python images come with full GCC and development headers by default, reaching 1GB. Multi-stage build can significantly reduce size:

```dockerfile
# services/agent/Dockerfile
FROM python:3.12-slim AS base

# Stage 1: Install system dependencies
FROM base AS builder
RUN apt-get update && apt-get install -y --no-install-recommends \
    gcc libpq-dev && \
    rm -rf /var/lib/apt/lists/*

# Copy dependency files and install Python packages
COPY requirements.txt .
RUN pip install --no-cache-dir --prefix=/install -r requirements.txt

# Stage 2: Minimal final image
FROM base
WORKDIR /app
COPY --from=builder /install /usr/local
COPY . .

# Run as non-root user
RUN useradd -m agentuser && chown -R agentuser /app
USER agentuser

EXPOSE 8000
CMD ["uvicorn", "services.agent.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

**Key optimization points**:

| Optimization | Effect |
|---|---|
| `python:3.12-slim` | Base image reduced from 1GB to ~150MB |
| `--no-install-recommends` | Avoid installing unnecessary recommended packages |
| `--no-cache-dir` | pip doesn't cache wheels, reducing image size |
| Non-root user | Security best practice, prevents container escape |

## 3.4 docker-compose.yml: Orchestrating Multi-Container Services

A production Agent service typically includes: FastAPI gateway, Celery Worker, Redis, Postgres. Use `docker-compose.yml` for one-click startup:

```yaml
# docker-compose.yml
services:
  api:
    build:
      context: .
      dockerfile: services/agent/Dockerfile
    ports:
      - "8000:8000"
    environment:
      - REDIS_URL=redis://redis:6379/0
      - DATABASE_URL=postgresql://agent:agent@postgres:5432/agentdb
      - CELERY_BROKER_URL=redis://redis:6379/1
      - CELERY_RESULT_BACKEND=redis://redis:6379/2
    depends_on:
      redis: { condition: service_healthy }
      postgres: { condition: service_healthy }
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/health"]
      interval: 30s
      timeout: 10s
      retries: 3

  worker:
    build:
      context: .
      dockerfile: services/agent/Dockerfile
    command: celery -A services.agent.celery_app worker --loglevel=info
    environment:
      - REDIS_URL=redis://redis:6379/0
      - DATABASE_URL=postgresql://agent:agent@postgres:5432/agentdb
      - CELERY_BROKER_URL=redis://redis:6379/1
    depends_on:
      redis: { condition: service_healthy }
      postgres: { condition: service_healthy }

  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"
    volumes:
      - redis_data:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 5s
      retries: 5

  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: agent
      POSTGRES_PASSWORD: agent
      POSTGRES_DB: agentdb
    ports:
      - "5432:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U agent"]
      interval: 10s
      timeout: 5s
      retries: 5

volumes:
  redis_data:
  postgres_data:
```

> 📌 **Health check**: `depends_on.condition: service_healthy` ensures dependent services are truly available before starting, avoiding race conditions.

## 3.5 Health Check and Graceful Shutdown

### FastAPI Health Endpoint

```python
# services/agent/main.py
from fastapi import FastAPI
from redis import Redis
import psycopg2

app = FastAPI()


@app.get("/health")
async def health_check():
    checks = {}

    # Redis connectivity
    try:
        r = Redis.from_url("redis://redis:6379/0")
        checks["redis"] = r.ping()
    except Exception as e:
        checks["redis"] = False

    # Postgres connectivity
    try:
        conn = psycopg2.connect("postgresql://agent:agent@postgres:5432/agentdb")
        conn.close()
        checks["postgres"] = True
    except Exception:
        checks["postgres"] = False

    healthy = all(checks.values())
    status_code = 200 if healthy else 503
    return {"status": "healthy" if healthy else "unhealthy", "checks": checks}, status_code
```

### Celery Worker Graceful Shutdown

```python
# services/agent/celery_app.py
from celery import Celery
import signal
import sys

app = Celery("agent", broker="redis://redis:6379/1")
app.conf.update(
    task_serializer="json",
    result_serializer="json",
    accept_content=["json"],
    timezone="UTC",
    enable_utc=True,
)


def graceful_shutdown(signum, frame):
    print("Received exit signal, stopping after completing current task...")
    sys.exit(0)


signal.signal(signal.SIGTERM, graceful_shutdown)
signal.signal(signal.SIGINT, graceful_shutdown)
```

> 💡 **Docker signal passing**: Add `ENTRYPOINT ["tini", "--"]` in Dockerfile to ensure process can correctly receive SIGTERM signal.
