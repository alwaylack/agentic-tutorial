## 29.1 Five Safety Mechanisms

Loops amplify the judgments youplant with machine execution power; therefore safety mechanisms are the**minimum配置** for production loops, not optional:

### 1. Path Denylist

The following paths **must never be auto-modified by the loop**; hitting them必须 escalate to a human:

```text
.env / .env.*
**/secrets/**  **/credentials/**  **/*_key*  **/*_secret*
.terraform/**  k8s/production/**
**/migrations/**          # unless it's a专门 migration loop
auth/**  payments/**  billing/**
```

Key design: the denylist doesn't rely on "写 a sentence in the system prompt not to modify" to执行; it's enforcedmechanically via the `loop-gate` tool — `loop-gate check --action <type> --paths <files>` exits with code 2 on denylist hits,强制 escalation; control scripts can链式 judge.

### 2. Auto-Merge Allowlist

Default strategy: **auto-merge is禁止**. Only truly trivial changes才进 the allowlist:

| Auto-merge allowed | Absolutely not allowed |
|---|---|
| Comment/doc typos | Any behavioral change |
| Lint auto-fix within test files only | Dependency version upgrades |
| Import排序 | Lock file changes |
| Config within allowlisted `docs/` paths | Any denylist path |

### 3. Human Gates

The following scenarios无条件 wait for a human: security/auth/zation-related, payment and PII, infrastructure (Terraform/K8s production), dependency upgrades, a single change exceeding N files (recommend N=10), the third attempt on the same item still failing, and budgetincrease requests.

### 4. MCP Least Privilege

| Connector | Allowed read | Allowed write |
|---|---|---|
| GitHub | issues, PR, checks | comments, labels (**默认不给 merge**) |
| Linear | team issues | comments, change status (no删除) |
| Slack | channel history | only to `#loop-escalations` |
| Database | — | **禁止生产库写入** |

Use an独立 bot account and a least-scope token; let each loop action be追溯able to the bot identity.

### 5. Worktree Isolation

All code-writing actions发生 in an独立 git worktree: failure → discard; success →走 the PR流程;配合 `loop-worktree` to achieve "one attempt per worktree; reject and清扫."

## 29.2 Official Failure Mode Catalog深读

The official分级 failures by severity into S1 (annoying) / S2 (harmful) / S3 (critical). Five经典形态:

| Failure Mode | Symptom | Root Cause | Mitigation |
|---|---|---|---|
| **Infinite Fix Loop** | The same PR被 auto-fixed 5+ times and stilldoesn't pass | The verifier is too弱 or in the same session as the implementer; only治 symptoms | Hard上限 on attempts (3) → escalate; independent verifier; isolate flaky tests instead of改代码 |
| **State Rot** | The state file references merged PRs, closed tickets | Not cleaned at the end of each round; multiple loops乱写 the same file | Trim each round; verify IDs are still存活; one state file per模式 |
| **Verifier Theater** | The verifier "passes" but CI is clearly red | The verification prompt is too vague ("looks good"); never真正 ran tests | The verifier must run tests and贴 the output; change the指令 to "find reasons to reject" |
| **Notification Fatigue** | Slack rings every 5 minutes; the teammutes the bot | Notifying every run instead of only on "actionable findings" | Only notify when human决策 is needed; use摘要 mode for reports |
| **Token Burn** | The billspikes | Even an empty triage runs the全链路 sub-agents | Exit early if the empty observations list <5k tokens; budget file +熔断器 |

::: tip How to Use
The correct way to打开 this catalog is as a**debugging manual**: when the loop behavior is异常, first match the symptom to the table; then逐项排查 the mitigation —绝大多数事故 can找到原型 here.
:::

## 29.3 Design Anti-Patterns: Eliminate Before Launch

Failure modes are "runtimeaccidents"; anti-patterns are "design-phaseerrors." The official lists seven; each has a clear "should do this":

```markdown
1. Same agent both implements and verifies   → 拆 out an独立 verifier; default stance REJECT
2. No attempt上限                 → Hard上限 3 → escalate with context
3. Triage output is narrative paragraphs    → Structured markdown; one line per item +明确建议 action
4. L1 quality未验证 before L3         → First report-only for a week; let数据 speak
5. Shared state has no schema          → One state file per模式; or clear分区 + trim rules
6. MCP starts with全 write权限        → L1 read-only connectors; earn trust before扩权
7. No stop switch               → LOOP.md写暂停/终止 conditions + budget file
```

## 29.4 Comprehension Debt, Intent Debt, and Cognitive Surrender

Loop Engineering provides a set of "operationalvocabulary" to help you名 thoseunclear失控感:

- **Intent Debt**: each round the agent cold-starts;缺失的项目意图 arefilled by "confident guesses." Skills are the还债方式 —约定 write once, read every round;
- **Comprehension Debt**: the差距 between what exists in the repo and what you实际 understand. The faster the loopruns, the faster "code you didn't写" piles up — **unless you坚持 read what the loopproduces**;
- **Cognitive Surrender**: the mostdangerous trap — letting the looprun, while you停止持有观点. Designing loops requires judgment; using loops to逃避 thinking is an加速器: the same action, opposite outcomes;
- **Orchestration Tax**: the协调人力 cost of parallel agents — review bandwidth, merge conflicts, context switching. Worktrees解决机械冲突, but **the上限 of parallel loops you can消化 is always yourself**.

## 29.5 Operational Points: Slowing Down, Pausing, and Terminating

### When to Slow Down / Pause

```text
Slow-down signals: token budget >80% used mid-week | triage false positive rate >30% | the same item escalated 2+ times within 48h
Pause signals: production incident in progress (the loop may interfere with热修) | destructive schema migration in progress | key reviewer on vacation and auto-merge is on
```

### When to Terminate the Loop

Consider杀掉 the loop when any of the following occurs: consecutive S2-level failures; cost高于价值 for two连续 weeks; the team has muteda all its notifications; the模式 has been取代 by an event-driven solution (e.g. pure CI Action).

The termination清单 three steps:

```bash
# 1. Stop scheduling: delete the timer / disable Automation / remove the GitHub Action
# 2. Archive the state:标记 the state file as retired
mv STATE.md STATE.retired-2026-06.md
# 3. Post-mortem (optional but stronglyrecommended): write the experience as a story;参考 for next design
```
