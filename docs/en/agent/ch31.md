## 31.2 The Capstone Goal: Daily Code Review Loop

We will落地 the most classic variant from [loop-engineering](https://github.com/cobusgreyling/loop-engineering)'s seven patterns — **Daily Triage** — auto-reviewing yesterday's commits and PRs every morning;产出 a priority list; handing risk items to humanGate.

### Step 1:固化工 Project Conventions with AGENTS.md

### Step 2:封装 the Review Criteria as a Skill

Review rules will get长; stuffing them into AGENTS.md would blow up常驻 context — encapsulate as a skill per the progressive disclosure principle:

```markdown

description: Review commits and PRs per team standards: check test coverage, error handling, security hazards; output severity grading. Use when the user asks for a code review or to review changes.
---

# Code Review Checklist

## Steps

1. Collect待 review changes using `git log` and `gh pr list`;
2. Check each change item by item:
   - Whether带 tests; whether错误 paths are handled; whether there are hardcoded credentials;
3. Grade per references/severity-rubric.md: blocker / major / minor;
4. Output as a Markdown table; blocker置顶.

- Only report issues; don't顺手修复 (fixes are handled by the subsequent L2 loop).
- When unsure whether it's an issue,标记 as needs-human instead of guessing.
```

Note the ReAct思想 learned in Chapter 6隐藏s in the steps: **collect first (action) → thenjudge (reasoning) → then output**, instead of letting the模型一气生成 from thin air.

## 31.3 Layer Responsibility Boundary Quick Reference

| Layer | Question it Answers | Change Frequency | Failure Symptom |
|---|---|---|---|
| Prompt Engineering | How to make the model do each stepright | May调 each iteration | Output unstable; formatdrifts |
| MCP | What data and actions the agent can reach | When the toolset changes | The agent "can't see" PRs/CI |
| Skills | How to沉淀 and reuse standard processes | When the process evolves | Inconsistent做法 each time |
| AGENTS.md | What the rules of this project are | When project conventions change | The agentviolates team conventions |
| Loop | When to do it; how long; who covers | When the运行策略调整s | Either doesn't动 or失控 burns money |

Troubleshootingmnemonic: **wrong → check prompts; can'tdo → check MCP; messy → check Skill;不守规矩 → check AGENTS.md; won't动 or won'tstop → check Loop.**

## 31.4 Common Combined Anti-Patterns

1. **Stuffing everything into AGENTS.md**:常驻 context drowned by hundreds of lines of rules; the model反而抓不住 the重点 —长 processes should下沉 to Skills;
2. **Skipping L1直跳 L3**: unattended without a report period验证, equivalent to handing the production repo to an unsupervised intern;
3. **Relying entirely on裸拼 prompts for tools**: not using MCP; pasting API docs into the prompt and letting the模型 guess the调用方式 — brittle and wasteful of tokens;
4. **STATE.md无人 maintained**: the loopmakes decisions基于过期 memory; moredangerous than no state (loop-sync类 tools exist to防 this);
5. **Write operations without a human gate**: review-type loops can仅 report; but any auto-merge/deploy action必须有门禁 and allowlist (denylist / auto-merge allowlist).
