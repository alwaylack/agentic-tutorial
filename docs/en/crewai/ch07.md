# Chapter 7 · Built-in Tooling System

> Chapter goals: Master the installation and practical usage of `crewai-tools`, understand tool environment variable conventions, Agent binding patterns, and build a correct mental model of RAG-class tools.

## 7.1 Installing `crewai[tools]`

The CrewAI main package contains only the framework core; all officially maintained tools live in the separate `crewai-tools` package. The official recommendation is a single command to install both together:

```bash
# Install crewai core + crewai-tools toolset in one shot
pip install 'crewai[tools]'
```

::: warning Version correspondence
`crewai-tools` is released in lockstep with the `crewai` main package. Mixing versions from different eras (e.g., a new main package with a tools包 from a year ago) is the #1 source of "tool call errors" in the community. When upgrading, upgrade both together: `pip install -U 'crewai[tools]'`.
:::

## 7.2 Common Tools Quick Reference and Practice

These are the most commonly used non-RAG tools:

| Tool | Purpose | External requirement |
|---|---|---|
| `SerperDevTool` | Google search (returns summary + links) | `SERPER_API_KEY` |
| `ScrapeWebsiteTool` | Scrape full text from a specified URL | None |
| `FileReadTool` | Read files (supports multiple formats) | None |
| `DirectoryReadTool` | List directory structure | None |
| `CodeInterpreterTool` | Execute Python code for computation / data processing | None (runs locally) |
| `WebsiteSearchTool` | RAG search on website content | Requires embedding provider by default |

A complete "search → scrape → persist" research squad example:

```python
import os

from crewai import Agent, Crew, Process, Task, LLM
from crewai_tools import SerperDevTool, ScrapeWebsiteTool, FileReadTool

# All examples uniformly use OpenAI-compatible third-party models
llm = LLM(
    model="openai/deepseek-chat",                 # LiteLLM rule: provider/model
    base_url="https://api.deepseek.com/v1",       # Third-party OpenAI-compatible endpoint
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    temperature=0.7,
)

# Instantiate tools: the same tool instance can be reused across agents
search_tool = SerperDevTool()            # Web search (requires SERPER_API_KEY)
scrape_tool = ScrapeWebsiteTool()        # Scrape web page full text
file_tool = FileReadTool()               # Read local files

researcher = Agent(
    role="Senior Industry Researcher",
    goal="Find high-quality information about 'edge AI chips' with minimal searches",
    backstory="Ten years of tech industry analysis experience, skilled at quickly assessing source reliability.",
    llm=llm,
    tools=[search_tool, scrape_tool],   # Bind tools available to this agent
    verbose=True,
)

writer = Agent(
    role="Technical Editor",
    goal="Organize the researcher's findings into a clearly structured briefing",
    backstory="Rigorous technical writer who values factual accuracy.",
    llm=llm,
    tools=[file_tool],
    verbose=True,
)

t1 = Task(
    description="Search and scrape 2-3 articles on edge AI chip market trends; distill key points.",
    expected_output="A trend points list under 500 characters, each item sourced with a URL.",
    agent=researcher,
)
t2 = Task(
    description="Write a briefing based on the researcher's points; save to brief.md.",
    expected_output="Markdown-formatted briefing.",
    agent=writer,
    output_file="brief.md",             # Task-level persistence — more reliable than asking the agent to call a file tool
)

crew = Crew(agents=[researcher, writer], tasks=[t1, t2], process=Process.sequential)
crew.kickoff()
```

::: tip output_file vs file tools
When you need to "write the result to disk", prefer `Task(output_file=...)` over hoping the model calls a file tool itself — the former is guaranteed by the framework; the latter depends on the model's willingness.
:::

## 7.3 How Tools Bind to Agents

Three rules for tool binding worth remembering:

1. **Agent-level binding**: `Agent(tools=[...])` — only this agent can use these tools;
2. **Task-level append**: `Task(tools=[...])` — available only during that task's execution;
3. **Principle of least privilege**: only give agents the tools they truly need. More tools = higher model selection error rate, longer prompts, higher cost.

```python
# Task-level tool: only the "data summary" step is allowed to execute code
from crewai_tools import CodeInterpreterTool

analyst = Agent(
    role="Data Analyst",
    goal="Accurately compute sales data statistics",
    backstory="Senior analyst proficient in Python data processing.",
    llm=llm,
)

export_task = Task(
    description="Read sales.csv and compute a quarterly sales summary by region.",
    expected_output="Markdown table.",
    agent=analyst,
    tools=[CodeInterpreterTool()],   # Only this task can use it
)
```

## 7.4 Environment Variable Management

Almost all web-connected tools follow the "env var injection for keys" convention (e.g., `SERPER_API_KEY`). Recommended practice for production projects:

- Load via `.env` file + `python-dotenv` at the program entry; add `.env` to `.gitignore`;
- **Fail early** when keys are missing: check explicitly before creating the tool, rather than erroring halfway through execution.

```python
import os
from dotenv import load_dotenv

load_dotenv()  # Load env vars from .env

def require_env(key: str) -> str:
    """Raise immediately if a required env var is missing, avoiding mid-flight failures."""
    value = os.getenv(key)
    if not value:
        raise RuntimeError(f"Missing environment variable {key}, please configure in .env")
    return value

require_env("SERPER_API_KEY")      # Validate at startup
search_tool = SerperDevTool()
```

## 7.5 Correctly Understanding RAG-Class Tools

Tools with "Search" in the name fall into two categories — the most common beginner confusion:

- **Web search tools** (`SerperDevTool`, `ExaSearchTool`): call an external search engine on each invocation; fresh results but unpredictable;
- **RAG retrieval tools** (`PDFSearchTool`, `CSVSearchTool`, `DirectorySearchTool`, `WebsiteSearchTool`): first chunk and embed content from a local / specified source into a vector store, then the agent "looks up materials" via semantic search. All inherit from the common `RagTool`.

```python
import os
from crewai_tools import PDFSearchTool

# Turn a local product manual into a searchable knowledge source
# (place files in the project's knowledge/ directory)
pdf_rag = PDFSearchTool(pdf="knowledge/product-manual.pdf")

support_agent = Agent(
    role="Post-Sales Support Expert",
    goal="Answer user questions solely based on the product manual",
    backstory="Seasoned customer service veteran who knows every page of the manual.",
    llm=llm,
    tools=[pdf_rag],
)
```

RAG tools default to OpenAI embeddings; if using a third-party OpenAI-compatible endpoint, specify via the embedder config (same format as memory/knowledge base embedder config — see Chapter 10 for details).

::: warning RAG Tool vs Knowledge
RAG **tools** are passive: the model only calls them when it judges necessary. If you want certain facts to enter context "reliably and stably", use Chapter 11's Knowledge Sources (the framework retrieves and injects at task start) rather than relying on the model to主动调用 the tool.
:::

## 7.6 Chapter Summary

- `pip install 'crewai[tools]'` installs the toolset; upgrade both packages together to stay in sync;
- Common combo: `SerperDevTool` search + `ScrapeWebsiteTool` scrape + `FileReadTool` read;
- Tools bind at the Agent level; can also be temporarily appended at the Task level; follow the principle of least privilege;
- Keys一律走环境变量; validate at the entry point early;
- Distinguish "web search tools" from "RAG retrieval tools" — the latter inherit from `RagTool`.
