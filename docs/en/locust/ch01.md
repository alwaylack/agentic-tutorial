# Chapter 1 · Performance Testing and Locust Overview

> Chapter goals: understand the differences between load testing, stress testing, and soak testing; learn about Locust's event-driven architecture; install and verify your Locust environment.

## 1.1 Three Types of Performance Testing

Performance testing is not a single test—it's a family of tests. The three types most commonly confused in engineering practice are:

| Type | Goal | Typical Question |
|---|---|---|
| **Load Testing** | Verify the system meets requirements under expected concurrency | "Can the page still open within 2s when 500 people are online simultaneously?" |
| **Stress Testing** | Find the system's breaking point | "How many more users can the system handle before it starts erroring?" |
| **Soak Testing** | Detect resource leaks under long-running conditions | "Will memory fill up after running continuously for 24h?" |

::: tip The Relationship Between the Three
Load testing answers "is it fast enough?", stress testing answers "how much can it handle?", and soak testing answers "can it last long?". A complete performance evaluation typically requires all three.
:::

## 1.2 What Is Locust

Locust is an open-source load testing tool written in Python. Its core characteristics:

```python
from locust import HttpUser, task

class HelloWorldUser(HttpUser):
    @task
    def hello_world(self):
        self.client.get("/hello")
```

A load test script is just a regular Python file—meaning you can use loops, functions, and third-party libraries to construct arbitrarily complex user behaviors, without learning XML configuration or a proprietary DSL.

## 1.3 Architecture: Event-Driven + gevent

Locust's concurrency model rests on two pillars:

- **gevent**: A coroutine-based concurrency library where each virtual user runs in its own greenlet (micro-thread). A single process can easily simulate thousands of users at far lower memory overhead than thread or process-based approaches.
- **Event-driven**: Request completion, task execution, and test start/stop all trigger event hooks, allowing you to inject custom statistics, alerts, and logging logic at these points.

```text
┌─────────────┐     ┌──────────┐     ┌─────────────┐
│  Master Node │────▶│ Worker×N │────▶│  Target System│
│(Web UI/Stats)│◀────│ (greenlet)│◀────│             │
└─────────────┘     └──────────┘     └─────────────┘
```

When a single machine isn't enough, Locust supports a distributed master-worker mode: the Master node handles scheduling and statistics aggregation, while Worker nodes each generate traffic independently.

## 1.4 Locust vs JMeter vs k6

| Feature | Locust | JMeter | k6 |
|---|---|---|---|
| Scripting Language | Python | XML / Groovy | JavaScript |
| Concurrency Model | gevent coroutines | Threads | Go goroutines |
| Distributed | Built-in master-worker | Requires JMeter Server | Cloud-native |
| Learning Curve | Low (just know Python) | Medium-high | Low |
| Programmability | ⭐⭐⭐ Full Python | ⭐⭐ Groovy scripts | ⭐⭐ JS subset |
| GUI | Web UI (browser) | Swing desktop | None |

Recommendation: choose Locust if your team already uses Python; JMeter if you need record-and-playback; k6 for maximum single-machine throughput.

## 1.5 Installation and Verification

```bash
python -m venv .venv && source .venv/bin/activate
pip install locust
```

Verify the installation:

```bash
locust --version
# locust 2.46.x (Python 3.x.x)
```

Create your first script `locustfile.py`:

```python
from locust import HttpUser, task


class HelloWorldUser(HttpUser):
    @task
    def hello_world(self):
        self.client.get("/hello")
        self.client.get("/world")
```

Run from the terminal:

```bash
$ locust
[2026-01-01 10:00:00] INFO/locust.main: Starting web interface at http://0.0.0.0:8089
```

Open your browser and visit `http://localhost:8089`, enter the target host URL, and start the test.

## Chapter Summary

- Performance testing divides into three categories: load (is it fast enough?), stress (how much can it handle?), and soak (can it last long?);
- Locust writes load test scripts as plain Python code, using gevent coroutines for high concurrency;
- When a single machine isn't enough, use the built-in master-worker distributed mode to scale;
- Compared to JMeter/k6, Locust's advantage is "full Python programmability + low learning curve."
