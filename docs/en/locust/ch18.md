## 18.1 Headless Mode Execution

CI environments have no图形界面 (graphic interface). Locust provides the `--headless` parameter to skip the Web UI and执行 directly (execute directly) from the command line:

```bash
# Basic usage: 10 users, 2 spawned per second, 60 seconds duration
locust -f locustfile.py --headless \
  --users 10 \
  --spawn-rate 2 \
  --run-time 60s \
  --host https://staging.example.com
```

Key parameters:

| Parameter | Abbreviation | Description |
|------|------|------|
| `--headless` | | Do not start Web UI |
| `--users` / `-u` | `-u` | Target concurrent user count |
| `--spawn-rate` / `-r` | `-r` | User spawn rate (users/second) |
| `--run-time` / `-t` | `-t` | Test duration (e.g., `60s`, `5m`) |
| `--host` | `-H` | Base URL of the system under test |

::: tip Exit Code Mechanism
Locust exits with a non-zero code by default when there are request failures. Combined with the `events.quitting` listener from Chapter 16 setting `process_exit_code = 1`, CI can correctly mark the build as failed当失败率或 p95 超标时 (when fail rate or p95 exceeds thresholds).
:::

## 18.2 GitHub Actions Workflow

Here is a complete GitHub Actions configuration example:

```yaml
# .github/workflows/load-test.yml
name: Performance Test

on:
  workflow_dispatch:        # Manual trigger
    inputs:
      target_url:
        description: 'Target URL'
        required: true
        default: 'https://staging.example.com'
      user_count:
        description: 'Concurrent users'
        required: false
        default: '50'
  schedule:
    - cron: '0 6 * * 1'     # Auto-execution at 6 AM UTC every Monday

jobs:
  load-test:
    runs-on: ubuntu-latest
    timeout-minutes: 15

    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-python@v5
        with:
          python-version: '3.12'

      - run: pip install locust

      - name: Run load test
        run: |
          locust -f locustfile.py \
            --headless \
            --users ${{ github.event.inputs.user_count || 50 }} \
            --spawn-rate 5 \
            --run-time 2m \
            --host ${{ github.event.inputs.target_url }} \
            --csv reports/run_$(date +%s)

      - name: Upload results
        uses: actions/upload-artifact@v4
        if: always()
        with:
          name: locust-reports
          path: reports/
```

## 18.3 Threshold Checking Script

For more precise控制 (control), write an独立 Python 脚本 (independent Python script) to parse CSV results:

```python
# check_threshold.py
import csv
import sys

def check(filepath, min_rps, max_p95):
    with open(filepath) as f:
        reader = csv.DictReader(f)
        total_rps = float(reader.__next__["Current RPS"])
        p95 = float(reader.__next__["50%"])  # median; adjust for p95 column

    ok = True
    if total_rps < min_rps:
        print(f"❌ RPS {total_rps} below threshold {min_rps}")
        ok = False
    if p95 > max_p95:
        print(f"❌ P95 {p95}ms exceeds threshold {max_p95}ms")
        ok = False
    if ok:
        print(f"✅ RPS={total_rps}, P95={p95}ms — PASSED")
    return ok

if __name__ == "__main__":
    import argparse
    parser = argparse.ArgumentParser()
    parser.add_argument("csv", help="Path to stats CSV")
    parser.add_argument("--min-rps", type=float, default=50)
    parser.add_argument("--max-p95", type=float, default=500)
    args = parser.parse_args()
    sys.exit(0 if check(args.csv, args.min_rps, args.max_p95) else 1)
```

Use in CI:

```bash
locust -f locustfile.py --headless -u 50 -r 5 --run-time 2m --csv reports/run
python check_threshold.py reports/run_stats.csv --min-rps 100 --max-p95 300
```

## 18.4 Scheduled Load Testing

定期压测 (periodic load testing) tracks性能趋势 (performance trends) over time:

```yaml
  schedule:
    - cron: '0 6 * * 1'     # Every Monday 6 AM UTC
```

::: warning 生产环境压测注意事项 (Production Load Test Precautions)
Never run full-scale load testsagainst生产环境 (against production) without事先通知 (prior notice) and运维团队协调 (ops team coordination). Prefer staging environments; if productiontesting is necessary, use极低负载 (very low load), off-peak hours, and have应急预案 (contingency plans) ready.
:::

## Chapter Summary

- `--headless` + `--csv` + `--html` are the CI scene三件套 (three-piece set);

- an独立 Python 脚本 (independent Python script) for threshold checking is more可控 (controllable) than inline shell;
- Scheduled load testing tracksperformance趋势 (performance trends); always target staging.
