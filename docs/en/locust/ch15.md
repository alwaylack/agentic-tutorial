# Chapter 15 · Using Locust as a Library

> Chapter goals: start load tests programmatically without the `locust` command line; master the Environment/Runner model; learn to embed in pytest and CI pipelines.

## 15.1 Environment and Runner Model

Locust's command-line tool is essentially a wrapper around these core classes:

```text
Environment
├── user_classes       → list of registered User classes
├── events             → event system
├── runner             → Runner instance (controls start/stop)
│   └── greenlet       → running coroutines
└── web_ui             → Web UI service (optional)
```

Minimal programmatic startup code:

```python
from locust.env import Environment
from my_locustfile import MyTestUser

# 1. Create Environment, register User classes
env = Environment(user_classes=[MyTestUser])

# 2. Create local Runner
env.create_local_runner()

# 3. Start load test: 500 users, 20 spawned per second
env.runner.start(500, spawn_rate=20)

# 4. Block until test completes
env.runner.greenlet.join()
```

## 15.2 Controlling Test Lifecycle

The Runner object provides complete lifecycle control:

```python
import time
from locust.env import Environment
from my_locustfile import MyTestUser

env = Environment(user_classes=[MyTestUser])
env.create_local_runner()

# Stepped pressure increase: gradually raise concurrent users
for users in [10, 50, 100, 200]:
    env.runner.start(users, spawn_rate=10)
    time.sleep(60)  # 60 seconds per level

# Manual stop
env.runner.quit()
```

### Automatic Stop with Timeout

```python
import time
from locust.env import Environment
from my_locustfile import MyTestUser

env = Environment(user_classes=[MyTestUser])
env.create_local_runner()
env.runner.start(100, spawn_rate=10)

# Wait up to 5 minutes, then stop
for _ in range(300):
    time.sleep(1)
    stats = env.runner.stats.total
    if stats.fail_ratio > 0.05:  # fail rate exceeds 5%
        print("Aborting: too many failures")
        env.runner.quit()
        break
else:
    print("Test completed successfully")
```

## 15.3 Accessing Statistics Programmatically

```python
stats = env.runner.stats.total

print(f"Total requests: {stats.num_requests}")
print(f"Failures: {stats.num_failures}")
print(f"Fail ratio: {stats.fail_ratio:.2%}")
print(f"RPS: {stats.current_rps:.2f}")
print(f"P95 response time: {stats.get_response_time_percentile(0.95):.0f}ms")
print(f"Median response time: {stats.median_response_time}ms")
```

## 15.4 Embedding in pytest

```python
# test_performance.py
import pytest
from locust.env import Environment
from my_locustfile import MyTestUser


@pytest.fixture
def locust_env():
    env = Environment(user_classes=[MyTestUser])
    env.create_local_runner()
    yield env
    env.runner.quit()


def test_api_p95_under_500ms(locust_env):
    locust_env.runner.start(50, spawn_rate=5, run_time="30s")
    locust_env.runner.greenlet.join()

    stats = locust_env.runner.stats.total
    p95 = stats.get_response_time_percentile(0.95)
    assert p95 < 500, f"P95 {p95}ms exceeds 500ms threshold"
    assert stats.fail_ratio < 0.01, f"Fail ratio {stats.fail_ratio:.1%} exceeds 1%"
```

Run with:

```bash
pytest test_performance.py -v
```

## 15.5 Skipping Monkey-Patching (Debug Mode)

In some scenarios (e.g., debugging in Jupyter Notebook), monkey-patching may cause conflicts. Skip it by setting an environment variable before importing locust:

```python
import os
os.environ["LOCUST_SKIP_MONKEY_PATCH"] = "1"

# Then import locust
from locust import User, task
```

::: warning Performance Impact
After skipping monkey-patching, all I/O operations become blocking—single-process can only execute tasks serially. Use only for debugging.
:::

## Chapter Summary

- `Environment` → `create_local_runner()` → `runner.start(users, spawn_rate)` three-step startup;
- `env.stats` provides programmatic access to RPS, response time percentiles, fail ratio;
- Embed lightweight performance checks into pytest fixtures for CI automation;
- Web UI can be enabled in programmatic mode via `create_web_ui()`;
- Always start distributed workers via CLI.
