# Chapter 7 · TaskSet and Nested Tasks

> Chapter goals: master writing TaskSet classes, implement hierarchical task organization and nested scheduling, learn to use `interrupt()` to exit sub-task sets, and understand `on_start` / `on_stop` lifecycle methods.

## 7.1 Why TaskSet Is Needed

When user behavior models become complex (e.g., "login first → browse products → add to cart → checkout"), piling all `@task` methods in one `HttpUser` class makes code hard to maintain. `TaskSet` lets you group tasks by business scenario:

```python
from locust import HttpUser, TaskSet, task, between

class BrowsingBehavior(TaskSet):
    """Simulate user behavior of browsing products"""

    @task(5)
    def view_products(self):
        self.client.get("/api/products")

    @task(3)
    def view_product_detail(self):
        self.client.get("/api/products/1")

    @task(1)
    def stop_browsing(self):
        # Exit browsing mode
        self.interrupt()


class ShoppingUser(HttpUser):
    wait_time = between(1, 3)
    host = "https://shop.example.com"
    tasks = {BrowsingBehavior: 10}  # Weight is 10
```

`HttpUser` references one or more `TaskSet`s through the `tasks` attribute. When a `TaskSet` is selected, its tasks begin looping until `interrupt()` is called to return to the parent level.

## 7.2 Nested TaskSet

TaskSet can be nested in multiple layers to build complex user journey models:

```python
class LoginTask(TaskSet):
    @task
    def login(self):
        resp = self.client.post("/api/login", json={
            "username": "test_user",
            "password": "secret"
        })
        if resp.status_code == 200:
            # Login successful, enter shopping flow
            self.interrupt()  # Return to parent


class ShoppingTask(TaskSet):
    tasks = {
        BrowseProducts: 5,
        AddToCart: 3,
        Checkout: 1
    }

    @task
    def stay_here(self):
        pass  # Fallback task keeping current level


class EcommerceUser(HttpUser):
    wait_time = between(1, 3)
    host = "https://shop.example.com"

    tasks = [LoginTask]
```

Each layer of TaskSet has its own task weight system. `interrupt(reschedule=True)` can immediately reschedule the next task after exiting.

## 7.3 Using interrupt()

`interrupt()` is the key method to return from a child TaskSet to the parent. Without calling it, the agent will loop forever in the current TaskSet.

```python
class SessionTimeout(TaskSet):
    @task
    def check_session(self):
        resp = self.client.get("/api/session/check")
        if resp.json().get("expired"):
            self.interrupt(reschedule=True)  # Session expired → return to parent to re-login

    @task
    def do_work(self):
        self.client.get("/api/work")
```

```python
# interrupt() parameter explanation
self.interrupt()               # Exit and wait for the next round to select a task
self.interrupt(reschedule=True)  # Exit and immediately reschedule
```

::: warning Forgetting interrupt()
The most common mistake is forgetting to set an exit condition in a child TaskSet, causing all virtual users to get permanently stuck at that level. Ensure every child TaskSet has at least one path that triggers `interrupt()`.
:::

## 7.4 on_start and on_stop Lifecycle

Each TaskSet (and User) supports two lifecycle methods:

- **on_start**: Executed once when the virtual user starts (e.g., login, obtaining token)
- **on_stop**: Executed once when the virtual user stops (e.g., logout, cleaning up resources)

```python
class AuthenticatedUser(HttpUser):
    host = "https://api.example.com"
    wait_time = between(1, 3)

    def on_start(self):
        """Executed once when each virtual user starts"""
        resp = self.client.post("/api/auth/login", json={
            "username": f"user_{id(self)}",
            "password": "test123"
        })
        self.token = resp.json()["token"]
        self.headers = {"Authorization": f"Bearer {self.token}"}

    def on_stop(self):
        """Clean up when virtual user stops"""
        self.client.post(
            "/api/auth/logout",
            headers=self.headers
        )

    class BrowseTask(TaskSet):
        @task
        def get_data(self):
            # Use parent's token
            self.client.get(
                "/api/data",
                headers=self.parent.headers  # Access parent attributes
            )
```

::: tip Accessing Parent
Inside nested TaskSets, access parent User or TaskSet instance attributes and methods via `self.parent`.
:::

## 7.5 SequentialTaskSet: Orderly Execution

By default, tasks in TaskSet are selected randomly by weight. If you need to execute strictly in order (e.g., register → verify → complete), use `SequentialTaskSet`:

```python
from locust import SequentialTaskSet, HttpUser, task

class RegistrationFlow(SequentialTaskSet):
    """Registration flow executed strictly in order"""

    @task
    def step1_submit_form(self):
        self.client.post("/api/register", json={"email": "new@test.com"})
        # Save return value for next step
        self.user_id = self.client.get("/api/me").json()["id"]

    @task
    def step2_verify_email(self):
        self.client.post("/api/verify", json={"user_id": self.user_id})

    @task
    def step3_complete_profile(self):
        self.client.put(f"/api/users/{self.user_id}", json={
            "nickname": "New User"
        })

class SignupUser(HttpUser):
    host = "https://app.example.com"
    tasks = [RegistrationFlow]
```

`SequentialTaskSet` automatically returns to the first step and continues looping after executing the last step, unless you call `interrupt()`.

## Chapter Summary

- `TaskSet` groups tasks by business scenario, referenced through parent class `tasks` attribute;
- Multi-layer nesting builds complex user journeys, `interrupt()` exits sub-levels;
- `on_start` / `on_stop` handle one-time initialization and cleanup;
- `SequentialTaskSet` guarantees tasks execute in declaration order;
- Child TaskSets access parent attributes via `self.parent`.
