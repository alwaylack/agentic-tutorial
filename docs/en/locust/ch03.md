# Chapter 3 · HttpUser and Task Writing

> Chapter goals: Master the `client` attribute usage on HttpUser (GET/POST/parameter passing), learn to aggregate statistics with the `name` parameter, and understand the `on_start` lifecycle hook.

## 3.1 Core HttpUser Attributes

```python
from locust import HttpUser, task


class ApiUser(HttpUser):
    host = "https://httpbin.org"  # Default target host

    @task
    def make_request(self):
        # self.client is an HttpSession instance
        resp = self.client.get("/get")
```

| Attribute | Type | Description |
|---|---|---|
| `client` | HttpSession | Entry point for HTTP requests; API compatible with requests |
| `host` | str | Target host, overridable via CLI `-H` |
| `environment` | Environment | Current test environment object (access runner, stats, etc.) |

## 3.2 Issuing Different Request Types

`self.client` supports all HTTP methods:

```python
@task
def http_methods(self):
    # GET with query parameters
    self.client.get("/get", params={"page": 1, "size": 20})

    # POST with JSON body
    self.client.post("/post", json={"username": "locust", "active": True})

    # PUT / DELETE / PATCH work the same way
    self.client.put("/put", json={"id": 1})
    self.client.delete("/delete")
    self.client.head("/get")
```

With custom headers:

```python
@task
def with_headers(self):
    self.client.get(
        "/headers",
        headers={"Authorization": "Bearer my-token", "X-Custom": "value"},
    )
```

## 3.3 Aggregating Statistics with name

This is the most easily overlooked but most important technique for beginners. Compare:

```python
# ❌ Not recommended: each product ID generates a separate stat row
self.client.get(f"/product/{product_id}")

# ✅ Recommended: all product pages grouped into one "/product" stat
self.client.get(f"/product/{product_id}", name="/product")
```

Without `name`, stress-testing 100 different products produces 100 stat rows — each with too few samples for meaningful percentile data. Grouping with `name` makes the statistics useful.

```python
@task
def browse_products(self):
    for product_id in range(10):
        self.client.get(
            f"/api/products/{product_id}",
            name="/api/products/[id]",  # Grouped stat name
        )
```

## 3.4 Validating Responses

Locust only marks non-2xx HTTP status codes as failures by default. Business-level validation requires manual handling:

```python
from locust import HttpUser, task


class UserApi(HttpUser):
    host = "https://httpbin.org"

    @task
    def get_user(self):
        with self.client.get("/json", catch_response=True) as resp:
            if resp.status_code != 200:
                resp.failure(f"Status code error: {resp.status_code}")
            elif "slideshow" not in resp.text:
                resp.failure("Response missing expected field")
            else:
                resp.success()
```

## 3.5 Chapter Summary

- `self.client` mirrors the requests API — GET, POST, PUT, DELETE all supported;
- `name=` parameter groups dynamic URL paths into one stat row;
- `catch_response=True` + `resp.failure()` / `resp.success()` for business-level validation;
- `on_start()` runs once per virtual user before tasks begin — ideal for login/setup.
