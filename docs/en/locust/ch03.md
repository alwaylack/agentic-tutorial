# Chapter 3 · HttpUser and Task Writing

> Chapter goals: master the client attribute usage of HttpUser (GET/POST/parameter passing); learn to aggregate statistics using the name parameter; understand the on_start lifecycle hook.

## 3.1 Core Attributes of HttpUser

```python
from locust import HttpUser, task


class ApiUser(HttpUser):
    host = "https://httpbin.org"  # default target host

    @task
    def make_request(self):
        # self.client is an HttpSession instance
        resp = self.client.get("/get")
```

| Attribute | Type | Description |
|---|---|---|
| `client` | HttpSession | Entry point for making HTTP requests, API compatible with requests |
| `host` | str | Target host, can be overridden via command-line `-H` |
| `environment` | Environment | Current test environment object (access runner, stats, etc.) |

## 3.2 Sending Various Request Types

`self.client` supports all HTTP methods:

```python
@task
def http_methods(self):
    # GET with query parameters
    self.client.get("/get", params={"page": 1, "size": 20})

    # POST with JSON body
    self.client.post("/post", json={"username": "locust", "active": True})

    # PUT / DELETE / PATCH similarly
    self.client.put("/put", json={"id": 1})
    self.client.delete("/delete")
    self.client.head("/get")
```

With request headers:

```python
@task
def with_headers(self):
    self.client.get(
        "/headers",
        headers={"Authorization": "Bearer my-token", "X-Custom": "value"},
    )
```

## 3.3 Aggregating Statistics with name

This is the most easily overlooked but most important technique for beginners. Look at the following example:

```python
# ❌ Not recommended: each product ID generates a separate statistic
self.client.get(f"/product/{product_id}")

# ✅ Recommended: all product pages grouped into one "/product" statistic
self.client.get(f"/product/{product_id}", name="/product")
```

Without setting `name`, load-testing 100 different products produces 100 rows of statistics—each row has too few samples for percentile data to be meaningful. After merging similar requests with `name`, the statistics become useful.

```python
@task
def browse_products(self):
    for product_id in range(10):
        self.client.get(
            f"/api/products/{product_id}",
            name="/api/products/[id]",  # grouped statistic name
        )
```

## 3.4 Validating Responses

Locust only marks requests as failed by default when the HTTP status code is non-2xx. Business-level validation requires manual handling:

```python
from locust import HttpUser, task


class UserApi(HttpUser):
    host = "https://httpbin.org"

    @task
    def get_user(self):
        with self.client.get("/json", catch_response=True) as resp:
            if resp.status_code != 200:
                resp.failure(f"Unexpected status code: {resp.status_code}")
            elif "slideshow" not in resp.text:
                resp.failure("Response body missing expected field")
            else:
                resp.success()
```

## Chapter Summary

- `self.client` supports all HTTP methods with the same API as requests;
- Use `name` parameter to group similar requests for meaningful statistics;
- Use `catch_response=True` for business-level response validation;
- `on_start()` runs once when a virtual user is spawned; `on_stop()` runs when it stops.
