# Chapter 17 · Performance Tuning and Request Rate Improvement

> Chapter goals: understand Locust's single-process concurrency bottleneck; master ulimit, FastHttpUser, --processes multi-process techniques to maximize request throughput; learn to judge "is the bottleneck in Locust or the target system?"

## 17.1 Locust's Concurrency Model and Bottleneck

Locust achieves high concurrency基于 gevent 协程库 (based on the gevent coroutine library). Each virtual user runs in a greenlet, with monkey-patching turning standard I/O operations non-blocking.

Single-process architecture bottleneck:

```text
┌─────────────────────────────┐
│  Single Python Process       │
│  ┌─────────────────────┐    │
│  │ gevent event loop   │ ← all users share one event loop
│  │ user1 user2 ... userN│    │
│  └─────────────────────┘    │
│  CPU: uses only one core     │
│  Memory: users × per-user mem│
└─────────────────────────────┘
```

When用户数达到数千 (user count reaches thousands), a single Python process's CPU becomes the bottleneck. The官方文档明确指出 (official documentation clearly states): when you see the `CPU usage above 90%!` warning, Locust itself is overloaded, and the measured response times are unreliable.

::: warning Key Insight
When the load-test tool itself is overloaded, the data测出的 (produced) is **distorted**—you are measuring "Locust processing capacity" not "target system performance." Alwaysensure压测机有余量 (the load-test machine has headroom) first.
:::

## 17.2 Increasing File Descriptor Limits

Each concurrent HTTP connection consumes one file descriptor (fd). Linux/macOS default fd limits are typically only 256 or 1024—farinsufficient for high-concurrency load testing:

```bash
# Check current limit
ulimit -n

# Temporarily raise to 100000 (effective for current shell)
ulimit -n 100000

# Permanent change: edit /etc/security/limits.conf
# * soft nofile 100000
# * hard nofile 100000

# macOS special handling (must execute before starting)
sudo launchctl limit maxfiles 100000 200000
```

If fd is insufficient, you'll see the `Too many open files` error—one of the most common environment issues in load testing.

## 17.3 Using FastHttpUser to Reduce CPU Overhead

The default `HttpUser` uses the `requests` library under the hood—feature-rich but with较高 CPU 开销 (higher CPU overhead). Locust内置 (internally provides) `FastHttpUser`, implementing a more efficient HTTP client基于 fasthttp (based on fasthttp):

```python
from locust import HttpUser, task, between
from locust.contrib.fasthttp import FastHttpUser


class StandardUser(HttpUser):
    """Traditional approach — requests under the hood"""
    wait_time = between(1, 2)

    @task
    def get_data(self):
        self.client.get("/api/data")


class FastUser(FastHttpUser):
    """Efficient approach — fasthttp under the hood, significantly reduced CPU"""
    wait_time = between(1, 2)
    host = "https://staging.example.com"

    @task
    def get_data(self):
        # API is largely identical to HttpUser
        self.client.get("/api/data")

    @task
    def post_data(self):
        self.client.post("/api/data", json={"key": "value"})
```

| Comparison | HttpUser (requests) | FastHttpUser (fasthttp) |
|------|---------------------|------------------------|
| CPU Efficiency | Moderate | Higher |
| Connection Pool | urllib3 | Built-in fasthttp pool |
| Cookie Auto-Management | ✅ | ⚠️ Manual handling in some scenarios |
| Streaming Response | ✅ | ❌ |
| Recommended Scenario | Functional testing / low concurrency | High-concurrency pure-throughput testing |

::: tip Switching Recommendation
If your script only does simple GET/POST and不需要 requests 特有功能 (doesn't need requests-specific features like streaming downloads), simply changing `HttpUser` to `FastHttpUser`提升单 worker 承载量 (increases single-worker capacity).
:::

## 17.4 Multi-Process Mode --processes

Starting from Locust 2.x, you can一键启动多进程模式 (start multi-process mode with one command) via the `--processes` parameter:

```bash
# Method 1: auto-spawn worker processes based on CPU core count
locust -f locustfile.py --processes 4

# Method 2: specify exact count
locust -f locustfile.py --processes 8 --headless -u 1000 -r 50
```

Locust启动 1 个 master 进程 + N 个 worker 进程 (starts 1 master process + N worker processes). The master does not generate traffic—it only coordinates and aggregates statistics. Each worker is an独立 gevent 进程 (independent gevent process), fully utilizing多核 CPU (multi-core CPUs).

## 17.5 Judging the Bottleneck: Locust vs Target System

| Symptom | Likely Bottleneck |
|---|---|
| `CPU usage above 90%!` warning | Locust 自身过载 (Locust itself overloaded) |
| `Too many open files` | fd 限制不足 (insufficient fd limit) |
| RPS plateaus while users increase | 被测系统饱和 (target system saturated) |
| Response时间持续上升且无报错 (response time keeps rising with no errors) | 被测系统资源耗尽 (target system resources exhausted) |

**黄金法则**: always确保压测机有至少 2× 的余量 (ensure the load-test machine has at least 2× headroom) before concluding the target system is the bottleneck.

## Chapter Summary

- Locust single-process is基于 gevent (based on gevent), can only利用一个 CPU 核 (utilize one CPU core);
- `ulimit -n 100000`解决文件描述符不足问题 (solves file descriptor insufficiency);
- `FastHttpUser` has higher CPU efficiency than `HttpUser`, ideal for高并发纯吞吐场景 (high-concurrency pure-throughput scenarios);
- `--processes`一键启动多进程 (starts multi-process with one command); use `--master/--worker`跨机器 (across machines);
- When Locust CPU > 90%,测得数据不可信 (measured data is unreliable)—address the load-test side bottleneck first.
