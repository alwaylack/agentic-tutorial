# Chapter 2 · Installation and First Script

> Chapter goals: understand the basic structure of locustfile.py; master the three core concepts—HttpUser class, @task decorator, and between() wait time—then write and run your first complete load test.

## 2.1 Minimum Structure of a locustfile

A valid locustfile needs to satisfy only one rule: **it must contain at least one class that inherits from `User` (or its subclass `HttpUser`)**.

```python
# locustfile.py
from locust import HttpUser, task, between


class QuickstartUser(HttpUser):
    wait_time = between(1, 5)

    @task
    def hello_world(self):
        self.client.get("/hello")
        self.client.get("/world")

    @task(3)
    def view_items(self):
        for item_id in range(10):
            self.client.get(f"/item?id={item_id}", name="/item")

    def on_start(self):
        self.client.post("/login", json={"username": "foo", "password": "bar"})
```

This code contains four core concepts of Locust, which we will unpack one by one.

## 2.2 HttpUser: Simulating a User

`HttpUser` is Locust's built-in user class, designed specifically for HTTP load testing. When the test starts:

1. Locust creates an **instance** of that class for each virtual user;
2. Each instance receives a `client` attribute—it is an `HttpSession` instance responsible for making HTTP requests;
3. Each user runs in its own greenlet coroutine, never blocking each other.

```python
class MyUser(HttpUser):
    host = "https://httpbin.org"  # default host can also be declared in the class

    @task
    def get_ip(self):
        resp = self.client.get("/ip")  # equivalent to requests.get("https://httpbin.org/ip")
        print(resp.json())
```

::: tip Relationship between client and requests
`self.client.get()` / `.post()` parameter signatures are almost identical to the requests library (supporting `headers`, `json`, `params`, etc.). If you have already completed our [HTTP Requests course](/http/), you can migrate seamlessly.
:::

## 2.3 @task: Declaring Tasks to Execute

Methods decorated with `@task` are the "behaviors" of virtual users. Each user loops through executing these methods, picking one at random each time:

```python
@task
def browse_homepage(self):
    self.client.get("/")


@task(3)  # weight = 3
def browse_product(self):
    self.client.get("/product/1")
```

`@task(3)` means this task is three times as likely to be selected as a weight-1 task—modeling the real-world scenario where "users browse products more frequently than the homepage."

## 2.4 between(): Controlling Think Time

Real users don't bomb the target system non-stop like robots. The `wait_time` attribute defines the pause between tasks:

```python
from locust import between

wait_time = between(1, 5)  # randomly wait 1–5 seconds after each task
```

Without wait time, all users would hammer the target at maximum speed—that's stress testing, not load testing. Chapter 4 covers more wait strategies in detail.

## 2.5 Running and Viewing Results

Save the script as `locustfile.py` and run from the terminal:

```bash
$ locust
[INFO] Starting web interface at http://0.0.0.0:8089
```

Open your browser and visit `http://localhost:8089`:

1. **Number of users**: total concurrent users (e.g., 50)
2. **Ramp up**: new users per second (e.g., 5/s)
3. **Host**: target address (e.g., `https://httpbin.org`)

Click Start, then switch to the **Charts** tab—you will see three real-time curves:

- **RPS**: requests per second
- **Response Times**: response time (median and percentiles)
- **Number of Users**: currently running virtual users

::: warning How to Know When You've Hit a Bottleneck
If RPS stops growing but response times spike sharply, the target system is saturated. If response times remain flat and RPS hasn't reached the target, you need to apply more pressure.
:::

## Chapter Summary

- A locustfile is just a regular Python module containing at least one `User` subclass;
- `HttpUser.client` makes requests with the same API as requests;
- `@task` decorator declares tasks; `@task(N)` controls selection probability;
- `wait_time = between(1, 5)` simulates real user thinking pauses;
- Web UI defaults to port 8089; the Charts page shows RPS / response times / user count in real time.
