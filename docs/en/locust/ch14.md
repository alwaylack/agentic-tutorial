# Chapter 14 · asyncio Support

> Chapter goals: understand the relationship between Locust's gevent concurrency model and the asyncio ecosystem; master aiolocust usage; choose the right approach based on scenarios.

## 14.1 Locust's Concurrency Model: gevent

Locust's traditional concurrency is based on **gevent**—a Python cooperative multitasking library that replaces standard library I/O operations with non-blocking versions via monkey-patching. Each virtual User runs in a greenlet (lightweight coroutine):

```python
# locust auto-executes monkey-patch at startup
from gevent import monkey
monkey.patch_all()  # replaces blocking calls in socket, time, threading, etc.

# Thereafter all User instances run in greenlets, yielding CPU automatically on I/O wait
```

The advantage of the gevent approach: **transparent to user code**—you write synchronous code, and Locust自动实现并发 (automatically achieves concurrency). The disadvantage is that monkey-patching is无效 on C extension libraries (see Chapter 13).

## 14.2 aiolocust: asyncio Redesign

**aiolocust** is a new project in the Locust ecosystem released in 2026,全面替代 (fully replacing) the gevent/requests tech stack with **asyncio/aiohttp**, embracing modern Python async standards.

```bash
pip install aiolocust
```

Basic usage:

```python
import asyncio
from aiolocust import HttpUser

async def run(user: HttpUser):
    async with user.client.get("http://example.com/") as resp:
        pass  # handle response

    async with user.client.get("http://example.com/") as resp:
        # Extra validation, not just HTTP status code:
        assert "expected text" in await resp.text()

    await asyncio.sleep(0.1)
```

::: info Project Status
aiolocust is currently maintained as an独立项目 (independent project), with fewer features than the Locust主线 (main line)—more minimalistic—and relies on OTEL for visualization. It may合并进 (merge into) Locust or ship with a major version in the future.
:::

## 14.3 gevent vs asyncio Comparison

| Dimension | gevent (Locust) | asyncio (aiolocust) |
|---|---|---|
| Concurrency Model | greenlet + monkey-patch | Native async/await |
| Learning Curve | Low (write sync code) | Medium (understand async programming) |
| C Extension Compatible | ❌ Cannot patch | ✅ Native support |
| HTTP Client | requests | aiohttp |
| WebSocket | Requires extra library | Built-in aiohttp |
| Ecosystem | Mature and stable | Rapidly evolving |
| Suitable Scenarios | Traditional HTTP API load testing | High concurrency, C library dependency, WebSocket |

## Chapter Summary

- gevent is transparent but C extension–hostile; asyncio is modern but requires async-aware code;
- aiolocust is a promising alternative for projects needing gRPC, WebSocket, or heavy C library usage;
- For most HTTP API load tests, the built-in gevent-based Locust remains the simplest choice.
