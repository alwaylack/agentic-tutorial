## 20.1 The System Under Test: A Simple Task Management API

Assume we have a FastAPI application deployed in staging:

```python
# app.py — the FastAPI application under test (staging environment)
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel
import asyncio
import time


app = FastAPI()
db = {"tasks": [], "next_id": 1}  # simulated database


class TaskCreate(BaseModel):
    title: str
    priority: int = 0


@app.get("/api/tasks")
async def list_tasks():
    return db["tasks"]


@app.post("/api/tasks", status_code=201)
async def create_task(task: TaskCreate):
    time.sleep(0.05)  # simulate DB write latency
    item = {"id": db["next_id"], **task.model_dump()}
    db["next_id"] += 1
    db["tasks"].append(item)
    return item


@app.get("/api/tasks/{task_id}")
async def get_task(task_id: int):
    for t in db["tasks"]:
        if t["id"] == task_id:
            return t
    raise HTTPException(status_code=404)
```

## 20.2 Step 1: Write the Locust Script

Design task weights按照真实用户的使用比例 (according to real user usage ratios)—read-heavy is the most common pattern:

```python
# locustfile.py
import random
from locust import HttpUser, task, between, LoadTestShape


class StagedShape(LoadTestShape):
    """Stepped pressure: 25 → 50 → 100 → 200 users"""
    stages = [
        {"duration": 120, "users": 25, "spawn_rate": 5},
        {"duration": 180, "users": 50, "spawn_rate": 5},
        {"duration": 180, "users": 100, "spawn_rate": 10},
        {"duration": 120, "users": 200, "spawn_rate": 10},
        {"duration": 60,  "users": 5,  "spawn_rate": 5},
    ]

    def tick_data(self):
        run_time = self.get_run_time()
        for stage in self.stages:
            if run_time < stage["duration"]:
                return (stage["users"], stage["spawn_rate"])
            stage["duration"] -= run_time
        return None


class TaskUser(HttpUser):
    wait_time = between(1, 3)
    host = "http://localhost:8000"

    @task(5)
    def list_tasks(self):
        self.client.get("/api/tasks")

    @task(3)
    def get_task(self):
        task_id = random.randint(1, 100)
        self.client.get(f"/api/tasks/{task_id}")

    @task(2)
    def create_task(self):
        self.client.post("/api/tasks", json={
            "title": f"Task {random.randint(1, 1000)}",
            "priority": random.choice([0, 1, 2])
        })
```

## 20.3 Step 2: Run the Test

```bash
# Local single-machine test
locust -f locustfile.py --headless \
  --users 200 --spawn-rate 10 --run-time 10m \
  --host http://localhost:8000 \
  --csv reports/final_run \
  --html reports/report.html

# Distributed test (master + workers)
# Terminal 1: master
locust -f locustfile.py --master --host http://target:8000
# Terminal 2+: workers
locust -f locustfile.py --worker --master-host <master-ip>
```

## 20.4 Step 3: Analyze Results

Open the HTML report or inspect the CSV:

```bash
python -c "
import csv
with open('reports/final_run_stats.csv') as f:
    for row in csv.DictReader(f):
        print(f\"{row['Name']:30s} | reqs={row['# Requests']:>6s} | "
              f"p95={row['95%']:>6s}ms | fails={row['# Fails']:>5s}\")
"
```

Key判断标准 (judgment criteria):

| Metric | Pass Threshold | Action if Failed |
|---|---|---|
| p95 response time | < 500ms | Optimize database queries / add caching |
| Fail ratio | < 1% | Checkerror logs / increase timeouts |
| RPS at 200 users | > 100 | Scale horizontally / tune gevent |

## 20.5 Step 4: Optimization Recommendations

Based on the analysis,常见优化方向 (common optimization directions):

1. **数据库层面 (Database layer)**: add indexes, connection pooling, query optimization
2. **应用层 (Application layer)**: async I/O, response compression, pagination
3. **架构层 (Architecture layer)**: CDN, reverse proxy caching, horizontal scaling
4. **压测端 (Load-test side)**: switch to FastHttpUser, increase fd limits, add workers
