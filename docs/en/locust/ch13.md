## 13.1 Extension Principle: The request Event

Locust natively supports only HTTP/HTTPS, but the architecture留有扩展口子 (has extension points). The core idea:

1. Inherit the `User` class (not `HttpUser`) to create a custom client;
2. After each protocol call completes, manually trigger the `request` event so Locust records statistics.

```python
from locust import User, task, between
from locust.exception import LocustError
import socket
import time

class TcpClient:
    def __init__(self, host, port):
        self.host = host
        self.port = port
        self.socket = None

    def connect(self):
        self.socket = socket.create_connection((self.host, self.port))

    def send_and_receive(self, payload: bytes) -> bytes:
        start_time = time.time()
        start_perf = time.perf_counter()
        try:
            self.socket.sendall(payload)
            response = self.socket.recv(4096)
            elapsed = time.perf_counter() - start_perf
            # Trigger request event so Locust records statistics
            events.request.fire(
                request_type="TCP",
                name="send_recv",
                response_time=elapsed * 1000,
                response_length=len(response),
                exception=None,
                context={},
            )
            return response
        except Exception as e:
            elapsed = time.perf_counter() - start_perf
            events.request.fire(
                request_type="TCP", name="send_recv",
                response_time=elapsed * 1000,
                response_length=0, exception=e, context={},
            )
            raise

    def close(self):
        if self.socket:
            self.socket.close()
```

## 13.2 gevent Monkey-Patching Constraints

::: danger Key Limitation
Locust's concurrency底层 uses gevent cooperative multitasking. **All protocol libraries under test must be可被 gevent monkey-patch**—pure Python libraries (using the standard `socket` module) work out of the box; but C extension libraries (like psycopg2) cannot be patched and will block the entire process.
:::

| Library | Patchable? | Alternative |
|---|---|---|
| `socket` / `ssl` | ✅ Out of the box | — |
| `requests` / `urllib3` | ✅ Built-in | — |
| `pymysql` / `asyncpg` | ✅ Pure Python | — |
| `psycopg2` (PostgreSQL) | ❌ C extension | Use `psycogreen` patch |
| `redis-py` (hiredis) | ⚠️ Partial | Disable hiredis parser |

## 13.3 XML-RPC Load Test Example

The official documentation provides an XML-RPC client wrapper example. First start a test server:

```python
# server.py
from xmlrpc.server import SimpleXMLRPCServer
import time, random

def get_time():
    time.sleep(random.uniform(0.01, 0.05))
    return time.time()

def get_random(a, b):
    time.sleep(random.uniform(0.01, 0.05))
    return random.randint(a, b)

server = SimpleXMLRPCServer(("localhost", 8877))
server.register_function(get_time, "get_time")
server.register_function(get_random, "get_random")
server.serve_forever()
```

Then the load test script:

```python
from locust import User, task, between, events
from xmlrpc.client import ServerProxy

class XmlRpcUser(User):
    wait_time = between(1, 3)

    def on_start(self):
        self.client = ServerProxy("http://localhost:8877")

    @task
    def call_get_time(self):
        start = time.perf_counter()
        result = self.client.get_time()
        elapsed = (time.perf_counter() - start) * 1000
        events.request.fire(
            request_type="XML-RPC", name="get_time",
            response_time=elapsed,
            response_length=len(str(result)),
            exception=None, context={},
        )

    @task(weight=3)
    def call_random(self):
        start = time.perf_counter()
        result = self.client.get_random(1, 100)
        elapsed = (time.perf_counter() - start) * 1000
        events.request.fire(
            request_type="XML-RPC", name="get_random",
            response_time=elapsed,
            response_length=len(str(result)),
            exception=None, context={},
        )
```

Run `python server.py &` then `locust -f locustfile.py --headless -u 10 -r 2`.

## 13.4 gRPC Testing Approach

gRPC is based on HTTP/2 + Protobuf, requiring `grpcio` and `grpcio-tools`:

```python
import grpc
import hello_pb2, hello_pb2_grpc  # generated by protoc

class GrpcUser(User):
    wait_time = between(0.5, 2)

    def on_start(self):
        self.channel = grpc.insecure_channel("localhost:50051")
        self.stub = hello_pb2_grpc.GreeterStub(self.channel)

    @task
    def say_hello(self):
        start = time.perf_counter()
        try:
            response = self.stub.SayHello(
                hello_pb2.HelloRequest(name="locust"),
                timeout=5.0
            )
            elapsed = (time.perf_counter() - start) * 1000
            environment.events.request.fire(
                request_type="gRPC", name="SayHello",
                response_time=elapsed,
                response_length=len(response.message),
                exception=None, context={},
            )
        except grpc.RpcError as e:
            elapsed = (time.perf_counter() - start) * 1000
            environment.events.request.fire(
                request_type="gRPC", name="SayHello",
                response_time=elapsed,
                response_length=0,
                exception=e, context={},
            )
```

::: warning gevent and grpcio
`grpcio` uses a C core that gevent cannot directly patch. Solutions: assign each User an独立 channel and control concurrency, or consider using aiolocust introduced in Chapter 14.
:::

## Chapter Summary

- Custom User classes inherit `User` (not `HttpUser`), triggering `environment.events.request.fire()` after each call;
- All protocol libraries must be gevent-patchable—pure Python works, C extensions do not;
- XML-RPC, Socket, MQTT, etc. can all be wrapped in this pattern;
- gRPC is limited by its C core—evaluate aiolocost or control concurrency.
