# Chapter 11 · Docker Containerized Running

> Chapter goals: run Locust using the official Docker image; orchestrate master + workers distributed load tests with Docker Compose; master custom images and OpenTelemetry image usage.

## 11.1 Why Run Locust with Docker

Running single-machine load tests locally is convenient, but production-grade load testing typically faces three problems:

1. **Environment consistency**—inconsistent dependency versions across load-test machines make results不可复现 (non-reproducible);
2. **Resource isolation**—load-test processes competing with application processes for CPU/memory skews results;
3. **Rapid scaling**—need to temporarily spin up multiple worker nodes.

Docker solves all three: images lock the environment, containers provide天然隔离 (natural isolation), and `docker compose up --scale` scales with one line.

## 11.2 Using the Official Image

The official image is hosted on Docker Hub at `locustio/locust`. Assuming `locustfile.py` in the current directory:

```bash
docker run -p 8089:8089 -v $PWD:/mnt/locust locustio/locust -f /mnt/locust/locustfile.py
```

Parameter explanation:

| Parameter | Description |
|---|---|
| `-p 8089:8089` | Map container port 8089 (Web UI) to host |
| `-v $PWD:/mnt/locust` | Mount current directory into container so Locust can read locustfile |
| `-f /mnt/locust/locustfile.py` | Specify locustfile path |

::: tip Windows Users Note
On Windows, `-v` mounting sometimes errors—use `--mount` form instead:
```bash
docker run -p 8089:8089 --mount type=bind,source=%cd%,target=/mnt/locust locustio/locust -f /mnt/locust/locustfile.py
```
:::

After starting, visit `http://localhost:8089` to see the Web UI.

Headless mode (no browser):

```bash
docker run -p 8089:8089 -v $PWD:/mnt/locust locustio/locust \
  -f /mnt/locust/locustfile.py --headless -u 100 -r 10 --run-time 60s
```

## 11.3 Docker Compose for Distributed Load Testing

Distributed load testing needs one **master** node (distribute tasks, aggregate results) and multiple **worker** nodes (generate actual load). The following compose file orchestrates everything in one command:

```yaml
# docker-compose.yml
version: '3'
services:
  master:
    image: locustio/locust
    ports:
      - "8089:8089"
    volumes:
      - ./:/mnt/locust
    command: -f /mnt/locust/locustfile.py --master -H http://master:8089

  worker:
    image: locustio/locust
    volumes:
      - ./:/mnt/locust
    command: -f /mnt/locust/locustfile.py --worker --master-host master
```

Key parameter explanation:

| Parameter | Description |
|---|---|
| `--master` | Mark this node as master |
| `-H http://master:8089` | Tell master its own address (for workers to connect) |
| `--worker` | Mark this node as worker |
| `--master-host master` | Worker finds the master via service name `master` |

Start master + 4 workers:

```bash
docker compose up -d --scale worker=4
```

## Chapter Summary

- Docker images lock the environment; containers provide天然隔离; scaling is one command;
- Use `docker compose up --scale worker=N` for quick distributed setup;
- Same locustfile must be accessible to all workers (shared volume or Docker image).
