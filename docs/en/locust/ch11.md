# Chapter 11 · Docker Containerized Execution

> Chapter goals: use the official Docker image to run Locust, orchestrate master + workers distributed load tests via Docker Compose, and master custom image and OpenTelemetry image usage.

## 11.1 Why Run Locust with Docker

Running a single-machine load test locally is convenient, but production-grade load testing usually faces three problems:

1. **Environment consistency** — Inconsistent dependency versions across load test machines lead to non-reproducible results;
2. **Resource isolation** — Load test processes competing with application processes for CPU/memory distort results;
3. **Rapid scaling** — Need to temporarily spin up multiple worker nodes.

Docker solves all three: images lock the environment, containers naturally isolate, and `docker compose up --scale` scales with one line.

## 11.2 Using the Official Image

The official image is hosted on Docker Hub at `locustio/locust`. Assuming you have `locustfile.py` in the current directory:

```bash
docker run -p 8089:8089 -v $PWD:/mnt/locust locustio/locust -f /mnt/locust/locustfile.py
```

Parameter explanation:

| Parameter | Description |
|---|---|
| `-p 8089:8089` | Map container port 8089 (Web UI) to the host |
| `-v $PWD:/mnt/locust` | Mount the current directory into the container so Locust can read locustfile |
| `-f /mnt/locust/locustfile.py` | Specify the locustfile path |

::: tip Windows Users Note
On Windows, `-v` mounting sometimes errors; use `--mount` form instead:
```bash
docker run -p 8089:8089 --mount type=bind,source=%cd%,target=/mnt/locust locustio/locust -f /mnt/locust/locustfile.py
```
:::

After starting, visit `http://localhost:8089` to see the Web UI.

Headless mode (no browser):

```bash
docker run -p 8089:8089 -v $PWD:/mnt/locust locustio/locust \
  -f /mnt/locust/locustfile.py --headless -u 100 -r 10 --run-time 60s
```

## 11.3 Docker Compose Orchestration for Distributed Testing

Distributed load testing needs a **master** node (distribute tasks, aggregate results) and multiple **worker** nodes (generate actual load). The following compose file orchestrates with one command:

```yaml
# docker-compose.yml
version: '3'
services:
  master:
    image: locustio/locust
    ports:
      - "8089:8089"
    volumes:
      - ./:/mnt/locust
    command: -f /mnt/locust/locustfile.py --master -H http://master:8089

  worker:
    image: locustio/locust
    volumes:
      - ./:/mnt/locust
    command: -f /mnt/locust/locustfile.py --worker --master-host master
```

Key parameter explanation:

| Parameter | Description |
|---|---|
| `--master` | Mark this node as master |
| `-H http://master:8089` | Tell the master its own address (for worker connections) |
| `--worker` | Mark this node as worker |
| `--master-host master` | Workers find the master via service name `master` |

Start master + 4 workers:

```bash
docker-compose up --scale worker=4
```

Dynamically scale to 10 workers (while running):

```bash
docker-compose up --scale worker=10 -d
```

## 11.4 Custom Images: Installing Third-Party Dependencies

When your locustfile needs additional Python packages, build a custom image based on the official image:

```dockerfile
# Dockerfile
FROM locustio/locust
RUN pip install some-package
RUN pip install faker pandas
```

```bash
docker build -t my-locust .
docker run -p 8089:8089 -v $PWD:/mnt/locust my-locust -f /mnt/locust/locustfile.py
```

In Docker Compose, replace `image: locustio/locust` with `image: my-locust`.

::: warning Don't pip install inside the container and commit it
The correct approach is to write a Dockerfile and rebuild — ensuring reproducible builds.
:::

## 11.5 OpenTelemetry Image

If you need to export load test metrics to an OpenTelemetry backend (Jaeger, Prometheus, etc.), Locust provides a dedicated image pre-installed with `locust[otel]` extras:

```bash
docker run -p 8089:8089 -v $PWD:/mnt/locust locustio/locust-otel \
  -f /mnt/locust/locustfile.py --otel
```

Paired with Grafana, you can view RPS curves, response time percentiles, and error rate heatmaps in real-time.

## Chapter Summary

- Official image `locustio/locust`, mount `$PWD:/mnt/locust` to run;
- Docker Compose uses `--scale worker=N` to scale worker count with one line;
- Third-party dependencies go in the Dockerfile, built from the official image as base;
- For OTel support, use the `locustio/locust-otel` image and pass the `--otel` parameter.
