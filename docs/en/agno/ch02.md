# Chapter 2 · Environment Setup and Your First Agent

> Chapter goals: Set up a reusable development environment, run your first Agent connected to DeepSeek, and learn to troubleshoot the three most common connection errors.

## 2.1 Installing Agno

It's recommended to always develop in a virtual environment to avoid polluting your system Python:

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -U agno python-dotenv
```

Verify the installation:

```bash
python -c "import agno; print(agno.__version__)"
# 3.0.x (the latest major version at the time of writing is 3.x)
```

::: warning Version Note
Agno has introduced many breaking changes since 2.x compared to 1.x (e.g., storage classes migrated from `agno.storage.sqlite.SqliteStorage` to `agno.db.sqlite.SqliteDb`). Version 3.x continues and consolidates this unified API—all usage covered in this course applies to 3.x. Many old tutorials online are based on 1.x; please refer to this course and the official documentation.
:::

## 2.2 Managing API Keys with .env

**Never hardcode your key in source code.** Create a `.env` file in the project root:

```text
DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxx
```

Then create a `.gitignore` to exclude it from version control. Load it in code using `python-dotenv`:

```python
# load_env.py
import os
from dotenv import load_dotenv

load_dotenv()  # Read the .env file in the current directory and inject environment variables

key = os.getenv("DEEPSEEK_API_KEY")
print("Key loaded: " + key[:6] + "..." if key else "DEEPSEEK_API_KEY not found!")
```

## 2.3 Your First Agent: Full Breakdown

```python
# agent_01.py -- Your first Agno Agent
import os
from dotenv import load_dotenv
from agno.agent import Agent
from agno.models.openai import OpenAIChat

load_dotenv()

agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",                              # Model ID for third-party models
        api_key=os.getenv("DEEPSEEK_API_KEY"),           # Read secret from environment variable
        base_url="https://api.deepseek.com/v1",          # OpenAI-compatible endpoint
    ),
    instructions=["Answer in concise Chinese", "Say clearly when unsure"],
    markdown=True,
)

agent.print_response("Introduce what an AI Agent is in one sentence")
```

Run `python agent_01.py`, and you'll see DeepSeek's response printed out. Let's understand each parameter:

- `id`: The model name, defined by the third-party provider (DeepSeek also has reasoning models like `deepseek-reasoner`);
- `base_url`: The compatible endpoint address. Switching to OpenRouter, Tongyi, Kimi, etc. only requires changing this line;
- `instructions`: A list of behavior instructions that Agno assembles into the system message;
- `markdown=True`: Renders output as Markdown, making tables and code blocks more readable in the terminal.

If you don't want to remember `base_url`, you can also use Agno's generic class `OpenAILike` (located at `agno.models.openai.like`), with identical parameters.

## 2.4 Troubleshooting Common Connection Errors

Nine out of ten errors from beginners fall into these three categories:

```python
# debug_connection.py -- Reproducing and self-checking three typical errors
import os
from agno.agent import Agent
from agno.models.openai import OpenAIChat

def make_agent(base_url):
    return Agent(model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url=base_url,
    ))

# Error 1: 401 Unauthorized → Key not loaded or typo
# Self-check: Is os.getenv("DEEPSEEK_API_KEY") None?

# Error 2: 404 Not Found → base_url missing or has extra path
# Correct DeepSeek format ends with /v1; writing https://api.deepseek.com will return 404

# Error 3: model not found → id doesn't match provider's provided name
# For example, mistakenly writing "deepseek_v3" instead of "deepseek-chat"

try:
    make_agent("https://api.deepseek.com/v1").run("ping")
    print("Connection successful")
except Exception as e:
    print("Failure reason:", e)
```

Troubleshooting mnemonic: **Check Key first (401), then URL (404), finally model name (400)**.

## 2.5 Making Your First Agent More Useful: Adding a Tool

An Agent without tools can only answer based on the model's internal knowledge. With a search tool added, it can fetch real-time information—the dividing line between an Agent and a regular chatbot:

```python
# agent_search.py -- Agent with search tool
import os
from dotenv import load_dotenv
from agno.agent import Agent
from agno.models.openai import OpenAIChat
from agno.tools.duckduckgo import DuckDuckGoTools

load_dotenv()

news_agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    tools=[DuckDuckGoTools()],            # Inject DuckDuckGo search capability
    instructions=["Search for latest info first before answering", "List reference links at the end of answers"],
    markdown=True,
    show_tool_calls=True,                 # Display tool call process in output
)

news_agent.print_response("What are the AI news today?", stream=True)
```

You'll notice an additional tool call record in the output: the model first requests to call the search tool, Agno executes it and passes the result back to the model to generate the final answer—this is exactly the execution loop discussed in Chapter 1. The principles of tools and customization are展开 in Chapters 7 and 8.

## 2.6 Chapter Summary

- Virtual environment + `pip install -U agno` is the standard starting point; all usage in this course applies to Agno 3.x, old 1.x API is incompatible;
- API Keys must go through `.env` + `python-dotenv`, never hardcode;
- Connecting to third-party models = `OpenAIChat(id, api_key, base_url)`, switching providers only requires changing `base_url`;
- Connection error troubleshooting order: 401 check Key → 404 check URL → 400 check model name;
- With `tools=[...]` added, the Agent upgrades from "chatting" to "acting".
