# Chapter 11 · Workflow Introduction: Step Orchestration

> Chapter goals: understand the本质区别 between Workflow and Team; learn to use `Workflow` + `Step` to orchestrate Agents, Teams, and plain functions into a确定性流水线.

## 11.1 Why Workflows Are Needed

Teams are "模型主导": the leader临场决定派谁、派什么任务. This brings灵活性, but also不确定性 — the same question may走 different执行路径. Yet many业务场景恰恰**不允许临场发挥**:

- Content production: must research first, then write, then review;顺序不能乱;
- Data processing: clean → analyze → report; each step\'s输入输出固定;
- Compliance scenarios:某些步骤 must execute无条件; the model cannot decide to跳过.

Agno\'s official定位 for the two:

| | Team | Workflow |
|---|---|---|
| Control | Leader模型自主决策 | The developer defines control flow with代码 |
| Suitability | Role协作, task dispatch | 确定性流程, structured pipelines |
| Primitives | mode / delegation / task list | Step / Parallel / Condition / Loop / Router |

## 11.2 Your First Two-Step Workflow: Write → Review

`Workflow` manages one run; the `steps` list executes in order. Each `Step` wraps exactly one executor: an Agent, a Team, a plain Python function, or even a nested Workflow.

```python
import os
from agno.agent import Agent
from agno.models.openai import OpenAIChat
from agno.workflow import Step, StepInput, StepOutput, Workflow

model = OpenAIChat(
    id="deepseek-chat",
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    base_url="https://api.deepseek.com/v1",
)

writer = Agent(
    name="Writer",
    model=model,
    instructions=["Write a short article within 300 characters on the given topic."],
)

reviewer = Agent(
    name="Reviewer",
    model=model,
    instructions=[
        "Review the article from the previous step:检查事实表述, grammar, and structure.",
        "直接输出修改后的最终版本.",
    ],
)

# Write → Review;顺序由代码保证
workflow = Workflow(
    name="writing-pipeline",
    steps=[
        Step(name="draft", executor=writer),
        Step(name="review", executor=reviewer),
    ],
)

workflow.print_response(
    "Topic: why investing in automated testing is worth it", markdown=True
)
```

At runtime the output of the `draft` step自动成为 `review` step的输入 — this data流不需要你手动接线.

## 11.3 Three Forms of Step Executors

```python
from agno.team import Team
from agno.workflow import Step, StepInput, StepOutput, Workflow


def data_preprocessor(step_input: StepInput) -> StepOutput:
    """Function executor: do deterministic processing without consuming tokens"""
    research = step_input.previous_step_content or "No research content received"
    return StepOutput(content=f"Research material待分析:\n{research}")


research_team = Team(name="Research Team", members=[...], model=model)

workflow = Workflow(
    name="mixed-pipeline",
    steps=[
        research_team,        # Form 1: directly place Agent/Team (auto-wrapped as Step)
        data_preprocessor,    # Form 2: directly place a function
        Step(                 # Form 3: explicit Step wrapper; recommended when命名/描述 is needed
            name="analysis",
            executor=writer,
            description="Produce an analysis report based on research",
        ),
    ],
)
```

The three forms can be自由混用. Naming steps (`name=`) is not just for可读性:事件追踪 and output lookup both use the step name as键.

## 11.4 StepInput and StepOutput: The Data Contract Between Steps

Function executors follow a标准签名 —接受 `StepInput`,返回 `StepOutput`:

```python
def summarize(step_input: StepInput) -> StepOutput:
    # input: the original workflow input (always preserved)
    original = str(step_input.input)
    # previous_step_content: the body of the previous step\'s output
    prev = step_input.previous_step_content or ""
    # previous_step_outputs: if the upstream is a parallel block, get the output dict for each named step
    return StepOutput(
        content=f"Original requirement: {original}\n\nMaterial summary:\n{prev[:500]}",
    )
```

Quick reference for common fields:

| StepInput field | Meaning |
|---|---|
| `input` | The original user input to the workflow |
| `previous_step_content` | The content text output by the previous step |
| `previous_step_outputs` | The集合 of outputs from upstream steps (especially useful after并行聚合) |
| `additional_data` | Custom data附加 at runtime |

::: tip The Value of Function Steps
Inserting a纯函数 step between two Agents is the most常用模式 for Workflows: format转换, length truncation, result validation should not烧 token — hand them to Python.
:::

## 11.5 Running and Parsing Outputs

`print_response()` suits debugging; for生产代码 use `run()` to get structured results:

```python
result = workflow.run("Topic: vector database选型")

# workflow_output.content is the last step\'s output
print(result.content)

# Finer-grained:查看每个步骤的执行结果 step by step
for step_result in (result.step_results or []):
    print(step_result.step_name, "->", str(step_result.content)[:80])
```

You can also use `arun()` for异步执行, or iterate the event流 when `run(..., stream=True)` to观察 each step\'s开始 and结束事件.

## 11.6 Chapter Summary

- Team =模型主导的灵活协作; Workflow =代码定义的确定性控制流;
- A `Step`\'s executor can be an Agent, Team, function, or nested Workflow; all three可混用 in one steps list;
- Data flows downstream automatically via `StepInput.previous_step_content`; `StepOutput(content=...)` is the标准出口 for function steps;
- For生产代码 use `run()` and iterate `step_results` to parse each step\'s output; do not parse打印文本.
