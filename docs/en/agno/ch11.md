# Chapter 11 · Workflow Introduction: Step Orchestration

> Chapter goals: understand the essential difference between Workflow and Team, and learn to use `Workflow` + `Step` to orchestrate Agents, Teams, and ordinary functions into a deterministic pipeline.

## 11.1 Why Workflows Are Needed

Teams are "model-driven": the leader decides on the fly whom to dispatch and what task to assign. This brings flexibility, but also uncertainty — the same question may走 different execution paths. Many business processes恰恰**do not允许 improvisation**:

- Content production: must research first, then write, then review — order cannot be乱;
- Data processing: clean → analyze → report, each step's input/output fixed;
- Compliance scenarios: certain steps must execute unconditionally, not decided by the model to skip.

Agno's official positioning of the two:

| | Team | Workflow |
|---|---|---|
| Control | Leader model自主决策 | Developer defines control flow with code |
| Suitable for | Role collaboration, task dispatch | Deterministic flows, structured pipelines |
| Primitives | mode / dispatch / task list | Step / Parallel / Condition / Loop / Router |

## 11.2 Your First Two-Step Workflow: Write → Review

`Workflow` manages one run; the `steps` list executes sequentially. Each `Step` wraps exactly one executor: Agent, Team, plain Python function, or even a nested Workflow.

```python
import os
from agno.agent import Agent
from agno.models.openai import OpenAIChat
from agno.workflow import Step, StepInput, StepOutput, Workflow

model = OpenAIChat(
    id="deepseek-chat",
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    base_url="https://api.deepseek.com/v1",
)

writer = Agent(
    name="Writer",
    model=model,
    instructions=["Write an essay within 300 characters on the given topic."],
)

reviewer = Agent(
    name="Reviewer",
    model=model,
    instructions=[
        "Review the previous article: check factual accuracy, grammar, and structure.",
        "Output the modified final version directly.",
    ],
)

# Write -> Review, order guaranteed by code
workflow = Workflow(
    name="writing-pipeline",
    steps=[
        Step(name="draft", executor=writer),
        Step(name="review", executor=reviewer),
    ],
)

workflow.print_response(
    "Topic: Why automated testing is worth the investment", markdown=True
)
```

At runtime, the output of the `draft` step自动 becomes the input of the `review` step — no manual wiring needed.

## 11.3 Three Shapes of Step Executors

```python
from agno.team import Team
from agno.workflow import Step, StepInput, StepOutput, Workflow


def data_preprocessor(step_input: StepInput) -> StepOutput:
    """Function executor: deterministic processing, consumes no tokens"""
    research = step_input.previous_step_content or "No research content received"
    return StepOutput(content=f"Research materials to analyze:\n{research}")


research_team = Team(name="Research Team", members=[...], model=model)

workflow = Workflow(
    name="mixed-pipeline",
    steps=[
        research_team,        # Shape 1: place Agent/Team directly (auto-wrapped as Step)
        data_preprocessor,    # Shape 2: place function directly
        Step(                 # Shape 3: explicit Step wrapper, recommended when naming/description needed
            name="analysis",
            executor=writer,
            description="Produce analysis report based on research output",
        ),
    ],
)
```

The three shapes can be freely mixed. Naming steps (`name=`) is not just for readability: event tracking and output lookup both use the step name as key.

## 11.4 StepInput and StepOutput: The Data Contract Between Steps

Function executors follow one standard signature — receive `StepInput`, return `StepOutput`:

```python
def summarize(step_input: StepInput) -> StepOutput:
    # input: the workflow's original user input (always preserved)
    original = str(step_input.input)
    # previous_step_content: the text output of the previous step
    prev = step_input.previous_step_content or ""
    # previous_step_outputs: if the upstream is a parallel block, get the output dict for each named step
    return StepOutput(
        content=f"Original request: {original}\n\nMaterial summary:\n{prev[:500]}",
    )
```

Quick reference for common fields:

| StepInput field | Meaning |
|---|---|
| `input` | The workflow's original user input |
| `previous_step_content` | The content text output by the previous step |
| `previous_step_outputs` | The集合 of outputs from upstream steps (especially useful after parallel aggregation) |
| `additional_data` | Custom data appended at runtime |

::: tip The Value of Function Steps
Inserting a plain function step between two Agents is the most common Workflow pattern: format转换, length truncation, result validation should not burn tokens — hand them to Python.
:::

## 11.5 Running and Parsing Output

`print_response()` suits debugging; production code uses `run()` to get structured results:

```python
result = workflow.run("Topic: vector database selection")

# workflow_output.content is the output of the last step
print(result.content)

# Finer-grained:查看 each step's execution result
for step_result in (result.step_results or []):
    print(step_result.step_name, "->", str(step_result.content)[:80])
```

You can also use `arun()` for async execution, or iterate the event stream when `run(..., stream=True)` to observe each step's start and end events.

## 11.6 Chapter Summary

- Team = model-driven flexible collaboration; Workflow = code-defined deterministic control flow;
- A `Step`'s executor can be an Agent, Team, function, or nested Workflow; all three can be mixed in one `steps` list;
- Data automatically flows downstream via `StepInput.previous_step_content`; `StepOutput(content=...)` is the standard出口 for function steps;
- Production code uses `run()` and iterates `step_results` to parse each step's output, rather than parsing printed text.
