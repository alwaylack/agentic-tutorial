# Chapter 9 · Agent Team Introduction: Collaboration Modes

> Chapter goals: understand Agno Team's "leader-member" architecture, master the mechanisms and applicable scenarios of four collaboration modes — coordinate / route / broadcast / tasks — and build a researcher + writer two-member team hands-on.

## 9.1 Why Teams Are Needed

A single Agent's context and role positioning are limited: asking it to research, write reports, and review simultaneously makes prompts increasingly bloated, and tools interfere with each other. **Team** splits tasks across multiple specialized Agents (members), with a **leader model** handling dispatch and aggregation — just like a small team division of labor: everyone focuses on their own work, and the team lead is accountable for final delivery.

::: warning When NOT to Use Teams
Each Team dispatch is an independent model call, introducing higher latency, token consumption, and coordination complexity. The official recommendation: if a single-domain task can be handled by one Agent, use a single Agent — don't use "multi-agent" just for the sake of it.
:::

```python
from agno.agent import Agent
from agno.team import Team

team = Team(
    members=[
        Agent(name="English Support", role="Answer customer questions in English"),
        Agent(name="Chinese Support", role="Answer customer questions in Chinese"),
    ],
)
```

## 9.2 Four Collaboration Modes

Agno explicitly specifies the mode via the `mode` parameter (import `TeamMode` from `agno.team.mode`). The four modes determine the leader's dispatch path:

| Mode | Config | Behavior |
|---|---|---|
| **Coordinate** (default) | `mode=TeamMode.coordinate` | Leader picks members, generates sub-tasks for each, then synthesizes results |
| **Route** | `mode=TeamMode.route` | Leader routes the request to **one** most suitable member, directly returning that member's reply |
| **Broadcast** | `mode=TeamMode.broadcast` | Same task sent to **all** members, then all answers aggregated |
| **Tasks** | `mode=TeamMode.tasks` | Leader maintains a shared task list, executing items one by one until the goal is reached |

::: info Version Note
Early versions expressed modes via combinations of two boolean switches: `respond_directly=True` (equivalent to route) and `delegate_to_all_members=True` (equivalent to broadcast). The unified `mode=` approach is now recommended; when both are present, `mode` overrides legacy flags.
:::

```python
from agno.team import Team, TeamMode

router_team = Team(
    name="Language Router",
    members=[english_agent, chinese_agent],
    mode=TeamMode.route,
    determine_input_for_members=False,   # User's original words passed directly to members, without leader rewriting
)
```

Selection heuristic: **split & synthesize → coordinate, classify & forward → route, multi-angle cross-validation → broadcast, checklist-driven → tasks**.

```python
from agno.team import Team, TeamMode

# broadcast: same task sent to all members then aggregated (old style: delegate_to_all_members=True)
review_team = Team(
    name="Multi-Perspective Review Panel",
    model=model,
    members=[lawyer, engineer, marketer],
    mode=TeamMode.broadcast,
)

# tasks: leader maintains shared task list, item by item — suitable for long-chain delivery
delivery_team = Team(
    name="Delivery Squad",
    model=model,
    members=[planner, developer, tester],
    mode=TeamMode.tasks,
)
```

## 9.3 How the Leader Dispatches

The complete flow under Coordinate mode:

1. Team receives user input;
2. Leader analyzes input, decides which members to delegate to;
3. Leader **writes specific sub-tasks** for each selected member (not simple forwarding);
4. Members execute independently and return results (members with no dependencies can execute concurrently);
5. Leader synthesizes all outputs into the final reply.

The leader can also call tools itself or answer directly (simple questions need not disturb members). Setting stable explicit `id`s on members helps with dispatch tracking and debugging.

## 9.4 Hands-On: Researcher + Writer Two-Member Team

```python
# research_writer_team.py
import os
from agno.agent import Agent
from agno.models.openai import OpenAIChat
from agno.team import Team, TeamMode
from agno.tools.duckduckgo import DuckDuckGoTools

model = OpenAIChat(
    id="deepseek-chat",
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    base_url="https://api.deepseek.com/v1",
)

researcher = Agent(
    name="Researcher",
    id="researcher",
    role="Responsible for online research, output only facts and sources",
    tools=[DuckDuckGoTools()],           # Researcher's exclusive tool: search
)

writer = Agent(
    name="Writer",
    id="writer",
    role="Responsible for rewriting materials into fluent Chinese essays, no fact-checking",
)

team = Team(
    name="Content Editorial Board",
    model=model,                          # Leader also needs a model for dispatch and synthesis
    members=[researcher, writer],
    mode=TeamMode.coordinate,
    instructions=[
        "First delegate the researcher to gather materials, then pass materials to the writer to compose.",
        "Final output: an essay within 300 characters, with source links attached.",
    ],
    markdown=True,
)

team.print_response("Introduce the core value of the MCP protocol")
```

After running and observing the logs, you will see two phases: first the researcher's tool calls and returns appear, then the writer generates an essay based on the materials, and finally the leader polishes the output.

## 9.5 Debugging and Cost Control

- **See the dispatch chain clearly**: enable `debug_mode=True` or read each member's independent responses and metrics to confirm whether the leader delegated to the right members;
- **Converge instructions**: `instructions` must clarify "who goes first, who goes second, what is the output"; vague instructions cause the leader to waver back and forth;
- **Control scale**: member count should typically be 2–4; for more roles, consider nested Teams or the Workflow fixed orchestration in the next chapter;
- **Model tiering**: the leader can use a cheap fast model; heavy-lifting members get strong models as needed.

## 9.6 Chapter Summary

- Team = leader (dispatch/synthesis) + multiple specialized members (execution);本质上是用额外模型调用换取职责分离;
- Four `TeamMode` modes: coordinate (split & synthesize), route (single-path forwarding), broadcast (all-member parallel), tasks (task-list driven). Prefer explicit `mode=` declaration;
- Coordinate flow: analyze → pick members → write sub-tasks → members execute concurrently → synthesize reply;
- `determine_input_for_members=False` lets user input reach members unchanged;
- Don't put single-Agent-solvable tasks on a Team; watch out for latency and token costs.
