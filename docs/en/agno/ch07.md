# Chapter 7 · Tools: Built-in Toolkit Principles and Usage

> Chapter goals: understand the complete execution loop of Agno tool calls; learn to use built-in toolkits; clarify "how functions become tools callable by the model".

## 7.1 Why Agents Need Tools

Large models本身只会生成文本 — they do not know today\'s stock price, cannot查 your database, and cannot send an email. **Tools** are the mechanism bridging this gap: register Python functions with the Agent; the model "requests调用" these functions when needed; Agno负责真正执行并把结果交回给模型.

::: tip Key Insight
Tools are not plugin-style magic;本质 is a loop: the model outputs "I want to call `get_weather(city='Beijing')`" → framework执行函数 → results appended to context →模型继续推理. This loop持续 until the model no longer requests tools and给出最终回答.
:::

The official docs describe the execution flow in five steps:

1. The Agent sends the current context and **tool definitions (schema)** to the model;
2. The model returns a普通回答, or requests one/multiple tool calls;
3. Agno validates parameters and **执行** each requested tool;
4. Tool results are加入模型上下文;
5. The loop continues until the model给出最终回答.

## 7.2 How Functions Become Tool Schemas

This is the most important principle in this chapter: **Agno automatically构建工具 schema from the function name, docstring, and type annotations**. See an官方风格的 example:

```python
import os
from agno.agent import Agent
from agno.models.openai import OpenAIChat


def lookup_order(order_id: str) -> dict:
    """Return the status and delivery date for an order.

    Args:
        order_id: The order ID to look up.
    """
    return {
        "order_id": order_id,
        "status": "shipped",
        "delivery_date": "2026-07-22",
    }


agent = Agent(
    # Unified third-party OpenAI-compatible model
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    tools=[lookup_order],  # Pass the function directly
    instructions="Use the order tool when a customer asks about a delivery.",
)

agent.print_response("When will order ORD-123 arrive?")
```

What the model实际收到 is a JSON Schema roughly equivalent to:

```json
{
  "name": "lookup_order",
  "description": "Return the status and delivery date for an order.",
  "parameters": {
    "type": "object",
    "properties": {
      "order_id": {
        "type": "string",
        "description": "The order ID to look up."
      }
    },
    "required": ["order_id"]
  }
}
```

From this we derive three铁律 for writing tools (官方称为 "Design Tools for Reliable Calls"):

- **Function names must be specific**: `lookup_order` is far better than `do_something`; the model靠名字选工具;
- **Write docstrings that clarify "when to use"**: they are the model\'s说明书;
- **Type annotations + parameter descriptions must be完整**: they directly决定入参 schema的准确性.

## 7.3 Built-in Toolkit Practical Usage

Writing custom tools固然灵活, but for common needs (search, quotes, web reading) the社区早有封装. Agno packs a group of related functions into a **Toolkit**; functions in one包 share内部状态 and协同工作. Using `DuckDuckGoTools` as the most common example:

```bash
pip install -U agno ddgs   # DuckDuckGoTools requires the ddgs library
```

```python
# search_agent.py —— give the Agent internet search capability
import os
from agno.agent import Agent
from agno.models.openai import OpenAIChat
from agno.tools.duckduckgo import DuckDuckGoTools

agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    tools=[DuckDuckGoTools()],
    instructions=["附带信息来源链接 when answering"],
    markdown=True,
    debug_mode=True,  # In v2, the way to observe tool calls: print detailed运行日志
)

agent.print_response("What major events happened in the AI Agent field this past week?")
```

After running you will see a process like this in the logs:

```text
● Tool call: web_search(query="AI Agent events past week")      ← model发起
● Tool result: [{"title": "...", "url": "..."}, ...]          ← function execution result
● Final answer (引用了搜索结果的链接)
```

> Note: Agno has移除旧版 `show_tool_calls=True` since 2.x (also in 3.x). To see tool call details, use `debug_mode=True`; for streaming场景, listen for tool events in `RunContentEvent`.

Other commonly used toolkits include `YFinanceTools` (financial quotes), `HackerNewsTools`, `Newspaper4kTools` (web reading), `FileTools` (local files), etc.; the full清单见官方 Toolkit Index. Another组合使用的 example:

```python
# stock_agent.py —— quotes tool + search tool collaboration
import os
from agno.agent import Agent
from agno.models.openai import OpenAIChat
from agno.tools.duckduckgo import DuckDuckGoTools
from agno.tools.yfinance import YFinanceTools

agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    tools=[
        YFinanceTools(enable_stock_price=True, enable_analyst_recommendations=True),
        DuckDuckGoTools(),
    ],
    instructions=[
        "优先使用行情工具获取金融数据的实时数据",
        "Use the search engine for industry news and注明来源",
        "Display data comparisons in tables",
    ],
    markdown=True,
    debug_mode=True,
)

agent.print_response("Compare the latest stock prices and analyst ratings for NVIDIA and AMD")
```

## 7.4 Toolkit Parameters and Trimming

Toolkits are not黑盒; most provide构造参数 to控制行为, and还支持统一裁剪暴露给模型的函数. Using `DuckDuckGoTools` as an example:

```python
# toolkit_params.py —— precisely control toolkit behavior
from agno.tools.duckduckgo import DuckDuckGoTools

tools = DuckDuckGoTools(
    enable_news=False,       # Disable news search; keep only web_search
    fixed_max_results=3,     # Fix maximum 3 results returned
    region="cn-zh",          # Region setting
    timeout=15,              # Timeout in seconds
)
```

Additionally, at the Agent level there are two通用参数 to further收窄暴露面:

```python
agent = Agent(
    # ...model config same as above...
    tools=[YFinanceTools(all=True)],
    include_tools=["get_current_stock_price"],  # Expose only whitelisted functions
    # exclude_tools=["get_company_profile"],    # Or exclude specified functions
)
```

::: warning Why Trim Tools
The more tools exposed, the harder the model\'s选择 becomes, and the higher the误调用率 (the official docs明确指出 "Expose only the tools needed for the task"). In production, an Agent with only 2 precise tools几乎总比 one with 20杂乱 tools更可靠.
:::

## 7.5 Tool Execution Control

Agno provides a组细粒度控制项; we认识 two most commonly used here; the rest (human confirmation, external execution) are expanded in Chapter 21 Guardrails:

| Config | Purpose |
|---|---|
| `tool_call_limit=N` | Limit the max工具 calls per run to N,防止死循环烧钱 |
| `read_chat_history=True` | Give the model an extra tool `get_chat_history()` to回看历史 on demand |
| Inject `run_context` into tools | Framework自动注入运行上下文 (user, session state, etc.); does not enter the model schema |

`run_context` is the关键 to understanding后续章节 (session state) —只要工具函数声明了这个参数, Agno自动传入 at execution, and**not count it into the model-visible parameters**:

```python
# run_context_demo.py —— hidden parameters injected by the framework
import os
from agno.agent import Agent
from agno.models.openai import OpenAIChat
from agno.run import RunContext


def who_is_calling(run_context: RunContext) -> str:
    """Get the current user id of this session."""
    # run_context is injected by the framework; the model cannot see it
    return f"Current user: {run_context.user_id or 'anonymous'}"


agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    tools=[who_is_calling],
)

agent.print_response("Who am I?", user_id="gao", session_id="s1")
```

Other built-in injected parameters include `agent`, `team`, and `images / videos / audios / files` (access multi-modal inputs carried by this run).

## 7.6 Chapter Summary

- Tools = Python functions registered with the Agent; execution is a loop of "request → execute →回填 → re-reason";
- **Function name + docstring + type annotations** together constitute the model-visible tool schema; quality of all three directly决定调用可靠性;
- Built-in Toolkits开箱即用 (`DuckDuckGoTools`, `YFinanceTools`, etc.);构造参数可精控行为;
- Trim exposure with `include_tools` / `exclude_tools`; fewer tools > more;
- In v2, observe tool calls with `debug_mode=True` (`show_tool_calls` removed); `run_context: RunContext` is a hidden parameter auto-injected by the框架.
