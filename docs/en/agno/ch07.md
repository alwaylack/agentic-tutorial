# Chapter 7 · Tools: Built-in Toolkit Principles and Usage

> Chapter goals: understand the complete execution loop of Agno tool calls, learn to use built-in toolkits, and clarify "how functions become model-callable tools".

## 7.1 Why Agents Need Tools

Large models can only generate text — they do not know today's stock price, cannot query your database, and cannot send an email. **Tools (Tools)** are the mechanism that bridges this gap: register Python functions with the Agent, and when needed the model "requests calling" those functions; Agno is responsible for actually executing them and returning results to the model.

::: tip Key Insight
Tools are not plugin-style magic; essentially they are a loop: the model outputs "I want to call `get_weather(city='Beijing')`" → the framework executes the function → results are appended to context → the model continues reasoning. This loop continues until the model stops requesting tools and gives a final answer.
:::

The official docs describe the execution flow in five steps:

1. The Agent sends current context and **tool definitions (schema)** to the model;
2. The model returns a normal answer, or requests one/multiple tool calls;
3. Agno validates parameters and **executes** each requested tool;
4. Tool results are added to the model's context;
5. The loop continues until the model gives a final answer.

## 7.2 How Functions Become Tool Schema

This is the most important principle in this chapter: **Agno automatically builds tool schema from function name, docstring, and type annotations**. Here is an example in the official style:

```python
import os
from agno.agent import Agent
from agno.models.openai import OpenAIChat


def lookup_order(order_id: str) -> dict:
    """Return the status and delivery date for an order.

    Args:
        order_id: The order ID to look up.
    """
    return {
        "order_id": order_id,
        "status": "shipped",
        "delivery_date": "2026-07-22",
    }


agent = Agent(
    # Uniformly use third-party OpenAI-compatible models
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    tools=[lookup_order],  # Pass the function directly
    instructions="Use the order tool when a customer asks about a delivery.",
)

agent.print_response("When will order ORD-123 arrive?")
```

What the model actually receives is a JSON Schema roughly equivalent to:

```json
{
  "name": "lookup_order",
  "description": "Return the status and delivery date for an order.",
  "parameters": {
    "type": "object",
    "properties": {
      "order_id": {
        "type": "string",
        "description": "The order ID to look up."
      }
    },
    "required": ["order_id"]
  }
}
```

From this we can derive three iron laws for writing tools (officially called "Design Tools for Reliable Calls"):

- **Function names must be specific**: `lookup_order` is far better than `do_something`; the model picks tools by name;
- **Write docstrings clarifying "when to use"**: it is the model's instruction manual;
- **Type annotations + parameter descriptions must be complete**: they directly determine the accuracy of the input schema.

## 7.3 Built-in Toolkit Practice

Writing custom tools is flexible, but common needs (search, market data, web reading) have long been封装 by the community. Agno packages related functions into **Toolkits**; functions within a kit share internal state and work协同. Taking the most commonly used `DuckDuckGoTools` as an example:

```bash
pip install -U agno ddgs   # DuckDuckGoTools requires the ddgs library
```

```python
# search_agent.py —— Give the Agent web search capability
import os
from agno.agent import Agent
from agno.models.openai import OpenAIChat
from agno.tools.duckduckgo import DuckDuckGoTools

agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    tools=[DuckDuckGoTools()],
    instructions=["Include source links when answering"],
    markdown=True,
    debug_mode=True,  # v2 way to observe tool calls: print detailed run logs
)

agent.print_response("What are the big events in the AI Agent field this past week?")
```

After running you will see in the logs a process like:

```text
● Tool call: web_search(query="AI Agent 大事 最近一周")      ← Model initiates
● Tool result: [{"title": "...", "url": "..."}, ...]          ← Function execution result
● Final answer (referencing links from search results)
```

> Note: Agno has removed the old `show_tool_calls=True` parameter since 2.x (also in 3.x). To see tool-call details, use `debug_mode=True`; in streaming scenarios listen for tool events in `RunContentEvent`.

Other commonly used toolkits include `YFinanceTools` (financial quotes), `HackerNewsTools`, `Newspaper4kTools` (web reading), `FileTools` (local files), etc. The full list is in the official Toolkit Index. Here is another example combining multiple kits:

```python
# stock_agent.py —— Market data tool + search tool collaboration
import os
from agno.agent import Agent
from agno.models.openai import OpenAIChat
from agno.tools.duckduckgo import DuckDuckGoTools
from agno.tools.yfinance import YFinanceTools

agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    tools=[
        YFinanceTools(enable_stock_price=True, enable_analyst_recommendations=True),
        DuckDuckGoTools(),
    ],
    instructions=[
        "Use market data tools to fetch real-time data for financial information",
        "Query industry news with the search engine and note the source",
        "Present data comparisons in tables",
    ],
    markdown=True,
    debug_mode=True,
)

agent.print_response("Compare NVIDIA and AMD latest stock prices and analyst ratings")
```

## 7.4 Toolkit Parameters and Trimming

Toolkits are not black boxes; most provide construction parameters to control behavior, and support unified trimming of which functions are exposed to the model. Using `DuckDuckGoTools` as an example:

```python
# toolkit_params.py —— Precisely control toolkit behavior
from agno.tools.duckduckgo import DuckDuckGoTools

tools = DuckDuckGoTools(
    enable_news=False,       # Disable news search, keep only web_search
    fixed_max_results=3,     # Fixed maximum 3 results returned
    region="cn-zh",          # Region setting
    timeout=15,              # Timeout in seconds
)
```

Additionally, at the Agent level there are two general parameters to further narrow the exposure surface:

```python
agent = Agent(
    # ...model config as above...
    tools=[YFinanceTools(all=True)],
    include_tools=["get_current_stock_price"],  # Only expose whitelist functions
    # exclude_tools=["get_company_profile"],    # Or exclude specified functions
)
```

::: warning Why Trim Tools
The more tools exposed, the harder for the model to choose, and the higher the误call rate (the official docs explicitly state "Expose only the tools needed for the task"). In production, an Agent with only 2 precise tools is almost always more reliable than one with 20 miscellaneous tools.
:::

## 7.5 Tool Execution Control Mechanisms

Agno provides a set of fine-grained controls; here we meet two of the most commonly used, while the rest (manual confirmation, external execution) are expanded in Chapter 21 on Guardrails:

| Configuration | Role |
|---|---|
| `tool_call_limit=N` | Limits maximum tool calls per run to N, preventing infinite loops burning money |
| `read_chat_history=True` | Adds an extra `get_chat_history()` tool to the model, allowing on-demand history review |
| Inject `run_context` into tools | Framework auto-injects runtime context (user, session state, etc.); does not enter model schema |

`run_context` is the key to understanding subsequent chapters (session state) — as long as the tool function declares this parameter, Agno auto-passes it at execution time and **does not count it toward model-visible parameters**:

```python
# run_context_demo.py —— Hidden parameters injected by the framework
import os
from agno.agent import Agent
from agno.models.openai import OpenAIChat
from agno.run import RunContext


def who_is_calling(run_context: RunContext) -> str:
    """Get the current user id of this session."""
    # run_context is injected by the framework; the model cannot see it
    return f"Current user: {run_context.user_id or 'anonymous'}"


agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    tools=[who_is_calling],
)

agent.print_response("Who am I?", user_id="gao", session_id="s1")
```

Other built-in injectable parameters include `agent`, `team`, and `images / videos / audios / files` (access multi-modal inputs carried this run).

## 7.6 Chapter Summary

- Tools = Python functions registered with the Agent; execution is a loop of "request → execute → feedback → further reasoning";
- **Function name + docstring + type annotations** together form the model-visible tool schema; quality of all three directly determines call reliability;
- Built-in Toolkits are ready-to-use (`DuckDuckGoTools`, `YFinanceTools`, etc.); construction parameters精控 behavior;
- Use `include_tools` / `exclude_tools` to trim exposure surface; fewer tools is better;
- v2 observe tool calls with `debug_mode=True` (`show_tool_calls` removed); `run_context: RunContext` is a hidden parameter auto-injected by the framework.
