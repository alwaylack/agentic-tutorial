# Chapter 24 · Observability and Debugging

> Chapter goals: learn to read the token and latency账单 for each run using metrics, troubleshoot the tool-call chain with debug_mode, and搭建生产级监控 with OpenTelemetry tracing.

## 24.1 Metrics: The Bill for Each Run

`RunOutput.metrics` records the token usage, cost, latency, and model-wise breakdown for this run. It answers "how much did this call成本, and where did it慢?"

```python
import os
from agno.agent import Agent
from agno.models.openai import OpenAIChat

agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    markdown=True,
)

response = agent.run("Explain vector retrieval in three sentences")

m = response.metrics
print("Input tokens:", m.input_tokens)
print("Output tokens:", m.output_tokens)
print("Total tokens:", m.total_tokens)
print("Duration:", m.duration)
```

All three layers — Agent, Team, Workflow — have metrics: Team breaks down to the member level; Workflow to the step level —这正是定位 "哪个环节最烧钱/最慢" 的依据.

## 24.2 Debug Mode: Seeing the Execution Flow

The core debugging诉求 is three things: what messages were sent to the model, what the model replied, and what the tool-call chain looked like. `debug_mode` gives all three at once:

```python
agent = Agent(
    model=model,
    tools=[DuckDuckGoTools()],
    instructions="Write a report on the topic, output only the report itself.",
    markdown=True,
    debug_mode=True,     # Print model requests/responses, tool calls and results, intermediate steps
    # debug_level=2,     # Open when more detailed logs are needed
)

agent.print_response("Trending startups and products.")
```

Three开启方式, scope从 small to large:

1. `agent.run(..., debug_mode=True)` — single run;
2. `Agent(debug_mode=True)` — all runs for that Agent;
3. Environment variable `AGNO_DEBUG=True` — global enable.

When排查工具调用链, debug logs展示 in order: the model decides which tool to call → tool入参 → tool返回 → how the result enters the next model request. The vast majority of "tools not生效" issues出 in the second and third rings (入参不符合预期, returned内容太长被截断).

## 24.3 Interactive CLI: Quick Multi-Turn Validation

Debugging multi-turn behavior (memory,历史注入) by repeatedly写脚本 is painful; Agno内置了 CLI 应用模式:

```python
from agno.db.sqlite import SqliteDb

agent = Agent(
    model=model,
    db=SqliteDb(db_file="tmp/debug.db"),
    add_history_to_context=True,
    num_history_runs=3,
    markdown=True,
)

agent.cli_app(stream=True)   # Run as an interactive multi-turn conversation in the terminal
```

## 24.4 Production Tracing: OpenTelemetry and AgentOS Tracing

Debug logs suit the开发期; production needs **structured tracing**. AgentOS has built-in OpenTelemetry-based tracing; just开 one switch:

```python
from agno.os import AgentOS

agent_os = AgentOS(
    agents=[agent],
    db=db,            # Trace data写入该数据库
    tracing=True,     # Instrument agent/team/workflow runs
)
```

After开启, each run produces:

- **Span**: one each for model calls, tool executions, Team coordination, Workflow steps; containing parent-child relationships, status, timestamps, duration, and attributes JSON; written to the `agno_spans` table;
- **Trace**: the聚合记录 for one run (run/session/user/component ID, start/end time, total duration); written to the `agno_traces` table.

Tracing follows the OpenInference语义规范; can be directly analyzed with SQL:

```sql
-- Slowest 10 span types
SELECT name, AVG(duration_ms) AS avg_ms, COUNT(*) AS calls
...
```

::: tip独立追踪库要独立
Trace data写入频繁、量大, with完全不同的访问模式 from业务会话数据. The官方建议给 AgentOS 的 `db` 单独指一个专用追踪数据库, isolating trace写入量 from session data,各自设置保留策略.
:::

The same trace tree also renders in the Agno Control Plane (os.agno.com): click into a single run to see the完整的 LLM hops, tool calls with输入输出, and子 Agent tracing, and filter by user/session/time.

## 24.5 Designing Your Production Monitoring Baseline

Combining the三层数据 Agno provides, a practical监控基线 is:

| Dimension | Metric | Source |
|---|---|---|
| Cost | total_tokens per session/user, broken down by model | `metrics` |
| Latency | P50/P95 run duration, step-level耗时 | `metrics` + `agno_spans` |
| Quality | Tool call失败率, retry count | spans + debug logs |
| Behavior | Session length分布, member dispatch频率 | traces + sessions |

::: warning Privacy Reminder
trace attributes may contain prompts, tool parameters, and model outputs. Apply the same访问控制和保留策略 to trace data as you would to业务敏感数据; do not treat the生产追踪库 as an un权限的日志库.
:::

## 24.6 Chapter Summary

- `RunOutput.metrics` provides token/cost/duration/model breakdown; Teams and Workflows have member-level and step-level细分;
- `debug_mode` has three scopes (单次运行/Agent/全局环境变量) + `debug_level=2` is the利器 for troubleshooting tool chains;
- `cli_app()` suits快速验证多轮会话行为;
- Production tracing = `AgentOS(tracing=True)` + a专用追踪库; spans land in `agno_spans`, aggregated in `agno_traces`; follows OpenInference for direct SQL分析;
- The监控基线 covers四个维度: cost, latency, quality, behavior.
