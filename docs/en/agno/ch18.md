> Chapter goals: distinguish the two RAG modes — Agentic RAG vs. traditional RAG; master three关键技术 to提升检索质量: chunking strategies, metadata filtering, and rerankers.

## 18.1 Agentic RAG vs. Traditional RAG

The example from the previous chapter is **Agentic RAG**: the model gets a `search_knowledge_base` tool and自主决定 "whether to查, what词 to search"; it can also改写 queries and do多轮补充检索. **Traditional RAG** is a fixed pipeline —每次提问都先检索;把结果直接注入提示词:

```python
from agno.agent import Agent

# Traditional RAG: retrieve先 on each request;参考内容自动拼进用户消息
traditional = Agent(
    model=model,
    knowledge=knowledge,
    add_knowledge_to_context=True,   # Retrieval results直接加入上下文
)

# Agentic RAG: the模型自主 decide whether/how to retrieve (default behavior)
agentic = Agent(
    model=model,
    knowledge=knowledge,
    search_knowledge=True,           # Register the retrieval tool; leave决策 to the model
)
```

| Dimension | Traditional RAG | Agentic RAG |
|---|---|---|
| Retrieval时机 | Always检索 on each request | Model decides on需求 |
| Latency & cost | Low and可预测 | Extra一轮工具调用 |
| Complex questions | Single retrieval可能不够 | Can改写查询, multiple retrievals |
| Suitable场景 | Simple Q&A,低延迟要求 | Knowledge work requiring多步推理 |

::: tip Selection建议
For客服 FAQ这类 "一问一答", traditional RAG suffices; for研究分析类任务 use Agentic RAG. The two can coexist配置.
:::

## 18.2 Chunking Strategies: The First Factor Determining Recall

The最小单位 stored in the向量库 is the chunk. Chunk too大 and unrelated content dilutes相似度; chunk too小 and语义不完整. Agno内置多种 `Chunking` strategies挂 on the Reader:

```python
from agno.knowledge.chunking.fixed import FixedSizeChunking
from agno.knowledge.chunking.recursive import RecursiveChunking
from agno.knowledge.chunking.document import DocumentChunking
from agno.knowledge.reader.pdf_reader import PDFReader
from agno.knowledge.knowledge import Knowledge

# Fixed length:简单粗暴; suits格式规整的文本
fixed_reader = PDFReader(chunking_strategy=FixedSizeChunking(size=1500))

# Recursive chunking:退 at paragraph→sentence→character多级分隔符; best通用性
recursive_reader = PDFReader(chunking_strategy=RecursiveChunking())

# Document-structure chunking:切按标题/段落等文档结构边界;保持章节完整
doc_reader = PDFReader(chunking_strategy=DocumentChunking())

knowledge = Knowledge(vector_db=vector_db)
knowledge.insert(path="handbook.pdf", reader=recursive_reader)
```

经验选型: Markdown/HTML use结构化切块; code use Code Chunking; unstructured长文 start with recursive chunking; if效果不佳 try Semantic Chunking based on embedding相似度断句.

## 18.3 Metadata Filtering: Making Retrieval "查得准"

Tag入库内容 with metadata labels; filter by标签 at query time to缩小检索范围 from "全库" to "该用户/该年份/该类型":

```python
# Attach metadata at insert time
knowledge.insert(
    path="resumes/",
    metadata={"department": "engineering", "year": 2025},
)

# Method 1:固定过滤 at the Agent level — this Agent永远只看 engineering docs
agent = Agent(
    model=model,
    knowledge=knowledge,
    search_knowledge=True,
    knowledge_filters={"department": "engineering"},
)

# Method 2:临时过滤 at call time; multiple conditions are ANDed
agent.print_response(
    "Summarize the highlights of engineer resumes hired in 2025",
    knowledge_filters={"year": 2025},
)

# Direct retrieval同样支持 filters
results = knowledge.search(query="Python experience", filters={"department": "engineering"})
```

You can also enable `enable_agentic_knowledge_filters=True` to let the模型从用户提问中自动推断过滤条件 (e.g., extract `user_id=jordan` from "Jordan\'s skills"); this requires配合 Contents DB to记录可用的过滤键.

## 18.4 Reranker: The Final Gate for Precision Ranking

Vector检索返回的是"粗排"结果. **Reranker** uses a heavier but更精准的交叉编码模型 to打分重新排序候选片段 one-by-one, pushing真正相关的 to the top:

```python
import os
from agno.knowledge.reranker.cohere import CohereReranker
from agno.vectordb.lancedb import LanceDb, SearchType

knowledge = Knowledge(
    vector_db=LanceDb(
        uri="tmp/lancedb",
        table_name="docs",
        search_type=SearchType.hybrid,   # Hybrid retrieval:向量 + keyword dual signals
        embedder=embedder,
        reranker=CohereReranker(model="rerank-v3.5"),   # Precision ranking model
    ),
)
```

分工 for the three组合: **hybrid retrieval** captures both语义相似 and关键词精确匹配 signals; **reranking** then做细粒度相关性排序 on these candidates. This is the标准三件套 for生产级 RAG.

## 18.5 How to Evaluate Retrieval Quality

改参数不能靠感觉;建立最小评估闭环:

1. Prepare 20–50 annotated pairs of 「question →应命中内容」;
2. Batch跑 with `knowledge.search()`;统计命中率 (whether the正确片段 is in top-k);
3. Re-run and对比每次调整切块大小/换 Embedding model/加重排后的效果.

```python
def hit_rate(kb, cases, k=5):
    hits = sum(
        any(c["keyword"] in r.content for r in kb.search(q=c["q"], top_k=k))
        for c in cases
    )
    return hits / len(cases)   # e.g., 0.85 means 85% of questions recalled the target snippet
```

## 18.6 Chapter Summary

- Agentic RAG (`search_knowledge=True`,模型自主检索) and traditional RAG (`add_knowledge_to_context=True`, retrieve-then-answer)各有适用场景;
- Chunking策略通过 Reader\'s `chunking_strategy` config; recursive chunking is the通用起点;
- `knowledge_filters`实现元数据过滤; `enable_agentic_knowledge_filters=True` lets the模型自动推断过滤条件;
- `SearchType.hybrid` + Reranker is the标准组合 for production retrieval;
- Use a小规模标注集 to量化评估每次调优的效果.
