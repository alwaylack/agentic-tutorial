# Chapter 10 · Team Advanced: Shared State and Member Communication

> Chapter goals: master switching among the four Team collaboration modes, learn the correct posture for sharing session state among members, and observe intra-team分工 via streaming events.

## 10.1 Four Collaboration Modes Overview

In the previous chapter we used `mode=TeamMode.coordinate` to let the leader dispatch tasks. Agno explicitly exposes four collaboration styles (`from agno.team.mode import TeamMode`):

| Mode | Config | Behavior |
|---|---|---|
| Coordinate (default) | No `mode` or set `coordinate` | Leader picks members, rewrites tasks, aggregates results |
| Route | `mode=TeamMode.route` | Leader routes to one member, **directly returns that member's reply** |
| Broadcast | `mode=TeamMode.broadcast` | Same task sent to all members |
| Tasks | `mode=TeamMode.tasks` | Leader maintains shared task list, loops until completion |

::: warning On Legacy Parameters
Old `respond_directly=True` and `delegate_to_all_members=True` remain compatible (mapping to `route` and `broadcast` respectively), but **new code should uniformly use `mode=`** — when both appear, `mode` overrides legacy flags.
:::

## 10.2 Route Mode: Direct Reply

For customer-service triage and language-routing scenarios where the leader need not再加工 results, route mode yields the lowest latency:

```python
import os
from agno.agent import Agent
from agno.models.openai import OpenAIChat
from agno.team import Team, TeamMode

model = OpenAIChat(
    id="deepseek-chat",
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    base_url="https://api.deepseek.com/v1",
)

billing_agent = Agent(name="Billing Agent", role="Handle billing and refund issues", model=model)
tech_agent = Agent(name="Tech Agent", role="Handle technical fault issues", model=model)

router_team = Team(
    name="Customer Router",
    model=model,
    mode=TeamMode.route,
    members=[billing_agent, tech_agent],
    # Key switch: pass user's original input verbatim to members, without leader rewriting
    determine_input_for_members=False,
    instructions=["Route requests to the most suitable member; answer自行 when unable to judge."],
)

router_team.print_response("My order was charged twice", stream=True)
```

`determine_input_for_members=False` is an important detail of route mode: without it, the leader默认 still "polishes" the task description for members, which反而 introduces distortion in scenarios requiring原话透传.

## 10.3 Broadcast and Tasks Modes

Broadcast suits "multi-perspective parallel review"; task loops suit goal-driven long flows:

```python
from agno.team import Team, TeamMode

# Broadcast: three reviewers simultaneously receive the same manuscript
review_team = Team(
    name="Review Panel",
    model=model,
    mode=TeamMode.broadcast,   # Same task sent to each member
    members=[
        Agent(name="Legal Reviewer", role="Review from compliance perspective", model=model),
        Agent(name="UX Reviewer", role="Review from user experience perspective", model=model),
        Agent(name="SEO Reviewer", role="Review from search optimization perspective", model=model),
    ],
    instructions="Aggregate all member opinions and output a merged revision checklist.",
)

# Task loop: leader decomposes task list and advances item by item
ops_team = Team(
    name="Ops Team",
    model=model,
    mode=TeamMode.tasks,
    max_iterations=6,          # Cap the task loop iterations to prevent runaway token burn
    members=[tech_agent, billing_agent],
)
```

Tasks mode务必 set `max_iterations`: the task list is generated and checked off by the model itself; an uncapped loop hands the budget to the model.

## 10.4 Sharing Session State Among Members

To let multiple members collaborate around the same mutable state (e.g., jointly maintaining a shopping list), the core is three things: **declare `session_state` on the team, enable `add_session_state_to_context`, and have the team and members share the same database**:

```python
import os
from agno.agent import Agent
from agno.db.sqlite import SqliteDb
from agno.models.openai import OpenAIChat
from agno.team import Team

db = SqliteDb(db_file="tmp/team.db")
model = OpenAIChat(
    id="deepseek-chat",
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    base_url="https://api.deepseek.com/v1",
)

shopping_agent = Agent(
    id="shopping-agent",
    name="Shopping List Agent",
    role="Manage the shopping list",
    model=model,
    db=db,                                    # Must share the same db as the team to共享 session
    add_session_state_to_context=True,        # Let members see the session state
    enable_agentic_state=True,                # Allow members to自主修改 state during conversation
)

team = Team(
    name="Household Team",
    members=[shopping_agent],
    session_state={"shopping_list": []},      # Initial shared state
    db=db,
    add_session_state_to_context=True,
    enable_agentic_state=True,
    description="You are a team managing shopping lists and household chores",
    show_members_responses=True,
)

team.print_response("Add milk, eggs, and bread to the shopping list")
team.print_response("I already bought eggs; what's still on the list?")

print(f"Final state: {team.get_session_state()}")
```

Another lightweight technique is **template injection** — state variables can be written directly into instructions, auto-replaced at runtime:

```python
team = Team(
    members=[],
    session_state={"user_name": "Xiao Ming"},
    instructions="The user's name is {user_name}; address them by name.",
    markdown=True,
)
```

## 10.5 Observing Division of Labor: Streaming Events and Member Responses

The key to debugging teams is seeing "who is doing the work". Three techniques配合:

```python
team = Team(
    name="Research Team",
    model=model,
    members=[news_agent, finance_agent],
    markdown=True,
    show_members_responses=True,   # Original replies from each member附带 in the final response
)

# With stream=True you can observe the full process: leader dispatch → member execution → leader synthesis
for event in team.run("What are the recent developments in AI companies and NVDA stock performance?", stream=True):
    print(event)   # Member start, tool calls, content increments all have corresponding events
```

Three配套 best practices:

1. **Set explicit `id`s on members**: dispatch selection and run tracking both use member ids; more稳定 than relying on names;
2. **Model inheritance**: when members do not set `model`, they自动 inherit the team's model — letting "members use small models, leader uses a big model" require only one省略;
3. **Callable factories**: `members=` can accept functions that dynamically decide the lineup based on `session_state` at each run (remember to配 `cache_callables=False`).

## 10.6 Chapter Summary

- New code uniformly uses `mode=TeamMode.coordinate/route/broadcast/tasks`; legacy flags `respond_directly` are overridden;
- Route mode配 `determine_input_for_members=False` passes user input verbatim to members;
- Full conditions for shared state: team and members share the same `db` + both set `add_session_state_to_context=True` + open `enable_agentic_state=True` when autonomous modification is needed;
- instructions support `{var}` template injection of session state;
- `show_members_responses` + streaming events + explicit member `id`s are the三板斧 for observing team division.
