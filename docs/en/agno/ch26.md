## 26.1 Requirements and Architecture Design

业务方不想写 SQL,也不想学 pandas — they希望 **用一句话拿到结论和图**. We拆解这条链路 into four角色:

```text
User question: "Which region had the worst sales decline last quarter?"
    │
    ▼
┌─────────────────────────────────────────────┐
│ Report Workflow                              │
│                                              │
│  Step1 Data Probe (function) ──▶ Step2 Deep Analysis (Agent) │
│         │                        │          │
│   describe/group aggregations    call query_csv   │
│   Results injected into context   multi-turn queries + charts     │
│                                  │          │
│                    Step3 Report Writing (Agent)      │
└─────────────────────────────────────────────┘
    │
    ▼
Markdown analysis report + charts/*.png
```

分工原则 with Chapter 21一致: **确定性任务给函数执行器 (zero token cost), 需要推理的才给 Agent**. Data probing is a固定动作 (describe + dimension enumeration); no need to burn模型; but "which insights are worth writing into the report" must be判断 by the model.

## 26.2 Data Probe Tool: query_csv

The first自定义工具 handles所有确定性 data access. Return a **dict structured result** instead of concatenated文本 — as explained in Chapter 8, the model extracts info from结构化 fields more reliably than parsing大段文字:

```python
# data_tools.py —— two tools: data probe and chart generation
import os
import pandas as pd
from agno.tools import tool

CSV_PATH = "sales.csv"

@tool(name="query_csv", description="Probe or group-aggregate the sales CSV")
def query_csv(operation: str, group_by: str = "", metric: str = "") -> dict:
    """operations support: describe / group_sum / top_n; group_by is the grouping column name"""
    df = pd.read_csv(CSV_PATH)

    if operation == "describe":
        # Whole-table overview: column types, missing values, numeric stats
        return {
            "shape": list(df.shape),
            "columns": list(df.columns),
            "dtypes": {c: str(t) for c, t in df.dtypes.items()},
            "missing": int(df.isna().sum().sum()),
            "numeric_summary": df.describe().to_dict(),
        }

    if operation == "group_sum":
        # Group aggregation: e.g., sum amount by region
        grouped = df.groupby(group_by)[metric].sum().sort_values(ascending=False)
        return {"group_by": group_by, "metric": metric,
                "values": grouped.to_dict()}

    if operation == "top_n":
        # Top N detailed rows
        top = df.nlargest(3, metric).to_dict(orient="records")
        return {"top_by": metric, "rows": top}

    return {"error": f"Unknown operation: {operation}"}
```

三个要点:

- `@tool(name=..., description=...)` explicitly names and describes the tool — this描述 enters the model\'s function definition; the more具体 it is, the higher the命中率 for the model to choose the correct操作;
- Parameter signatures are the JSON Schema source: `operation: str` required; `group_by` / `metric` optional with defaults;
-异常输入 returns `{"error": ...}` instead of raising, allowing the model to自行修正参数重试.

## 26.3 Chart Generation Tool: chart

matplotlib defaults to报错 in environments without a display (服务器/Docker); must first switch to the `Agg` backend. The generated file paths are returned to the model; the报告阶段引用 directly:

```python
import matplotlib
matplotlib.use("Agg")          # Must set before importing pyplot
import matplotlib.pyplot as plt
from pathlib import Path

@tool(name="chart", description="Generate a bar chart from aggregated data")
def chart(data: dict, title: str = "") -> dict:
    fig, ax = plt.subplots()
    ax.bar(data["labels"], data["values"])
    if title: ax.set_title(title)
    path = Path(f"charts/{title or 'chart'}.png")
    path.parent.mkdir(parents=True, exist_ok=True)
    fig.savefig(path)
    plt.close(fig)
    return {"chart_path": str(path)}
```

## 26.4 Building the Workflow Pipeline

Combining tools into a线性 Workflow:

```python
from agno.agent import Agent
from agno.workflow import Workflow, Step
from agno.models.openai import OpenAIChat
import os

model = OpenAIChat(
    id="deepseek-chat",
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    base_url="https://api.deepseek.com/v1",
)

# Step1: deterministic probe —函数执行器
probe = Step(
    name="probe",
    executor=query_csv,          # Direct function call, no token cost
)

# Step2: deep analysis — Agent
deep_analyst = Agent(
    name="DeepAnalyst",
    model=model,
    tools=[query_csv, chart],
    instructions=["Based on the probe data, find trends, anomalies, and risks. Output structured findings."],
)

# Step3: report writing — Agent
writer = Agent(
    name="ReportWriter",
    model=model,
    instructions=["Synthesize the findings into a professional Markdown weekly report with charts referenced."],
)

workflow = Workflow(
    name="sales-weekly-report",
    steps=[
        Step(name="probe", executor=probe),
        Step(name="analyze", executor=deep_analyst),
        Step(name="write", executor=writer),
    ],
)

if __name__ == "__main__":
    workflow.print_response(
        "Focus on month-over-month changes and潜在风险 across regions", markdown=True
    )
```

Note the `probe` signature convention:接受 `StepInput`,返回 `StepOutput`;传递数据 between步骤 via `previous_step_content` (the pattern from Chapter 11). Only Step2耗 token, and its起点 is already a结构化 data profile — saving far more than asking the模型裸.

## 26.5 Optional Enhancement: Team for Dual-Role Report Refinement

If报告质量要求高 (对外发布级别), replace Steps 2–3 with a **Team**: the analystproduces a draft; the reviewer逐条核对数字后定稿. The Team\'s routing模式让审稿意见自动回传 (see Chapter 19):

```python
# team_report.py —— Analyst + Reviewer collaboration (replaces the last two workflow steps)
from agno.team import Team

fact_checker = Agent(
    name="FactChecker",
    model=model,
    tools=[query_csv],
    instructions=["Verify every number in the report; immediately指出 if it conflicts with the CSV and给出正确值."],
)

report_team = Team(
    name="report-team",
    model=model,
    members=[deep_analyst, fact_checker, writer],
    instructions=[
        "Collaboratively produce the weekly report: Analyst drafts, FactChecker verifies all numbers, Writer finalizes.",
        "Do not进入终稿 if there are未通过 checks.",
    ],
)

report_team.print_response(
    "Based on data overview: … (probe step output)\nPlease产本周销售周报",
    markdown=True,
)
```

实战取舍建议:内部周报 use the linear Workflow from 26.5 (fast, cheap,稳定);对外发布再 up Team (slightly slower, but numbers经过核验). **Do not默认全上 Team** — one more member means几轮 more交互 token.

## 26.6 Chapter Summary

- Architecture principle for综合实战: **确定性步骤用函数执行器, 推理步骤用 Agent, 格式固化用 Workflow**;
- Tools returning结构化 dict with explicit name/description显著提升了模型调用准确率;
- matplotlib must切 Agg backend on the服务端; charts return file paths for报告引用;
- Linear Workflow vs. Team取舍: cost vs. quality天平; choose based on受众, not盲目堆成员;
- This "probe → analyze → write" pipeline can be directly迁移 to your own业务表 — just换掉 CSV_PATH and the prompts.
