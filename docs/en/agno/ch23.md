## 23.1 What Is AgentOS

The code in前面章节 are all "run and the process ends" scripts. AgentOS is Agno's官方 runtime: it wraps your智能体 into a **FastAPI application you own and self-host**, providing执行 API,持久化状态, authorization,追踪, and运维 endpoints.

```python
import os
from agno.agent import Agent
from agno.db.sqlite import SqliteDb
from agno.models.openai import OpenAIChat
from agno.os import AgentOS

db = SqliteDb(db_file="tmp/agentos.db")

support_agent = Agent(
    id="support-agent",            # id becomes part of the URL; must set explicitly
    name="Support Agent",
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    db=db,
)

agent_os = AgentOS(
    id="product-agent-os",
    agents=[support_agent],
    teams=[],          # Can also注册 teams=[...], workflows=[...]
    workflows=[],
    db=db,             # Components未单独配库时继承该默认库
)

app = agent_os.get_app()   # Get the原生 FastAPI instance

if __name__ == "__main__":
    agent_os.serve(app="agent_os:app", reload=True)   # Listens on port 7777 by default
```

After启动,访问 `http://localhost:7777` to see the interfaces provided by the runtime. `get_app()` returns a标准 FastAPI application, so the整套部署经验 for Uvicorn/Gunicorn/Docker all apply.

## 23.2 Auto-Generated REST Interfaces

AgentOS organizes执行端点 by 「component type + component id」:

| Component | Execution endpoint |
|---|---|
| Agent | `POST /agents/{agent_id}/runs` |
| Team | `POST /teams/{team_id}/runs` |
| Workflow | `POST /workflows/{workflow_id}/runs` |

Call the刚才的客服 Agent with curl:

```bash
curl http://localhost:7777/agents/support-agent/runs \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "message=Where is my order?" \
  -d "user_id=customer-42" \
  -d "session_id=order-support-42" \
  -d "stream=false"
```

Key points:

- The response contains `run_id` and `session_id`; **复用同一个 `session_id`串成同一会话线程** multiple calls;
- When `stream=true`, the endpoint returns events via SSE流式; add `-N` to curl to see逐块输出;
- Besides message, you can also pass `dependencies`, `session_state`, `metadata`, `knowledge_filters`, and even `output_schema` (JSON Schema string) to注入运行时上下文.

## 23.3 Encapsulating Calls with a Python Client

生产代码里当然不会手写 curl. Wrap with an `httpx`-based client that manages sessions:

```python
import httpx


class AgentOSClient:
    def __init__(self, base_url: str, session_id: str = None):
        self.base_url = base_url.rstrip("/")
        self.session_id = session_id
        self.client = httpx.Client(base_url=base_url, timeout=30.0)

    def run(self, agent_id: str, message: str, stream: bool = False) -> dict:
        data = {"message": message, "session_id": self.session_id}
        resp = self.client.post(f"/agents/{agent_id}/runs", data=data)
        return resp.json()
```

## 23.4 Authorization: Don't Let Agents Run Naked

生产环境必须开启授权:

```python
agent_os = AgentOS(
    id="product-agent-os",
    agents=[support_agent],
    db=db,
    authorization=True,   # After enabling, validates requests by security_key or JWT模式
)
```

Two modes after enabling:

- **security_key**: for简单场景, protect the entire instance with a静态密钥 (Bearer token) — configured via the环境变量 `OS_SECURITY_KEY`; clients carry the凭证 in the request header;
- **JWT**: set `JWT_VERIFICATION_KEY` or `JWT_JWKS_FILE`等环境变量 to接入你自己的身份体系; control可调用组件 by user/role.

```python
# No code changes needed: security_key mode is完全由环境变量驱动 (pydantic-settings reads it)
# Before starting the service:
#   export AUTHORIZATION_ENABLED=true    # or pass authorization=True at construction
#   export OS_SECURITY_KEY="your-random-long-key"   # validated as a Bearer token
agent_os = AgentOS(
    id="product-agent-os",
    agents=[support_agent],
    db=db,
    authorization=True,
)
```

After配置, verify with curl: a request without凭证 to a protected endpoint gets 401; adding `-H "Authorization: Bearer $OS_SECURITY_KEY"` returns normally. Note: if both JWT-related variables and `OS_SECURITY_KEY` are set, the runtime warns and以 JWT为准.

::: warning Security Bottom Line
`auth_mode=none` should only appear in本机开发. Any公网可达的 AgentOS instance must开 `authorization=True`, and叠加 HTTPS with rate-limiting at the网关层 — exposing the model endpoint directly等于把你的 API Key and数据敞开给全网.
:::

## 23.5 Runtime Capability Panorama
AgentOS is designed for "按需加能力"; each capability has one开关:

| Need | Configuration |
|---|---|
| Storage/tracking with a default database | `db=...` |
| JWT authorization | `authorization=True` |
| Store执行追踪 | `tracing=True` (expanded in the next chapter) |
| Expose the instance as an MCP Server | `mcp_server=True` |
| Scheduled tasks | `scheduler=True` |
| Plug into an existing FastAPI application | `base_app=existing_app` |

`base_app=` is the key to渐进式迁移: the business routes of an existing FastAPI项目 remain unchanged; only挂 the `/agents/*` etc. prefixes in, avoiding重写整个服务 just to引入 Agno.

## 23.6 Chapter Summary

- AgentOS =官方 runtime; wraps components into a自托管 FastAPI app; `get_app()` + `serve()` two steps to起服务;
- Execution endpoints统一为 `POST /{component}/{id}/runs`; maintain会话线程靠 `session_id`;
- Check `GET /info` (containing `auth_mode`) before calling; this is the标准握手动作 for clients;
- Production must开 `authorization=True`; `tracing`, `mcp_server`, `scheduler`, `base_app` are all单开关 capabilities.
