# Chapter 14 · Session Management: session state and chat history

> Chapter goals: distinguish the two mechanisms of "chat history" and "session state", master the usage of `session_id`, `add_history_to_context`, and `session_state`, and understand how tools read/write state via `RunContext`.

## 14.1 Three Concepts Easily Confused

Multi-turn conversation applications have three "memory" layers. The official docs clarify their boundaries with a table:

| Mechanism | Stores | Scope | Typical use |
|---|---|---|---|
| Chat history | Messages and tool calls from previous runs | `session_id` | Conversation coherence within a single session |
| Session state | Application data managed by code/tools | `session_id` | Shopping carts, to-do lists, counters |
| Memory (user memory) | Refined user facts | `user_id` (cross-session) | Preferences, profiles (Chapter 16) |

One-sentence summary: **history is "what we talked about", state is "where we got to", memory is "who this person is"**. This chapter聚焦 the first two.

## 14.2 session_id and Chat History

`session_id` is the ID card for one conversation thread. Multiple runs with the same `session_id` belong to the same conversation. To let the model "remember the上文", two conditions must同时满足:

1. **Configure a database** —历史消息要落库 (`db=SqliteDb(...)`, detailed in the next chapter);
2. **Enable history injection** — `add_history_to_context=True`.

```python
# chat_history.py —— Multi-turn conversation memory
import os
from agno.agent import Agent
from agno.db.sqlite import SqliteDb
from agno.models.openai import OpenAIChat

agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    db=SqliteDb(db_file="tmp/agent.db"),   # Store session runs
    add_history_to_context=True,           # Inject historical messages each run
    num_history_runs=3,                    # Carry only the最近 3 rounds
    markdown=True,
)

agent.print_response("My name is Gao Xiaoling, I'm preparing for a FastAPI interview", session_id="chat_001")
agent.print_response("What is my name? What am I preparing for?", session_id="chat_001")  # Can answer
agent.print_response("What is my name?", session_id="chat_002")               # Switch session: cannot answer
```

History injection is**costly**: each round塞历史消息 into context, tokens grow with conversation length. The official docs provide three控制阀门:

| Parameter | Description |
|---|---|
| `num_history_runs` | Inject the最近几轮 runs (default 3) |
| `num_history_messages` | Cap by message count (choose one of the above; when both set, `num_history_runs` takes precedence) |
| `max_tool_calls_from_history` | Limit the number of tool-call messages in history |

The on-demand lookup写法 requires only one line of配置,效果立竿见影:

```python
# on_demand_history.py —— Let the model decide when to look back at history
import os
from agno.agent import Agent
from agno.db.sqlite import SqliteDb
from agno.models.openai import OpenAIChat

agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    db=SqliteDb(db_file="tmp/agent.db"),
    read_chat_history=True,   # Model gets the get_chat_history() tool
    # Note: without add_history_to_context=True,普通提问不携带历史
)

agent.print_response("Did we ever agree on a secret code?", session_id="chat_001")
# Model judges need context -> calls get_chat_history() -> answers based on result
```

This模式适用面很讲究: suited for audit/analysis scenarios (most questions do not depend on上文, occasionally need to翻旧账); if every sentence carries指代, straightforwardly开 `add_history_to_context`反而延迟更低 — on-demand lookup costs an extra tool call round.

::: tip Another Cost-Saving Idea
If most questions其实不依赖上文, instead of history injection, use `read_chat_history=True` — this gives the model a `get_chat_history()` tool, letting it **lookup on demand** rather than carrying全量 every round.
:::

## 14.3 Session State: Giving the Agent a "Blackboard"

`session_state` is a dict挂 on the session,初始值由 `Agent(session_state={...})` 提供. Its本质区别 from chat history: **state is read/written by your code (usually tools), not naturally accumulated by the model's messages**.

```python
# session_state_basic.py —— Official shopping list example adapted for third-party models
import os
from agno.agent import Agent
from agno.db.sqlite import SqliteDb
from agno.models.openai import OpenAIChat
from agno.run import RunContext


def add_item(run_context: RunContext, item: str) -> str:
    """Add an item to the shopping list.

    Args:
        item: The item to add to the shopping list.
    """
    # run_context.session_state is the current session's state dict
    if run_context.session_state is None:
        run_context.session_state = {}
    run_context.session_state["shopping_list"].append(item)
    return f"The shopping list is now {run_context.session_state['shopping_list']}"


agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    db=SqliteDb(db_file="tmp/agent.db"),
    session_state={"shopping_list": []},      # Initial state for new sessions
    tools=[add_item],
    # instructions can引用 state via {键名}; template replacement happens at injection
    instructions="Current state (shopping list) is: {shopping_list}",
    markdown=True,
)

agent.print_response("Help me add milk, eggs, and bread to the shopping list", session_id="s_100")
print(f"Final session state: {agent.get_session_state()}")   # Read from code side
```

Three key mechanisms:

1. **`RunContext` injection**: after a tool function declares the `run_context: RunContext` parameter, the framework auto-passes it at execution time, and该参数 does not appear in the schema sent to the model (the伏笔 planted in Chapter 7 pays off here);
2. **Auto-persistence**: modifications to `run_context.session_state` are written to the database with the session; the next run with the same `session_id` auto-loads;
3. **Instructions template**: placeholders like `{shopping_list}` are replaced with the state's actual value at injection, letting the model "see" the current state.

## 14.4 Multi-Session Isolation Experiment

The best way to understand state scope is to亲手做隔离实验:

```python
# state_isolation.py —— Verify state is隔离 per session
import os
from agno.agent import Agent
from agno.db.sqlite import SqliteDb
from agno.models.openai import OpenAIChat
from agno.run import RunContext


def set_counter(run_context: RunContext, value: int) -> str:
    """Set the counter to a value.

    Args:
        value: New counter value.
    """
    run_context.session_state["counter"] = value
    return f"counter = {value}"


agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    db=SqliteDb(db_file="tmp/agent.db"),
    session_state={"counter": 0},
    tools=[set_counter],
    instructions="The current value of counter is: {counter}",
)

agent.print_response("Set the counter to 42", session_id="session_A")
agent.print_response("What is the counter now?", session_id="session_A")  # 42
agent.print_response("What is the counter now?", session_id="session_B")  # 0 (initial value)
```

`session_A` and `session_B`'s states are互不可见 —这正是 "each user / each ticket one session"的隔离基础. Additionally, `session_state` can be临时传入 at `run()` time to override the default (higher priority than Agent construction params); `enable_agentic_state=True` further lets the model自主 update state via JSON patch protocol, suitable for让 Agent自主维护 complex task progress.

## 14.5 Selection: When to Use History vs State

- **Conversation tone,指代消解** ("How much is it?" "Expand on the second pointjust mentioned") → chat history;
- **Business progress** (shopping cart contents, where approval stands, how many retries done) → session state;
- **Cross-session user preferences** ("this user prefers concise replies") → memory (Chapter 16).

A标准组合拳 for a customer-service Agent: memory记客户沟通偏好, history维持当前工单对话连贯, state存工单处理状态. The three各司其职,互不替代.

## 14.6 Chapter Summary

- `session_id`划定一次对话线程; history/state both use it as scope; memory uses `user_id`;
- Chat记忆 = database + `add_history_to_context=True`; token budget controlled by `num_history_runs` / `num_history_messages`, or switch to `read_chat_history=True` for on-demand lookup;
- `session_state` is read/written by code (tools) via `run_context.session_state`; modifications auto-persist; referenced in instructions via `{键}`;
- State is naturally隔离 per session, the基石 for构建多用户/多工单 applications.
