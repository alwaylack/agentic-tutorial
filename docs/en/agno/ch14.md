# Chapter 14 · Session Management: session state and chat history

> Chapter goals: distinguish the "chat history" and "session state" two mechanisms; master the usage of `session_id`, `add_history_to_context`, and `session_state`;理解工具如何通过 `RunContext` 读写状态.

## 14.1 Three容易混淆的 Concepts

Multi-turn对话 applications have three "memory" layers; the official docs use a table to clarify their边界:

| Mechanism | Stores | Scope | Typical Use |
|---|---|---|---|
| Chat history | Previous runs\' messages and tool calls | `session_id` |对话连贯性 within the same session |
| Session state | App data managed by code/tools | `session_id` | Shopping carts, task lists, counters |
| Memory (user) | Refined user facts | `user_id` (cross-session) | Preferences, profiles (Chapter 16) |

One-sentence summary: **history is "what was聊过", state is "where we are in办到哪了", memory is "who this person is"**. This chapter focuses on the前两者.

## 14.2 session_id and Chat History

`session_id` is the身份证 for one对话线程. Multiple runs with the same `session_id` belong to the same对话. To let the model "remember the上文", both conditions must同时满足:

1. **配置数据库** —历史消息 must落库 (`db=SqliteDb(...)`, detailed in the next chapter);
2. **开启历史注入** — `add_history_to_context=True`.

```python
# chat_history.py —— multi-turn对话记忆
import os
from agno.agent import Agent
from agno.db.sqlite import SqliteDb
from agno.models.openai import OpenAIChat

agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    db=SqliteDb(db_file="tmp/agent.db"),   # Store会话 runs
    add_history_to_context=True,           # Inject历史消息 on each run
    num_history_runs=3,                    # Bring only the最近 3 rounds
    markdown=True,
)

agent.print_response("My name is Xiao Gao, I am preparing for a FastAPI interview", session_id="chat_001")
agent.print_response("What is my name? What am I preparing for?", session_id="chat_001")  # Can answer
agent.print_response("What is my name?", session_id="chat_002")               # Change session: cannot answer
```

History injection is**有成本的**: every round塞进上下文; tokens增长随对话长度. The官方 provides three控制阀门:

| Parameter | Description |
|---|---|
| `num_history_runs` | Inject the最近几轮 runs (default 3) |
| `num_history_messages` | Cap by消息条数 (choose one with the above; when both are set, `num_history_runs`生效) |
| `max_tool_calls_from_history` | Limit the数量 of tool call messages in history |

The按需回查写法只需一行配置,效果立竿见影:

```python
# on_demand_history.py —— let the model decide when to回看历史
import os
from agno.agent import Agent
from agno.db.sqlite import SqliteDb
from agno.models.openai import OpenAIChat

agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    db=SqliteDb(db_file="tmp/agent.db"),
    read_chat_history=True,   # The model gets the get_chat_history() tool
    # Note: without add_history_to_context=True,普通提问不携带历史
)

agent.print_response("Did we约定过什么暗号 before?", session_id="chat_001")
# Model判断需要上下文 → calls get_chat_history() → answers based on the result
```

This模式 applies to很讲究的场景: suited for审计, analysis类 scenarios (most questions do not依赖上文; occasionally need to翻旧账); if every sentence带指代,老老实实开 `add_history_to_context` is反而延迟更低 — on-demand回查 costs an extra一轮工具调用.

::: tip Another Cost-Saving思路
If most questions其实不依赖上文, instead of开启历史注入, use `read_chat_history=True` — this gives the model a `get_chat_history()` tool, letting it**按需回查**历史 rather than carrying全量 every round.
:::

## 14.3 Session State: Giving the Agent a "Blackboard"

`session_state` is a dict挂 on the session, with初始值 provided by `Agent(session_state={...})`. Its本质区别 from chat history: **state is read and written by your code (usually tools), not自然累积 by the model\'s messages**.

```python
# session_state_basic.py —— official shopping list example adapted for third-party models
import os
from agno.agent import Agent
from agno.db.sqlite import SqliteDb
from agno.models.openai import OpenAIChat
from agno.run import RunContext


def add_item(run_context: RunContext, item: str) -> str:
    """Add an item to the shopping list.

    Args:
        item: The item to add to the shopping list.
    """
    # run_context.session_state is the current session\'s state dict
    if run_context.session_state is None:
        run_context.session_state = {}
    run_context.session_state["shopping_list"].append(item)
    return f"The shopping list is now {run_context.session_state['shopping_list']}"


agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    db=SqliteDb(db_file="tmp/agent.db"),
    session_state={"shopping_list": []},      # Initial state for new sessions
    tools=[add_item],
    # Instructions can引用状态 via {键名}; template replacement happens at injection
    instructions="Current state (shopping list) is: {shopping_list}",
    markdown=True,
)

agent.print_response("Help me add milk, eggs, and bread to the shopping list", session_id="s_100")
print(f"Final session state: {agent.get_session_state()}")   # Read from the code side
```

Three关键机制:

1. **`RunContext` injection**: after the工具函数声明s `run_context: RunContext`, the框架执行时自动传入; this parameter does not appear in the schema sent to the model (the伏笔 from Chapter 7兑现 here);
2. **Auto-persistence**: modifications to `run_context.session_state` are随会话写入数据库; the next run with the same `session_id`自动加载;
3. **Instructions template**: placeholders like `{shopping_list}` are replaced with the state\'s actual value at injection, letting the model"看得见" the current state.

## 14.4 Multi-Session Isolation Experiment

The best way to理解 state scope is to亲手做隔离实验:

```python
# state_isolation.py —— verify state is isolated by session
import os
from agno.agent import Agent
from agno.db.sqlite import SqliteDb
from agno.models.openai import OpenAIChat
from agno.run import RunContext


def set_counter(run_context: RunContext, value: int) -> str:
    """Set the counter to a value.

    Args:
        value: New counter value.
    """
    run_context.session_state["counter"] = value
    return f"counter = {value}"


agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    db=SqliteDb(db_file="tmp/agent.db"),
    session_state={"counter": 0},
    tools=[set_counter],
    instructions="The current value of counter is: {counter}",
)

agent.print_response("Set the counter to 42", session_id="session_A")
agent.print_response("What is the counter now?", session_id="session_A")  # 42
agent.print_response("What is the counter now?", session_id="session_B")  # 0 (initial value)
```

The states of `session_A` and `session_B`互不可见 — this is the隔离基础 for "one session per用户/每工单". Additionally, `session_state` can be临时传入 in `run()` to覆盖默认值 (higher priority than the Agent constructor参数); `enable_agentic_state=True` further lets the model更新状态 itself via the JSON补丁协议, suited for让 Agent自主维护复杂任务进度.

## 14.5 Selection: When to Use History vs. State

- **对话语气,指代消解** ("How much is it?" "Expand on the second point mentioned earlier") → chat history;
- **业务进度** (shopping cart contents, approval status, retry counts) → session state;
- **Cross-session user preferences** ("This user prefers concise replies") → memory (Chapter 16).

A standard客服 Agent组合拳: memory records客户沟通偏好; history maintains当前工单对话连贯; state stores工单处理状态. Each plays its role,互不替代.

## 14.6 Chapter Summary

- `session_id`划定了对话线程; history/state both scoped by it; memory scoped by `user_id`;
- Chat记忆 = database + `add_history_to_context=True`; token预算用 `num_history_runs` / `num_history_messages`控制; or switch to `read_chat_history=True` for on-demand回查;
- `session_state` is read/written by code (tools) via `run_context.session_state`; modifications自动落库; instructions引用状态 via `{键}`;
- State is天然按 session隔离; the基石 for building多用户/多工单 applications.
