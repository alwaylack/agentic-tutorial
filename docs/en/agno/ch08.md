## 8.1 Plain Functions: The Lightest Custom Tool

We have already used plain functions as tools in the previous chapter; here we补全工程细节. Function tools支持同步 with异步两种定义:

```python
# custom_func.py —— both sync and async functions可作为工具
import asyncio
import os
import sqlite3
from agno.agent import Agent
from agno.models.openai import OpenAIChat


def get_user(user_id: int) -> dict:
    """Get a user\'s name and email by user id.

    Args:
        user_id: The numeric id of the user.
    """
    # In a real project this would通常查数据库 or call an internal API
    return {"id": user_id, "name": "Student Gao", "email": "gao@example.com"}


async def query_report(report_date: str) -> str:
    """Fetch the daily report content for a given date.

    Args:
        report_date: Date string in YYYY-MM-DD format.
    """
    await asyncio.sleep(0.1)  # Simulate IO
    return f"Daily report for {report_date}: 1024 new users today."


agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    tools=[get_user, query_report],  # Sync and async can be混搭
)

agent.print_response("Look up user 42\'s email, then give me the key points of the 2026-01-10 daily report")
```

::: tip Return Value Convention
Tools can return strings, numbers, dicts, lists, etc. Returning **structured data** (dict/list) is通常 better than concatenating long text — the model extracts所需字段更准确. If you need to返回媒体文件 alongside text, use `ToolResult`.
:::

## 8.2 @tool Decorator: Adding Behavior Control to Functions

The `agno.tools.tool` decorator (new in v2, continued in 3.x) can附加执行策略 to a tool without改变函数体. The following parameters have been verified in the agno 3.x source:

| Parameter | Default | Description |
|---|---|---|
| `name` / `description` | None | Override the tool name/description visible to the model |
| `show_result` | False | Display the result to the user directly after execution |
| `stop_after_tool_call` | False | Terminate the current run after executing this tool |
| `cache_results` / `cache_dir` / `cache_ttl` | False | Result caching with directory and TTL (seconds) |
| `requires_confirmation` | False | Requires human confirmation before execution (expanded in Ch. 21) |
| `pre_hook` / `post_hook` / `tool_hooks` | None | Hooks before/after tool execution |

```python
# tool_decorator.py —— control tool behavior with @tool
import os
import time
from agno.agent import Agent
from agno.models.openai import OpenAIChat
from agno.tools import tool


@tool(cache_results=True, cache_ttl=300)   # Same inputs走缓存 within 5 minutes
def slow_exchange_rate(base: str, quote: str) -> str:
    """Get the current exchange rate from base currency to quote currency.

    Args:
        base: The base currency code, e.g. USD.
        quote: The quote currency code, e.g. CNY.
    """
    time.sleep(2)  # Simulate an expensive third-party API call
    return f"1 {base} = 7.23 {quote}"


@tool(stop_after_tool_call=True, show_result=True)
def submit_ticket(title: str) -> str:
    """Create a support ticket and finish the conversation.

    Args:
        title: Short summary of the issue.
    """
    return f"Ticket #{8848} created: {title}"


agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    tools=[slow_exchange_rate, submit_ticket],
)

agent.print_response("What is the current USD to CNY exchange rate?")
agent.print_response("Submit a ticket for me: laptop cannot connect to WiFi")
```

The semantics of two parameters deserve close咀嚼:

- **`stop_after_tool_call`**: suits "终态动作". After submitting a ticket there is no need to let the model总结 another round; end the run直接, saving one model call;
- **`show_result`**: suits "结果即答案" for deterministic outputs (calculators, queries), bypassing the model\'s复述环节.

## 8.3 Toolkit Subclass: Batch-Register a Group of Related Tools

When a业务域 has multiple operations and需要共享状态 (e.g., a unified client, auth config), it is time to写 a Toolkit. The写法 is inheriting `agno.tools.Toolkit` and implementing `__init__`:

```python
# todo_toolkit.py —— custom todo list Toolkit
import os
from agno.agent import Agent
from agno.models.openai import OpenAIChat
from agno.tools import Toolkit


class TodoTools(Toolkit):
    def __init__(self, **kwargs):
        super().__init__(name="todo_tools", **kwargs)
        self._todos: list[str] = []          # Shared state within the toolkit

        self.register(self.add_todo)
        self.register(self.list_todos)
        self.register(self.remove_todo)

    def add_todo(self, task: str) -> str:
        """Add a task to the todo list.

        Args:
            task: The task description to add.
        """
        self._todos.append(task)
        return f"Added: {task}"

    def list_todos(self) -> str:
        """List all tasks in the todo list."""
        if not self._todos:
            return "List is empty"
        return "\n".join(f"{i + 1}. {t}" for i, t in enumerate(self._todos))

    def remove_todo(self, index: int) -> str:
        """Remove a task by its 1-based index.

        Args:
            index: The 1-based position of the task to remove.
        """
        removed = self._todos.pop(index - 1)
        return f"Removed: {removed}"


agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    tools=[TodoTools()],
    instructions="Manage the user\'s todo list; show the full list after each增删查.",
)

agent.print_response("Add three things: buy milk, write weekly report, run for half an hour")
agent.print_response("Delete the 2nd item")
```

The Toolkit constructor also批量声明控制策略 by name (also from `Toolkit.__init__` parameters, verified in agno 3.x source): `stop_after_tool_call_tools=["submit_order"]`, `show_result_tools=[...]`, `requires_confirmation_tools=[...]`, and package-level `cache_results=True`. This is equivalent to the decorator effects in 8.2,只是作用在 Toolkit维度.

## 8.4 Exception Handling Within Tools

Tools access the外部世界; failures are常态. Agno捕获工具抛出的异常 and回传错误信息 to the model, letting the model decide whether to重试 or switch paths; you can also做统一兜底 via `tool_hooks`:

```python
# safe_tools.py —— exception handling example
import os
from agno.agent import Agent
from agno.models.openai import OpenAIChat
from agno.tools import tool


def retry_on_error(func_name: str, func, *args, **kwargs):
    """post_hook style fallback: log and transform the exception."""
    try:
        return func(*args, **kwargs)
    except Exception as e:
        # Error信息写给模型应当"可行动": tell it what it can do next
        return f"Call failed ({type(e).__name__}): {e}. Please检查参数后重试一次。"


@tool(post_hook=retry_on_error)
def divide(a: float, b: float) -> float:
    """Divide a by b.

    Args:
        a: Numerator.
        b: Denominator, must not be zero.
    """
    return a / b   # ZeroDivisionError on b=0 is caught by the hook


agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    tools=[divide],
)

agent.print_response("Calculate 10 divided by 0")
```

>经验法则: error messages for "人" and for "模型" should be分开设计. Errors to the model should clearly state**下一步能做什么** ("please check parameters", "no data for this city, please try another"), not堆一段堆栈.

## 8.5 Granularity Principles for Tool Design

The two extremes beginners最容易犯:

- ❌ **Too fine-grained**: `get_id`, `get_name`, `get_email` as three tools; the model must call multiple times to拼装;
- ❌ **Too coarse**: one `manage_company(query: str)`万能接口; vague schema导致模型乱传参.

The推荐做法 is **面向任务建模**: one tool完成一件模型视角下完整的事; parameters kept少而明确. Compare:

```python
# granularity.py —— task-oriented vs database-oriented
def get_weather_bad(city: str, field: str) -> str:
    """Get one field of weather. BAD: model must先猜 field取值."""


def get_weather_good(city: str) -> dict:
    """Get current weather summary (temperature, condition, humidity) for a city.

    Args:
        city: City name in Chinese or English.
    """
    # Return all structured fields at once; the model picks what it needs
    return {"city": city, "temperature": 26, "condition": "cloudy", "humidity": 62}
```

Additionally, two生产守则:

1. **Separate idempotent reads from side effects**: read-only tools can be called freely; tools with副作用 (ordering, emailing) must配 `requires_confirmation=True` or限流;
2. **Solve超时与重试 within the tool itself**: do not expect the model to handle network抖动.

## 8.6 Chapter Summary

- Three customization approaches: plain function (lightest), `@tool` decorator (附加执行策略), `Toolkit` subclass (共享状态 + 批量注册);
- `@tool` core parameters: `cache_results` caching, `stop_after_tool_call` terminate run, `show_result` direct output, `requires_confirmation` human confirmation;
- Toolkits can批量声明策略 by name with `*_tools` list parameters;
- Tool exceptions are捕获 by Agno and回传 to the model; error文案 should be written as "actionable" guidance;
- Tools designed at the任务粒度: one call solves one完整问题;返回结构化数据.
