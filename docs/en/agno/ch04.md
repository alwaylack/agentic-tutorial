# Chapter 4 · Streaming Output and Real-time Responses

> Chapter goals: understand the value and principle of streaming, master both synchronous and asynchronous streaming writing patterns and event types, and learn to obtain final metrics during streaming.

## 4.1 Why Streaming Is Needed

Non-streaming requests require waiting for the model to finish generating all content before returning. Long answers can take tens of seconds, and users facing a blank page are prone to churn. Streaming lets the server **push as it generates**: users see the first character almost immediately, changing the overall experience from "waiting for an elevator" to "watching a live broadcast."

Technically, streaming is based on HTTP chunked transfer: the model provider pushes generated tokens segment by segment to Agno, and Agno wraps them into event objects for you to iterate.

## 4.2 Synchronous Streaming: The Basic Typewriter Effect

Add `stream=True` to `run()`, and the return value changes from `RunOutput` to an **event iterator**:

```python
# stream_basic.py —— Terminal typewriter effect
import os
from dotenv import load_dotenv
from agno.agent import Agent
from agno.models.openai import OpenAIChat

load_dotenv()
agent = Agent(model=OpenAIChat(
    id="deepseek-chat",
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    base_url="https://api.deepseek.com/v1",
))

# When stream=True, returns RunOutputEvent iterator instead of RunOutput
stream = agent.run("Write 200 words of Python learning advice", stream=True)

for chunk in stream:
    # By default, only RunContent events flow out (model text fragments)
    print(chunk.content, end="", flush=True)
print()  # Newline at end
```

`end=""` + `flush=True` is the fixed combination for the typewriter effect: no newline, immediately flush the buffer. Note that you **cannot** access `.content` to get the full text at this point — each chunk contains only a fragment; you need to concatenate them yourself.

## 4.3 Event Types: Not Just Text Flow

By default, only model text flows (`RunContent` events). Open `stream_events=True`, and all events including tool calls, reasoning steps, memory updates will flow out — this is a powerful tool for building real-time UIs and debugging:

```python
# stream_events.py —— Observe complete event stream
from agno.agent import Agent, RunEvent
from agno.models.openai import OpenAIChat
from agno.tools.duckduckgo import DuckDuckGoTools
import os
from dotenv import load_dotenv

load_dotenv()
agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    tools=[DuckDuckGoTools()],
)

stream = agent.run("What framework is Agno?", stream=True, stream_events=True)

for chunk in stream:
    if chunk.event == RunEvent.run_content:
        print(chunk.content or "", end="", flush=True)      # Text fragment
    elif chunk.event == RunEvent.tool_call_started:
        print(f"\n[Starting tool call: {chunk.tool.tool_name}]")   # Tool start
    elif chunk.event == RunEvent.tool_call_completed:
        print("[Tool call completed]")
print()
```

Official event type quick reference (common ones):

| Category | Event | Description |
|---|---|---|
| Core | `run_started` / `run_content` / `run_completed` / `run_error` | Run lifecycle |
| Tool | `tool_call_started` / `tool_call_completed` / `tool_call_error` | Tool call three phases |
| Reasoning | `reasoning_started` / `reasoning_step` / `reasoning_completed` | Thinking process |
| Memory | `memory_update_started` / `memory_update_completed` | Memory write |

::: warning Common Pitfall
The `content` of `run_content` events may be `None` for certain fragments (e.g., between tool calls); perform null-check before printing, otherwise "None" will the interface.
:::

## 4.4 Asynchronous Streaming

In asynchronous frameworks (FastAPI, WebSocket services), use `arun(stream=True)` with `async for`:

```python
# stream_async.py —— Asynchronous streaming consumption
import asyncio
import os
from dotenv import load_dotenv
from agno.agent import Agent
from agno.models.openai import OpenAIChat

load_dotenv()
agent = Agent(model=OpenAIChat(
    id="deepseek-chat",
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    base_url="https://api.deepseek.com/v1",
))

async def main():
    # arun + stream=True returns async iterator
    stream = agent.arun("Summarize microservice pros and cons in three points", stream=True)
    async for chunk in stream:
        print(chunk.content or "", end="", flush=True)

asyncio.run(main())
```

In FastAPI, push fragments received in `async for` to the frontend via `StreamingResponse` or WebSocket, achieving a web-based typewriter — this is the capstone preview for Chapter 22 (combined with FastAPI).

## 4.5 Getting Metrics After Streaming Ends

You cannot get complete `metrics` during streaming, but the **last event after streaming ends** (or the `RunCompleted` event when `stream_events=True` is open) carries summary information:

```python
# stream_metrics.py —— Streaming + final metrics
from agno.agent import Agent, RunEvent
from agno.models.openai import OpenAIChat
import os
from dotenv import load_dotenv

load_dotenv()
agent = Agent(model=OpenAIChat(
    id="deepseek-chat",
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    base_url="https://api.deepseek.com/v1",
))

full_text = ""
stream = agent.run("Explain idempotency", stream=True, stream_events=True)

for chunk in stream:
    if chunk.event == RunEvent.run_content:
        full_text += chunk.content or ""
    elif chunk.event == RunEvent.run_completed:
        # RunCompleted event carries complete run results and metrics
        m = chunk.metrics
        print("\n--- This run's metrics ---")
        print("Input tokens:", m.input_tokens, "Output tokens:", m.output_tokens)

print("Full text length:", len(full_text))
```

Pattern summary: **concatenate text from `run_content`, read summary from `run_completed`**. This pattern is standard for billing and log instrumentation scenarios.

## 4.6 Chapter Summary

- Streaming changes "wait for all generation" to "watch as it generates," significantly improving long-answer experience;
- After `stream=True`, returns an event iterator: use `for` for synchronous, `async for` for asynchronous;
- By default only text flows; `stream_events=True` is needed to see all events including tools/reasoning/memory;
- `run_content`'s content may be `None`; null-check is mandatory before printing;
- Metrics are read from the `run_completed` event — text concatenation and metric collection are.
