# Chapter 4 · Streaming output与Real-time response

> Chapter goals：Understandstreaming的价值与原理，Mastersynchronous/asynchronous两种streaming写法与event types，学会在streaming过程中拿到最终metrics。

## 4.1 为什么需要streaming

非streaming请求要等模型生成完全部内容才返回，长回答动辄几十秒，用户面对空白页面极易流失。streaming（Streaming）让服务端**push as generating**：用户几乎立刻看到第一个字，整体体验从"等电梯"变成"看直播"。

技术上，streaming基于 HTTP chunked transfer：模型服务商把生成的 token 逐段push to Agno，Agno 再把它们wrap成事件对象交给你iterate。

## 4.2 synchronousstreaming：最基础的typewriter effect

给 `run()` 加上 `stream=True`，返回值就从 `RunOutput` 变成了**事件iterate器**：

```python
# stream_basic.py —— 终端typewriter effect
import os
from dotenv import load_dotenv
from agno.agent import Agent
from agno.models.openai import OpenAIChat

load_dotenv()
agent = Agent(model=OpenAIChat(
    id="deepseek-chat",
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    base_url="https://api.deepseek.com/v1",
))

# stream=True 时返回 RunOutputEvent iterate器而非 RunOutput
stream = agent.run("写一段 200 字的 Python 学习建议", stream=True)

for chunk in stream:
    # default只流出 RunContent 事件（模型content chunks）
    print(chunk.content, end="", flush=True)
print()  # 结束换行
```

`end=""` + `flush=True` 是typewriter effect的固定搭配：不换行、立刻刷新缓冲区。注意此时**不能**再访问 `.content` 拿full text——每个 chunk 只含一个片段，需要自己concatenate。

## 4.3 event types：不只流出content

default只推送模型文本（`RunContent` 事件）。enable `stream_events=True` 后，tool calls、reasoning steps、memory updates等所有事件都会流出，这是构建real-time UI 和调试的powerful tool：

```python
# stream_events.py —— 观察完整事件流
from agno.agent import Agent, RunEvent
from agno.models.openai import OpenAIChat
from agno.tools.duckduckgo import DuckDuckGoTools
import os
from dotenv import load_dotenv

load_dotenv()
agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    tools=[DuckDuckGoTools()],
)

stream = agent.run("Agno 是什么框架？", stream=True, stream_events=True)

for chunk in stream:
    if chunk.event == RunEvent.run_content:
        print(chunk.content or "", end="", flush=True)      # content chunks
    elif chunk.event == RunEvent.tool_call_started:
        print(f"\n[开始调用工具: {chunk.tool.tool_name}]")   # 工具开始
    elif chunk.event == RunEvent.tool_call_completed:
        print("[tool calls完成]")
print()
```

官方event types速查（常用部分）：

| 类别 | 事件 | 说明 |
|---|---|---|
| 核心 | `run_started` / `run_content` / `run_completed` / `run_error` | 运行lifecycle |
| 工具 | `tool_call_started` / `tool_call_completed` / `tool_call_error` | tool callsthree stages |
| 推理 | `reasoning_started` / `reasoning_step` / `reasoning_completed` | thinking process |
| 记忆 | `memory_update_started` / `memory_update_completed` | 记忆write |

::: warning 常见坑
`run_content` 事件的 `content` 在某些片段（如tool calls间隙）可能为 `None`，打印前务必做null protection，否则会打出 "None" 字样pollute the interface。
:::

## 4.4 asynchronousstreaming

asynchronous框架（FastAPI、WebSocket 服务）中要用 `arun(stream=True)`，配合 `async for` consume：

```python
# stream_async.py —— asynchronousstreamingconsume
import asyncio
import os
from dotenv import load_dotenv
from agno.agent import Agent
from agno.models.openai import OpenAIChat

load_dotenv()
agent = Agent(model=OpenAIChat(
    id="deepseek-chat",
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    base_url="https://api.deepseek.com/v1",
))

async def main():
    # arun + stream=True 返回asynchronousiterate器
    stream = agent.arun("用三点总结微服务优缺点", stream=True)
    async for chunk in stream:
        print(chunk.content or "", end="", flush=True)

asyncio.run(main())
```

在 FastAPI 中，把 `async for` 里收到的片段通过 `StreamingResponse` 或 WebSocket push to前端，就Implement了web version打字机——这是第 22 章（结合 FastAPI）的实战preview。

## 4.5 streaming结束后拿metrics

streaming过程中拿不到完整 `metrics`，但**流结束后**最后一个事件（或 `RunCompleted` 事件，开启 `stream_events=True` 时）会携带summary信息：

```python
# stream_metrics.py —— streaming + 最终metrics
from agno.agent import Agent, RunEvent
from agno.models.openai import OpenAIChat
import os
from dotenv import load_dotenv

load_dotenv()
agent = Agent(model=OpenAIChat(
    id="deepseek-chat",
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    base_url="https://api.deepseek.com/v1",
))

full_text = ""
stream = agent.run("解释什么是幂等", stream=True, stream_events=True)

for chunk in stream:
    if chunk.event == RunEvent.run_content:
        full_text += chunk.content or ""
    elif chunk.event == RunEvent.run_completed:
        # RunCompleted 事件上带有完整的运行结果与metrics
        m = chunk.metrics
        print("\n--- 本次运行metrics ---")
        print("输入 tokens:", m.input_tokens, "输出 tokens:", m.output_tokens)

print("full text长度:", len(full_text))
```

模式总结：**content从 `run_content` concatenate，summary从 `run_completed` 读取**。这个模式在计费、日志instrumentation场景是standard practice。

## 4.6 本章小结

- streaming把"等全部生成"变成"边生成边看"，显著改善长回答体验；
- `stream=True` 后返回事件iterate器：synchronous用 `for`，asynchronous用 `async for`；
- default只流content；`stream_events=True` 才能看到工具/推理/记忆等all events；
- `run_content` 的 content 可能为 `None`，打印必须做null protection；
- metrics在 `run_completed` 事件上读取——contentconcatenate与metrics采集分离。
