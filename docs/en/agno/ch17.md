# Chapter 17 · Knowledge and RAG Introduction

> Chapter goals: understand the complete RAG pipeline; learn to use Agno\'s `Knowledge` to load documents;配置本地向量库 LanceDB and third-party Embedding services;挂 the knowledge base to an Agent to实现可溯源的问答.

## 17.1 RAG Principles at a Glance

Large models only know知识 they saw during训练; they know nothing about企业内部文档 or最新资料, and may even编造 confidently (幻觉). **RAG (Retrieval-Augmented Generation)**的思路 is: first检索 relevant snippets from your own资料库, then塞进提示词 let the model "answer based on them".

The complete pipeline分两个阶段:

1. **写入阶段 (Indexing)**: document → chunking → embedding → store in向量数据库;
2. **查询阶段 (Retrieval)**: user question vectorized → find最相似的若干片段 in the向量库 → concatenate into the prompt →模型生成带依据的回答.

::: tip Three Roles
- **Embedder**: transforms文本 into vectors (a string of floats); semantically相近的文本向量距离更近;
- **Vector DB**: stores vectors and supports "nearest-neighbor retrieval"; Agno supports LanceDB, PgVector, Chroma etc.;
- **Knowledge**: Agno\'s封装 for the entire pipeline above; responsible for reading, chunking,入库, retrieval.
:::

## 17.2 Building a Knowledge Base with Knowledge

`Knowledge` is Agno\'s核心类 for knowledge capabilities (统一后的 API continued in 3.x). Specify the向量库 and Embedder at creation; then灌入内容 via `insert()` — it supports本地路径, URLs,纯文本 etc., and自动识别 PDF, DOCX, CSV, Markdown等格式选择合适的 Reader:

```python
# knowledge_basic.py
import os
from agno.knowledge.knowledge import Knowledge
from agno.knowledge.embedder.openai import OpenAIEmbedder
from agno.vectordb.lancedb import LanceDb, SearchType

# Local向量库 LanceDB: no separate service deployment needed; data lands in a local directory
knowledge = Knowledge(
    vector_db=LanceDb(
        table_name="company_docs",          # Vector table name
        uri="tmp/lancedb",                  # Data storage directory
        search_type=SearchType.vector,      # Vector retrieval (hybrid检索 discussed in后续章节)
        embedder=OpenAIEmbedder(            # Third-party OpenAI-compatible embedding service
            id="Qwen/Qwen3-Embedding-8B",   # Use the model id actually provided by your platform
            api_key=os.getenv("EMBEDDING_API_KEY"),
            base_url="https://api.siliconflow.cn/v1",
        ),
    )
)

# Insert content: supports url / path / directory / pure text
knowledge.insert(
    url="https://agno-public.s3.amazonaws.com/recipes/ThaiRecipes.pdf",
    skip_if_exists=True,     # Skip已入库的内容 to avoid重复索引
)
knowledge.insert(text_content="Company annual leave policy: after one year of service, enjoy 5 days of paid leave...")
```

Dependency installation:

```bash
pip install "agno[lancedb]" pypdf   # lancedb and PDF reading support
```

::: warning Note
`insert()`真实调用 Embedding API and产生费用与耗时;务必带上 `skip_if_exists=True` in开发阶段; otherwise每次运行都会重复入库.
:::

## 17.3 Attaching the Knowledge Base to an Agent

Only pass the `knowledge=` parameter to `Agent`. At this point Agno自动给模型注册一个 `search_knowledge_base` tool; the模型自己决定何时检索 — this is the Agentic RAG展开 in the next chapter:

```python
# rag_agent.py
from agno.agent import Agent
from agno.models.openai import OpenAIChat

agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    knowledge=knowledge,
    search_knowledge=True,   # Enabled by default when knowledge is provided; explicit is clearer
    instructions=[
        "Search the知识 base before answering.",
        "注明引用了哪些来源 at the end of the answer.",
        "For内容 not in the knowledge base,明确说不知道; do not编造.",
    ],
    markdown=True,
)

agent.print_response("How to make Thai coconut chicken soup?")
```

After运行观察日志, you will see the模型 first发起一次工具调用 (retrieval); only after拿到相关片段 does it生成最终答案.

## 17.4 Direct Retrieval and Result Traceability

Sometimes you need绕过模型 directly测试检索质量 — use `knowledge.search()`;每条结果都带有内容和元数据:

```python
results = knowledge.search(query="How many days of annual leave?")
for r in results:
    print("Relevance:", getattr(r, "score", None))
    print("Content:", r.content[:100])
    print("Metadata:", r.meta_data)       # Contains来源文件名 etc.;可用于溯源
```

To let the检索到的参考内容自动注入用户提示词 (traditional RAG模式) rather than leaving the decision to the模型, enable `add_knowledge_to_context=True`; the取舍 between the two modes见下一章.

```python
# Traditional RAG: fixed retrieval before each question;参考内容自动拼进用户消息
traditional_rag_agent = Agent(
    model=model,
    knowledge=knowledge,
    add_knowledge_to_context=True,   # Retrieval results自动加入上下文
)
traditional_rag_agent.print_response("What is the company annual leave policy?")
```

## 17.5 Common Pitfalls

- **Embedding and提问不在同一"语义空间"**: the入库 and检索 must use the same Embedder configuration; switching models requires重建整个向量表;
- **Poor Chinese retrieval效果**: mostly the Embedding model不支持中文;选多语种模型 (e.g., Qwen/BGE series);
- **Forgetting持久化目录**: `uri` pointing to a临时目录 causes每次重启都要重新入库;
- **Chunks too大**: stuffing too much unrelated content into one chunk稀释相似度; Chunking strategies are详细讲 in Chapter 18.

## 17.6 Chapter Summary

- RAG = two stages:写入 (chunking→embedding→入库) + 查询 (retrieval→concat prompt→generate);
- `Knowledge(vector_db=LanceDb(...), embedder=OpenAIEmbedder(...))` is the标准组合; LanceDB is免部署 and suited for本地开发;
- `Agent(knowledge=..., search_knowledge=True)` lets the模型自主检索 via tools;
- `knowledge.search()` can脱离模型 directly验证检索质量;
- 入库 and检索 must use同一套 Embedding configuration.
