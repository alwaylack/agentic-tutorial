> Chapter goals: master the分工 and优先级 of `description`, `instructions`, and `system_message` three layers in Agno; learn to写 stable, maintainable Agent prompts.

## 6.1 Agno\'s Three-Layer Prompt System

Agno does not let you手写 a huge system prompt; instead it拆分 into structured config items. Following the official Context Engineering model:

| Config Item | Layer | Purpose |
|---|---|---|
| `description` | Top | What the Agent is, overall responsibilities —相当于"岗位说明书" |
| `instructions` | Middle | A list of specific behavior rules —相当于"操作手册" |
| `system_message` | Override | Fully custom system message; once set它取代 the auto-assembly of the前两者 |

```python
# prompt_layers.py —— usage of the three-layer system
import os
from dotenv import load_dotenv
from agno.agent import Agent
from agno.models.openai import OpenAIChat

load_dotenv()
model = OpenAIChat(
    id="deepseek-chat",
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    base_url="https://api.deepseek.com/v1",
)

agent = Agent(
    model=model,
    # Job description: one sentence clarifying role and边界
    description="You are a rigorous Python technical interviewer.",
    # Operations manual: list behavior rules item by item; Agno numbers them and injects into the system message
    instructions=[
        "Ask only one question at a time; wait for the candidate to answer before probing further",
        "Follow-up questions should target weak points in the previous answer",
        "Use Chinese throughout; code examples may use English identifiers",
        "Do not give the answer all at once; guide the candidate to think first",
    ],
    markdown=True,
)

agent.print_response("Start the interview with me")
```

**Why use a list instead of one long paragraph?** A list makes each rule独立成行; the model\'s adherence rate to "itemized指令" is significantly higher than for长段落;同时便于代码评审 and 版本 diff — this is the key to treating prompts as "config"而非"文案".

## 6.2 instructions Support Template Variables

instructions can contain placeholders, filled at runtime配合会话状态,实现"一套提示词服务多种用户":

```python
# prompt_template.py —— template variable injection
agent = Agent(
    model=model,
    db=None,
    instructions=[
        "The user\'s current membership level is {plan}; adjust tone accordingly",
        "When recommending plans to free users,必须说明付费功能限制",
    ],
    session_state={"plan": "pro"},     # Values in session state fill into {plan}
)

# The same Agent serves不同等级 users with a different session_state
agent.print_response("What features are available?", session_state={"plan": "free"})
```

This approach decouples "business data" from the prompt text: changing membership rules only touches `session_state`, not the prompt.

## 6.3 When to Use system_message

`description + instructions` suffices for most场景. Only use `system_message` when you need **完全控制 system message原文** — note it bypasses the auto-assembly:

```python
# system_message_demo.py —— fully overriding system message
agent = Agent(
    model=model,
    description="This field is ignored",           # ⚠️ Ineffective after setting system_message
    instructions=["Neither will this"],
    system_message="You are Pirate Translator, translating user input into pirate-style English.",
)
```

::: warning Recommendation
Unless migrating a legacy system or integrating with a强约束 third-party prompt spec, **do not use `system_message`**. Abandoning structured分层 means放弃 Agno\'s精细上下文管理能力.
:::

## 6.4 Few-Shot Example Injection

To make output formats极其稳定, the most effective means is to give examples in the指令 (few-shot). Combined with Chapter 5\'s structured output, the format is保证 by the schema; while **风格和判断标准** rely on examples:

```python
# few_shot.py —— anchor classification standards with examples
from pydantic import BaseModel, Field
from typing import Literal

class TicketCategory(BaseModel):
    category: Literal["bug", "feature", "question", "complaint"]
    urgency: int = Field(ge=1, le=5, description="Urgency level")

support_router = Agent(
    model=model,
    description="Customer service ticket classifier.",
    instructions=[
        "Output category and urgency (1-5) based on ticket content",
        "Judgment standard examples:",
        "- 'The login button does not respond when clicked' → bug, urgency=3",
        '- "Hope dark mode is added" → feature, urgency=2',
        '- "Will data leak?" → question, urgency=1',
        '- "If not resolved I will complain to the consumer association!" → complaint, urgency=5',
    ],
    output_schema=TicketCategory,
)

cases = ["The app crashed and cannot be opened at all", "Can you make a WeChat mini-program version?"]
for c in cases:
    r = support_router.run(c)
    print(c, "->", r.content.category, r.content.urgency)
```

The value of examples lies in **消除标准的歧义**: is "闪退" a bug or a complaint? With对照样例, the model\'s choice becomes much more稳定.

## 6.5 Practical Tips for Chinese Prompts

The tutorial统一使用中文模型与中文场景; several empirically有效的经验:

1. **指令语言与业务语言一致**: when having DeepSeek handle Chinese tasks,写 the指令 also in Chinese for更准术语理解;
2. **Avoid long negative sentences**: "不要使用复杂句式" is不如直接写"每句不超过 25 字";
3. **Control the number of rules to within 10**: beyond that中间条款容易被忽略; better to split into多个专职 Agents;
4. **Place critical format requirements at the beginning and end**: adherence rate for the first and last items is最高; put硬性格式约束 at these two positions;
5. **Use `additional_guidance` to supplement临时规则** (when动态追加行为要求 is needed); keep the主 instructions稳定 for easier效果对比.

## 6.6 Iteration Method: Test Prompts Like Code

The正确姿势 for prompt engineering is not "change凭感觉", but建立小评测集回归验证:

```python
# prompt_eval.py —— simplest prompt regression test
EVAL_CASES = [
    ("登录页面白屏", "bug"),
    ("希望支持导出 Excel", "feature"),
    ("怎么修改绑定的手机号", "question"),
]

def evaluate(agent) -> float:
    hits = sum(
        agent.run(q).content.category == expect
        for q, expect in EVAL_CASES
    )
    return hits / len(EVAL_CASES)

print(f"Accuracy: {evaluate(support_router):.0%}")
# Run once before and after modifying instructions; use the number to decide whether to采纳 the new version
```

Extending this思路 to dozens of cases and integrating into CI for periodic runs is the雏形 of the evaluation system (Evals) in Chapter 25.

## 6.7 Chapter Summary

- `description` defines角色; `instructions` defines规则; `system_message`全覆盖 (use with caution);
- instructions用条目列表 + template variables `{placeholder}`; this is maintainable "config"而非文案;
- Few-shot examples消除判断标准的歧义; best效果 with output_schema;
- Chinese prompts:指令与业务同语言, fewer negative sentences, rules ≤10, hard constraints at首尾;
- Prompt changes must be验证 with an eval set;拒绝凭感觉上线.
