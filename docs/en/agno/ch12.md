## 12.1 Parallel: Concurrent Execution of Independent Steps

Steps within a `Parallel` block执行 concurrently; outputs are **aggregated in configured order** and passed to the next step:

```python
import os
from agno.agent import Agent
from agno.models.openai import OpenAIChat
from agno.workflow import Parallel, Step, StepInput, StepOutput, Workflow

model = OpenAIChat(
    id="deepseek-chat",
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    base_url="https://api.deepseek.com/v1",
)

hackernews_researcher = Agent(name="HN Researcher", role="Find tech trends from HackerNews", model=model)
web_researcher = Agent(name="Web Researcher", role="Search web pages and official docs", model=model)
paper_researcher = Agent(name="Paper Researcher", role="Retrieve academic paper viewpoints", model=model)

workflow = Workflow(
    name="parallel-research",
    steps=[
        Parallel(
            Step(name="hn", executor=hackernews_researcher),
            Step(name="web", executor=web_researcher),
            Step(name="papers", executor=paper_researcher),
            name="research",
        ),
        Step(name="synthesis", executor=writer),  # Receives the three-path aggregated output
    ],
)
```

The three research directions are independent; concurrent execution压缩es total time to the slowest path. Note: if parallel function steps need to写 session state, each branch应写**different keys** to avoid races.

## 12.2 Condition: Conditional Branching

`Condition` uses an evaluator function to决定 which path to take, supporting `else_steps` for the反向 branch:

```python
from agno.workflow import Condition, Step, StepInput, StepOutput, Workflow


def is_technical_issue(step_input: StepInput) -> bool:
    text = str(step_input.input or "").lower()
    return any(kw in text for kw in ["error", "bug", "crash", "timeout"])


def diagnose(step_input: StepInput) -> StepOutput:
    return StepOutput(content=f"Technical diagnosis: {step_input.input}")


def general_support(step_input: StepInput) -> StepOutput:
    return StepOutput(content=f"General support reply: {step_input.input}")


workflow = Workflow(
    name="support-router",
    steps=[
        Condition(
            name="triage",
            evaluator=is_technical_issue,
            steps=[Step(name="diagnose", executor=diagnose)],          # True branch
            else_steps=[Step(name="general", executor=general_support)],  # False branch
        ),
        Step(name="follow_up", executor=log_and_reply),
    ],
)
```

The evaluator can be a sync/async Python function, a boolean value, or a CEL expression string. Compared to Team's "the model decides who to派", the branching logic here is **code you wrote** — testable, reproducible.

## 12.3 Loop: Iterate Until Qualified

`Loop`重复执行内部步骤 until `end_condition` returns True or `max_iterations` (default 3) is reached:

```python
from agno.workflow import Loop, Step, StepInput, StepOutput, Workflow


def draft_section(step_input: StepInput) -> StepOutput:
    prev = step_input.previous_step_content or str(step_input.input)
    return StepOutput(content=f"{prev}\n[Add a more specific argument]")


def quality_check(outputs: list[StepOutput]) -> bool:
    """Qualified when any iteration output exceeds 120 characters"""
    return any(len(str(o.content or "")) > 120 for o in outputs)


def final_edit(step_input: StepInput) -> StepOutput:
    return StepOutput(content=f"Final draft:\n{step_input.previous_step_content}")


workflow = Workflow(
    name="quality-loop",
    steps=[
        Loop(
            name="drafting-loop",
            steps=[Step(name="expand", executor=draft_section)],
            end_condition=quality_check,
            max_iterations=3,
            forward_iteration_output=True,  # Next round receives the previous round's output as previous_step_content
        ),
        Step(name="edit", executor=final_edit),
    ],
)
```

`forward_iteration_output=True` is the key to iterationaccumulation: by default each round restarts from the original input; when enabled, the next round's `previous_step_content` is the previous round's result,实现 "长写作, 逐轮打磨".

## 12.4 Router: Dynamic Path Selection

The `Router`'s selector function returns **the set of steps to execute**, picked from `choices`:

```python
from typing import List
from agno.workflow import Router, Step
from agno.workflow.types import StepInput

tech_step = Step(name="tech_research", executor=hackernews_researcher)
general_step = Step(name="general_research", executor=web_researcher)


def research_router(step_input: StepInput) -> List[Step]:
    topic = (step_input.previous_step_content or step_input.input or "").lower()
    if any(kw in topic for kw in ["ai", "programming", "startup", "software"]):
        return [tech_step]     # Returns a list; can return multiple steps
    return [general_step]


workflow = Workflow(
    name="router-demo",
    steps=[
        Router(
            name="strategy",
            selector=research_router,
            choices=[tech_step, general_step],
        ),
        publish_step,
    ],
)
```

Selection heuristic: **boolean judgment → `Condition`; multi-way selection → `Router`**. Both can be nested — for example, a Loop placed inside a branch chosen by a Router.

## 12.5 Composition Hands-On: Content Production Pipeline + Step-Level Structured IO

String the primitives together into a real pipeline, and let each LLM step use `output_schema` to output Pydantic objects:

```python
from pydantic import BaseModel, Field


class Draft(BaseModel):
    title: str = Field(description="Article title")
    body: str = Field(description="Body text")
    word_count: int


class Review(BaseModel):
    approved: bool
    comments: list[str]


drafter = Agent(name="Drafter", model=model, output_schema=Draft,
                instructions=["Output the draft according to the schema"])
review_agent = Agent(name="Reviewer", model=model, output_schema=Review,
                     instructions=["Review the draft; approved indicates whether it passes"])

content_workflow = Workflow(
    name="content-pipeline",
    steps=[
        Parallel(Step(name="collect_hn", executor=hackernews_researcher),
                 Step(name="collect_web", executor=web_researcher),
                 name="collect"),
        Step(name="draft", executor=drafter),
        Loop(
            name="revise-loop",
            steps=[Step(name="review", executor=review_agent)],
            end_condition=lambda outputs: all(
                getattr(o.content, "approved", False) for o in outputs
            ),
            max_iterations=3,
            forward_iteration_output=True,
        ),
        Step(name="publish", executor=publisher),
    ],
)
```

Each step's output is a Pydantic-validated object; the downstream step receives not "hoping the format is correct" raw text — this is the分水岭 between production-grade Workflows and demos.

::: tip Class Executors
When initialization配置 or state maintenance is needed, implement a class with `__call__(self, step_input) -> StepOutput` as the executor; the instance is reused across multiple runs.
:::

## 12.6 Chapter Summary

- `Parallel` runs independent steps concurrently and aggregates outputs in configured order; parallel branches写 shared state withdifferent keys;
- `Condition(evaluator, steps, else_steps)`实现 testable deterministic branching;
- `Loop` converges via `end_condition` + `max_iterations`; `forward_iteration_output=True`让 iterations累积 on the previous round's result;
- `Router.selector` returns the list of Steps to execute, suitable for multi-way mutually exclusive selection;
- Step-level `output_schema` lets structured data流转 across the entire pipeline.
