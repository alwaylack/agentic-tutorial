# Chapter 15 · Storage: Session Persistence

> Chapter goals: understand Agno\'s unified database layer (introduced in 2.x, continued in 3.x); learn to use `SqliteDb` for development and `PostgresDb` for production; verify "对话依然接得上 after restarting the process".

## 15.1 What Storage Solves

The chat history and session state from the previous chapter both依赖 a前提: **a database**. An Agent without storage is a "goldfish" — process重启即失忆; with storage, the same `session_id` can跨进程, 跨机器续上对话. The official docs定义非常直白:

> Storage让 Agent拥有跨会话的记忆: as long as the same `session_id` is used, even if the process重启, the conversation can continue from where it left off. (Chinese translation of the official docs wording)

Agno has unified the存储层 since 2.x (continued in 3.x):不再区分旧版的 `Storage` with记忆库等多套配置; instead把会话 run, session state, user memory, session summary全部交给同一个 `db` object管理 (对应表如 `agno_sessions`, `agno_memories` etc.). You only need选对数据库驱动.

## 15.2 Development Environment: SqliteDb

SQLite is零部署,单文件; the默认选择 for本地开发:

```python
# storage_basic.py —— minimal session persistence example
import os
from agno.agent import Agent
from agno.db.sqlite import SqliteDb
from agno.models.openai import OpenAIChat
from agno.tools.yfinance import YFinanceTools

db = SqliteDb(db_file="tmp/agents.db")   # One file is the entire database

agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    tools=[YFinanceTools(enable_stock_price=True)],
    db=db,
    add_history_to_context=True,
    num_history_runs=5,
    markdown=True,
)

session_id = "finance-session"

agent.print_response("Briefly analyze NVIDIA\'s stock trend", session_id=session_id)
agent.print_response("Compare it with AMD", session_id=session_id)      # "it" = NVIDIA
agent.print_response("Which is more worth investing in?", session_id=session_id)      # Full context
```

On the third提问 the model能同时理解 "both" refers to what — because the完整消息 (including tool call results) from the前两轮 are in the database.

## 15.3 Restart Verification: The Touchstone for Persistence

Whether storage生效的标准只有一个: **kill the process and run again; whether the对话还能接上**.

```python
# resume_check.py — first run: write
import os
from agno.agent import Agent
from agno.db.sqlite import SqliteDb
from agno.models.openai import OpenAIChat

agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    db=SqliteDb(db_file="tmp/agent.db"),
    add_history_to_context=True,
)

agent.print_response(
    "Remember this code word: pineapple pizza.",
    session_id="resume-demo",
)
print("First run ends; now please结束进程 after running resume_check_2.py")
```

```python
# resume_check_2.py — second run (new process): read
import os
from agno.agent import Agent
from agno.db.sqlite import SqliteDb
from agno.models.openai import OpenAIChat

agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    db=SqliteDb(db_file="tmp/agent.db"),   # Point to the same file
    add_history_to_context=True,
)

agent.print_response(
    "What is the code word? Where were we last?",
    session_id="resume-demo",
)   # The model should复述 the code word and上文 — persistence生效
```

Regardless of间隔多久 between the two runs (even换一台装着同一份 `agent.db`文件的机器), the对话都能无缝衔接.

::: tip What Exactly Is Stored in the Database
Open `tmp/agents.db` (`sqlite3 tmp/agents.db ".tables"`) to see tables like `agno_sessions`, `agno_runs`: each run\'s消息列表, tool calls, metrics, session_state snapshots are存 as JSON in行记录. Understanding this helps排查 "why the model knew something it shouldn\'t have".
:::

## 15.4 Production Environment: PostgresDb

SQLite does not支持并发写与水平扩展; switch to `PostgresDb` for生产. Thanks to the统一接口, **迁移通常只需改一行**:

```python
# storage_postgres.py —— production-grade storage
import os
from agno.agent import Agent
from agno.db.postgres import PostgresDb
from agno.models.openai import OpenAIChat

db = PostgresDb(
    db_url=os.getenv(
        "DB_URL",
        "postgresql+psycopg://ai:ai@localhost:5432/ai",
    ),
)

agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    db=db,
    add_history_to_context=True,
    update_memory_on_run=True,   # Memory also走同一个 db (Chapter 16)
)

# Under多实例部署, as long as the same Postgres is共享,
# any instance can服务同一 session_id的requests.
agent.print_response("Continue our上次的话题", session_id="user-42-thread-1")
```

The官方 also provides an异步版 `AsyncPostgresDb`配合 `Agent.arun()`; besides Postgres, the same `db` abstraction has MySQL, MongoDB, Redis, DynamoDB etc.驱动可选; the选型原则 is to保持一致 with your team\'s existing运维栈.

| Scenario | Recommendation | Reason |
|---|---|---|
| Local开发/测试/演示 | `SqliteDb` | Zero部署;单文件易备份 |
| Production API service (multi-replica) | `PostgresDb` / `AsyncPostgresDb` | 并发安全;可水平扩展 |
| Existing Redis/Mongo stack | Corresponding Db driver | Reuse现有运维能力 |

## 15.5 Collaboration of Storage, State, and History

串联前面所学 into a完整的心智模型:

```python
# full_stack.py —— storage + history + state协作
import os
from agno.agent import Agent
from agno.db.sqlite import SqliteDb
from agno.models.openai import OpenAIChat
from agno.run import RunContext


def advance_stage(run_context: RunContext) -> str:
    """Move the order workflow to its next stage.

    Args:
        (No model-visible parameters)
    """
    stages = ["Collect requirements", "Confirm plan", "Quote", "Complete"]
    current = run_context.session_state.get("stage_idx", 0)
    if current >= len(stages) - 1:
        return "Workflow completed"
    run_context.session_state["stage_idx"] = current + 1
    return f"Current stage: {stages[current + 1]}"


agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    db=SqliteDb(db_file="tmp/workflow.db"),   # The根基 for all persistence
    session_state={"stage_idx": 0},           # State persists with the session
    tools=[advance_stage],
    instructions="Order stage: {stage_idx} corresponds to Collect/Confirm/Quote/Complete",
    add_history_to_context=True,              # History persists with the session
)

agent.print_response("I want to customize a batch of T-shirts", session_id="order-9001")   # Advance to confirm plan
# ...after process重启...
agent.print_response("Where are we in the process? What is next?", session_id="order-9001")
```

After one run ends, the content写入数据库 includes: message历史 (including tool calls), session state snapshots, token metrics. `db` is the共同载体 for all three — this is why Chapter 14 says "历史注入的前提是配置数据库".

## 15.6 Chapter Summary

- Storage让 Agent跨进程/跨机器保持记忆; the判定标准 is "after restart, the same session can续聊";
- Agno\'s unified storage layer (introduced in 2.x, continued in 3.x): sessions, state, memory, summaries all共用一个 `db` object;
- Development uses `SqliteDb(db_file=...)`; production uses `PostgresDb` (async scenario `AsyncPostgresDb`);迁移成本约等于改一行;
- The database可以看到 `agno_sessions` / `agno_runs` etc. tables; runs\' messages, state snapshots, metrics all therein.
