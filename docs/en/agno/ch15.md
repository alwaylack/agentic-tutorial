# Chapter 15 · Storage: Session Persistence

> Chapter goals: understand Agno's unified database layer (introduced in 2.x, continued in 3.x), learn to use `SqliteDb` for development storage and `PostgresDb` for production, and verify "conversations remain接续 after process restart".

## 15.1 What Storage Solves

The chat history and session state from the previous chapter both依赖 a premise: **a database exists**. An Agent without storage is a "goldfish" — process restart means amnesia; with storage, the same `session_id` can跨进程、跨机器续上对话. The official docs定义非常直白:

> Storage lets Agents拥有跨会话的记忆: as long as the same `session_id` is used, even after process restart, the conversation can继续 from where it was interrupted. (Chinese translation of the official doc原文)

Agno has unified the storage layer since 2.x (continued in 3.x):不再区分旧版的 `Storage` 与记忆库等多套配置,而是把会话 run、会话状态、用户记忆、会话摘要全部交给同一个 `db` object管理 (对应表如 `agno_sessions`, `agno_memories` 等). You只需选对数据库驱动.

## 15.2 Development Environment: SqliteDb

SQLite is零部署, single-file, the default choice for本地开发:

```python
# storage_basic.py —— Minimal session persistence example
import os
from agno.agent import Agent
from agno.db.sqlite import SqliteDb
from agno.models.openai import OpenAIChat
from agno.tools.yfinance import YFinanceTools

db = SqliteDb(db_file="tmp/agents.db")   # One file is an entire database

agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    tools=[YFinanceTools(enable_stock_price=True)],
    db=db,
    add_history_to_context=True,
    num_history_runs=5,
    markdown=True,
)

session_id = "finance-session"

agent.print_response("Briefly analyze NVIDIA's stock trend", session_id=session_id)
agent.print_response("Compare it with AMD", session_id=session_id)      # "it" = NVIDIA
agent.print_response("Which is more worth investing in?", session_id=session_id)      # Full context
```

On the third提问 the model能同时理解"两者"指什么 — because the前两轮的完整消息 (including tool call results) are in the database.

## 15.3 Restart Verification: The Touchstone of Persistence

Whether存储 is生效, the标准只有一个: **kill the process and run again — can the conversation still接续?**

```python
# resume_check.py —— First run: write
import os
from agno.agent import Agent
from agno.db.sqlite import SqliteDb
from agno.models.openai import OpenAIChat

agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    db=SqliteDb(db_file="tmp/agent.db"),
    add_history_to_context=True,
)

agent.print_response(
    "Remember this secret code: pineapple pizza.",
    session_id="resume-demo",
)
print("First run ended; now please结束进程 and run resume_check_2.py")
```

```python
# resume_check_2.py —— Second run (new process): read
import os
from agno.agent import Agent
from agno.db.sqlite import SqliteDb
from agno.models.openai import OpenAIChat

agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    db=SqliteDb(db_file="tmp/agent.db"),   # Points to the same file
    add_history_to_context=True,
)

agent.print_response(
    "What is the secret code? Where were we?",
    session_id="resume-demo",
)   # Model should be able to复述 the code and上文 — persistence生效
```

Regardless of间隔多久 between the two runs (even换一台装着同一份 `agent.db` 文件的机器), the conversation无缝衔接.

::: tip What Exactly Is在库里
Open `tmp/agents.db` (`sqlite3 tmp/agents.db ".tables"`) to see tables like `agno_sessions`, `agno_runs`: each run's message list, tool calls, metrics, and session_state snapshots are stored as JSON in行记录. Understanding this helps排查 "why did the model know something it shouldn't".
:::

## 15.4 Production Environment: PostgresDb

SQLite does not support concurrent writes and horizontal scaling; switch to `PostgresDb` for production. Thanks to the统一接口, **迁移通常只需改一行**:

```python
# storage_postgres.py —— Production-grade storage
import os
from agno.agent import Agent
from agno.db.postgres import PostgresDb
from agno.models.openai import OpenAIChat

db = PostgresDb(
    db_url=os.getenv(
        "DB_URL",
        "postgresql+psycopg://ai:ai@localhost:5432/ai",
    ),
)

agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    db=db,
    add_history_to_context=True,
    update_memory_on_run=True,   # Memory also走同一个 db (Chapter 16)
)

# Under多实例部署, as long as the same Postgres is共享,
#任意实例都能服务同一 session_id 的请求.
agent.print_response("Continue our last topic", session_id="user-42-thread-1")
```

The官方 also provides an async version `AsyncPostgresDb`配合 `Agent.arun()`; besides Postgres, the same `db` abstraction有 MySQL, MongoDB, Redis, DynamoDB等驱动可选, the selection原则与你的团队现有的运维栈保持一致即可.

| Scenario | Recommendation | Reason |
|---|---|---|
| Local dev/test/demo | `SqliteDb` | Zero deployment, single-file easy备份 |
| Production API service (multi-replica) | `PostgresDb` / `AsyncPostgresDb` | Concurrency-safe, horizontally scalable |
| Existing Redis/Mongo stack | Corresponding Db driver | Reuse existing运维能力 |

## 15.5 Storage, State, and History协同

String the前面所学 into one完整的心智模型:

```python
# full_stack.py —— Storage + history + state三者协作
import os
from agno.agent import Agent
from agno.db.sqlite import SqliteDb
from agno.models.openai import OpenAIChat
from agno.run import RunContext


def advance_stage(run_context: RunContext) -> str:
    """Move the order workflow to its next stage.

    Args:
        (no model-visible parameters)
    """
    stages = ["Collect requirements", "Confirm plan", "Quote", "Complete"]
    current = run_context.session_state.get("stage_idx", 0)
    if current >= len(stages) - 1:
        return "Workflow complete"
    run_context.session_state["stage_idx"] = current + 1
    return f"Current stage: {stages[current + 1]}"


agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    db=SqliteDb(db_file="tmp/workflow.db"),   # The根基 of all persistence
    session_state={"stage_idx": 0},           # State persists with session
    tools=[advance_stage],
    instructions="Order stage: {stage_idx} corresponds to Collect requirements/Confirm plan/Quote/Complete",
    add_history_to_context=True,              # History persists with session
)

agent.print_response("I want to定制一批 T-shirts", session_id="order-9001")   # Advance to confirm plan
# ……after process restart……
agent.print_response("Where did we get to? What's next?", session_id="order-9001")
```

After one run ends, the contentpersisted to the database includes: message history (including tool calls), session state snapshots, token metrics. `db` is the共同载体 for the three — this is why Chapter 14 said "the prerequisite for history injection is configuring a database".

## 15.6 Chapter Summary

- Storage lets Agents保持记忆跨进程/跨机器; the判定标准 is "can the same session resume chatting after restart";
- Agno's unified storage layer (introduced in 2.x, continued in 3.x): sessions, state, memory, summaries all share one `db` object;
- Dev uses `SqliteDb(db_file=...)`, production uses `PostgresDb` (async scenario `AsyncPostgresDb`); migration cost约等于改一行;
- The database can see tables like `agno_sessions` / `agno_runs`; runs' messages, state snapshots, and metrics are all in there.
