## 1.1 From LLM Calls to Agents

Directly calling an LLM API (e.g., sending text to DeepSeek and receiving a reply) can only solve "one question, one answer" problems. Real business often requires the model to **work in multiple steps**: query data first, then calculate, then summarize. Encapsulating this "perceive → decide → act → observe results → decide again" loop creates an **Agent**.

A typical Agent consists of five building blocks:

| Block | Purpose | Analogy |
|---|---|---|
| Model | Handles "thinking," produces text or tool calls | Brain |
| Tools | Lets the model check weather, search the web, call APIs | Hands |
| Memory | Remembers user preferences and facts across sessions | Long-term memory |
| Knowledge | Injects domain materials via retrieval (RAG) | Reference bookshelf |
| Storage/DB | Saves conversation history so dialogue can continue | Notebook |

The Agent run loop can be summarized in one sentence: **build context, send to model → model either answers or requests tool calls → execute tools and feed results back to model → loop until model stops calling tools → return final answer**. Expressed in pseudocode:

```python
# Skeleton of the Agent run loop (pseudocode)
def agent_loop(user_input):
    messages = build_context(user_input)   # 1. Assemble context
    while True:
        reply = model(messages)            # 2. Request model
        if reply.tool_calls:               # 3. Model wants to call tools
            results = run_tools(reply.tool_calls)
            messages.append(results)       # 4. Tool results fed back, continue loop
        else:
            return reply.text              # 5. No more tool calls → final answer
```

Understand this loop, and every subsequent chapter is just upgrading one of these five blocks.

## 1.2 What Is Agno

Agno is an open-source Python Agent framework. The current latest major version is **Agno 3.x** (this tutorial has been fully verified against official documents up to agno 3.x). Its official positioning has three layers:

1. **Agent SDK** — define Agents with a few lines of Python;
2. **Agent Runtime** — runtime for multi-agent Teams and step-by-step Workflows;
3. **Control Plane (AgentOS)** — turn Agents into FastAPI services with one click, providing session isolation, monitoring, evaluation and other production capabilities.

::: tip Why choose Agno for learning
Compared to LangChain's "chain abstraction," Agno deliberately lets you write AI logic using plain Python structures (`if/else`, functions, classes) with fewer concepts and faster onboarding. Meanwhile, it has built-in production-grade features like memory, knowledge base, storage, and human-in-the-loop coordination — no need to switch frameworks from toy to production.
:::

## 1.3 Core Components Overview

The following code is Agno's official "minimal working Agent," adapted here to connect with **DeepSeek** (an OpenAI-compatible third-party model) — this is also the unified pattern throughout the book:

```python
# first_agent.py
import os
from agno.agent import Agent
from agno.models.openai import OpenAIChat
from agno.tools.duckduckgo import DuckDuckGoTools

agent = Agent(
    # Connect to any OpenAI-compatible endpoint via OpenAIChat (using DeepSeek as example)
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    tools=[DuckDuckGoTools()],   # Built-in search toolkit
    instructions=["Search first, then answer", "Cite sources at the end"],
    markdown=True,               # Output in Markdown format
)

agent.print_response("What is the latest version of the Agno framework?", stream=True)
```

Referencing the table in 1.1, this code already uses three blocks: model (`model`), tools (`tools`), and instructions (`instructions`). The remaining parts will be filled in chapter by chapter:

## 1.5 How Agno Differs from Traditional Chain Frameworks

Beginners often ask: "LangChain/LangGraph can also build Agents — why use Agno?" The differences are mainly in three areas:

1. **Abstraction level**: Chain frameworks organize flows into "chain/graph" nodes; Agno advocates writing Python control flow directly — when debugging, you're facing ordinary code.
2. **Built-in completeness**: Agno packages session storage, user memory, vector knowledge bases, Guardrails, MCP, and AgentOS service-orientation as out-of-the-box components, eliminating the need to assemble a dozen integration packages yourself.
3. **Performance orientation**: The official documentation emphasizes that Agent instantiation is microsecond-level with minimal memory footprint, suitable for high-concurrency scenarios creating many short-lived Agents.

Of course, no framework is a silver bullet: if your scenario is a complex deterministic state machine, Workflow (Chapter 11) combined with plain functions may be more appropriate — which is precisely why Agno provides three orchestration forms (single Agent / Team / Workflow).
