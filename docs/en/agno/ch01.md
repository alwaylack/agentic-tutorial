## 1.1 From LLM Calls to Agents

Directly calling an LLM API（比如发一段文字给 DeepSeek 然后拿回回复）只能解决"one-question-one-answer"的Issue。真实业务往往需要Model**multi-step work**：query data first, then calculate, then summarize。把这种"perceive → decide → act → observe results → decide again"的循环封装起来，就是一个 **Agent（Agent）**。

一个典型的 Agent 由五classesbuilding block组成：

| building block | 作用 | classes比 |
|---|---|---|
| Model（Model） | 负责"思考"，produces text or tool calls | brain |
| Tool（Tools） | lets the model check weather、search the web、call APIs | hands |
| Memory（Memory） | remembers user preferences and facts across sessions | long-term memory |
| Knowledge Base（Knowledge） | 通过检索（RAG）注入领域资料 | reference bookshelf |
| Storage（Storage/DB） | saves session history，so conversations can continue | notebook |

Agent 的operation loop可以概括为一句话：**build context and send to model → model either responds or requests tool calls → execute tools and feed results back to model → loop until model stops calling tools → return final answer**。用pseudocode表达：

```python
# Agent Running循环的骨架（伪代码）
def agent_loop(user_input):
    messages = build_context(user_input)   # 1. 组装上下文
    while True:
        reply = model(messages)            # 2. 请求Model
        if reply.tool_calls:               # 3. Model想调用Tool
            results = run_tools(reply.tool_calls)
            messages.append(results)       # 4. Tool结果回传，继续循环
        else:
            return reply.text              # 5. 没有Tool调用 → 最终答案
```

Understand了这个循环，后面所有章节都只是在给这五块building block"升级配件"。

## 1.2 What is Agno

Agno 是一个open-source Python Agent framework，current latest major version is **Agno 3.x**（本教程已对照官方文档全面核对至 agno 3.x）。official positioning has three layers：

1. **Agent SDK**——define Agents with a few lines of Python；
2. **Agent Runtime**——多Agent Team、step-by-step Workflow 的Running时；
3. **Control Plane（AgentOS）**——把 Agent turn into FastAPI services with one click，提供session isolation、monitoring、evaluation等生产能力。

::: tip Why Choose Agno for Learning
相比 LangChain 的"链式抽象"，Agno 刻意让你用普通 Python 结构（`if/else`、函数、类）来写 AI 逻辑，概念少、上手快；同时它内置了Memory、Knowledge Base、Storage、人机协同等production-grade特性，从玩具到上线不需要换框架。
:::

## 1.3 Core Components Overview

下面这段代码是 Agno 官方文档的"minimal viable Agent"，我们把它adapted to integrate **DeepSeek**（OpenAI-compatible third-party models）的版本——这也是unified approach throughout the book：

```python
# first_agent.py
import os
from agno.agent import Agent
from agno.models.openai import OpenAIChat
from agno.tools.duckduckgo import DuckDuckGoTools

agent = Agent(
    # 用 OpenAIChat 连接任意 OpenAI 兼容端点（这里以 DeepSeek 为例）
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    tools=[DuckDuckGoTools()],   # 内置搜索Tool包
    instructions=["先搜索再回答", "回答末尾附上信息来源"],
    markdown=True,               # 以 Markdown 格式Output
)

agent.print_response("Agno 框架最新版本是多少？", stream=True)
```

对照 1.1 的表格，这段代码已经用到了三块积木：Model（`model`）、Tool（`tools`）、指令（`instructions`）。后续章节会逐一补齐其余部分：

- collaboration与编排 → Team：第 9–10 章；Workflow：第 11–12 章；
- 多模态 → 第 13 章；Session与状态 → 第 14 章；Storage → 第 15 章；Memory → 第 16 章；
- Knowledge Base/RAG → 第 17–18 章；推理Model与技能包 → 第 19–20 章；
- 人机协同/Guardrails → 第 21 章；MCP → 第 22 章；服务化 AgentOS → 第 23 章。

## 1.5 Agno 与传统 Chain 框架的差异

初学者常问："LangChain/LangGraph 也能做 Agent，为什么要用 Agno？"差异主要在三点：

1. **抽象层级**：Chain 框架把流程编排成"链/图"节点；Agno 主张直接写 Python 控制流，调试时你面对的就是普通代码。
2. **内置完整度**：Agno 把SessionStorage、用户Memory、向量Knowledge Base、Guardrails、MCP、AgentOS 服务化做成开箱即用的组件，不用自己拼装十几个集成包。
3. **性能取向**：官方强调 Agent 实例化是微秒级、内存占用极小，适合高concurrency场景大量创建短生命周期 Agent。

当然，框架没有银弹：如果你的场景是复杂的确定性状态机，Workflow（第 11 章）配合普通functions会更合适——这正是 Agno 提供三种编排形态（单 Agent / Team / Workflow）的原因。
