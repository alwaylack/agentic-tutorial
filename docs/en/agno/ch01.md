## 1.1 From LLM Calls to Agents

Calling an LLM API directly (e.g., sending text to DeepSeek and getting a reply back) can only solve "one question, one answer" problems. Real business needs **multi-step work**: query data first, then compute, then summarize. Encapsulating this "perceive → decide → act → observe results → decide again" loop is what makes an **Agent**.

A typical Agent is composed of five building blocks:

| Block | Role | Analogy |
|---|---|---|
| Model | Handles "thinking"; produces text or tool calls | Brain |
| Tools | Lets the model check weather, search the web, call APIs | Hands |
| Memory | Remembers user preferences and facts across sessions | Long-term memory |
| Knowledge Base | Injects domain materials via retrieval (RAG) | Reference bookshelf |
| Storage (DB) | Persists session history so conversations can resume | Notebook |

The Agent run loop can be summarized in one sentence: **build context and send it to the model → model either answers or requests tool calls → execute tools and feed results back → loop until the model stops calling tools → return the final answer**. In pseudocode:

```python
# Agent run loop skeleton (pseudocode)
def agent_loop(user_input):
    messages = build_context(user_input)   # 1. Build context
    while True:
        reply = model(messages)            # 2. Request from model
        if reply.tool_calls:               # 3. Model wants to call tools
            results = run_tools(reply.tool_calls)
            messages.append(results)       # 4. Feed tool results back, continue loop
        else:
            return reply.text              # 5. No tool calls → final answer
```

Once you understand this loop, every chapter ahead is just upgrading one of these five blocks.

## 1.2 What Is Agno

Agno is an open-source Python Agent framework. The current major version is **Agno 3.x** (this tutorial has been verified against the official docs for agno 3.x). The official positioning spans three layers:

1. **Agent SDK** — define an Agent in a few lines of Python;
2. **Agent Runtime** — runtime for multi-agent Teams and step-by-step Workflows;
3. **Control Plane (AgentOS)** — turn your Agent into a FastAPI service with one command, providing session isolation, monitoring, evaluations, and other production capabilities.

::: tip Why choose Agno to get started
Compared to LangChain's "chain abstraction," Agno deliberately lets you write AI logic using plain Python constructs (`if/else`, functions, classes) — fewer concepts, faster onboarding. It also ships built-in production features like memory, knowledge base, storage, and human-in-the-loop, so you never need to switch frameworks from toy to production.
:::

## 1.3 Core Components Overview

The code below is the "minimum viable Agent" from the Agno official docs, adapted to connect to **DeepSeek** (an OpenAI-compatible third-party model) — this is the unified pattern used throughout the book:

```python
# first_agent.py
import os
from agno.agent import Agent
from agno.models.openai import OpenAIChat
from agno.tools.duckduckgo import DuckDuckGoTools

agent = Agent(
    # Connect to any OpenAI-compatible endpoint using OpenAIChat (DeepSeek shown here)
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    tools=[DuckDuckGoTools()],   # Built-in search toolkit
    instructions=["Search before answering", "Cite sources at the end of your answer"],
    markdown=True,               # Render output as Markdown
)

agent.print_response("What is the latest version of the Agno framework?", stream=True)
```

对照 1.1 的表格，这段代码已经用到了三块积木：模型（`model`）、工具（`tools`）、指令（`instructions`）。后续章节会逐一补齐其余部分：

## 1.5 How Agno Differs from Traditional Chain Frameworks

Beginners often ask: "LangChain/LangGraph can also build Agents — why use Agno?" The differences are mainly threefold:

1. **Abstraction level**: Chain frameworks compose flows into "chain/graph" nodes; Agno advocates writing Python control flow directly — when debugging, you're looking at plain code.
2. **Built-in completeness**: Agno bundles session storage, user memory, vector knowledge bases, Guardrails, MCP, and AgentOS service publishing as out-of-the-box components — no need to assemble a dozen integration packages yourself.
3. **Performance orientation**: The official docs stress that Agent instantiation is microsecond-level with minimal memory footprint, ideal for high-concurrency scenarios with many short-lived Agents.

Of course, no framework is a silver bullet: if your scenario is a complex deterministic state machine, a Workflow (Chapter 11) paired with plain functions is more suitable — which is precisely why Agno offers three orchestration shapes (single Agent / Team / Workflow).
