# Chapter 21 · Human-in-the-Loop and Guardrails

> Chapter goals: equip the Agent with "brakes" —实现人机协同 via tool confirmation mechanisms;拦截敏感输入 and危险输出 with pre/post hooks and内置 Guardrails;设计合理的失败降级策略.

## 21.1 Why Agents Need "Brakes"

The风险 from autonomous Agents comes from two ends: the **入口** (the user may注入恶意指令 or submit隐私数据) and the **出口** (the模型 may call destructive operations like删库, 转账). The工程对策 is three layers of防线:

1. **Tool confirmation (Human-in-the-Loop)**: pause before dangerous操作执行; wait for human批准;
2. **Guardrails (pre_hooks)**: validate/detokenize/intercept before输入 reaches the model;
3. **Output checks (post_hooks)**: compliance审查 before回复返回用户.

::: info Version Note
The Guardrails and hooks system was introduced自 Agno v2.1.0; tool confirmation (`requires_confirmation`) is同样 HITL标准做法. This tutorial is基于 Agno 3.x.
:::

## 21.2 Tool Confirmation: Letting Dangerous Operations Wait for a Human

Add `@tool(requires_confirmation=True)` to a自定义工具; when the Agent执行 to this tool, it **pauses** (`is_paused=True`); hands the待执行的工具名 with参数 to you for审批; after approval continue with `continue_run()`:

```python
# hitl_confirm.py
import os
from agno.agent import Agent
from agno.db.sqlite import SqliteDb          # Persistence needed to保存运行状态 for resuming
from agno.models.openai import OpenAIChat
from agno.tools import tool

@tool(requires_confirmation=True)
def refund_order(order_id: str, amount: float) -> str:
    """Execute a refund for the specified order; a sensitive资金操作."""
    return f"Order {order_id} refunded {amount} yuan"

agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    tools=[refund_order],
    db=SqliteDb(db_file="tmp/hitl.db"),      # Must persist run状态 to support续跑
)

run_response = agent.run("Help me refund order A1001 for 99 yuan")

# Approval环节: iterate over待确认需求
for requirement in run_response.active_requirements:
    if requirement.needs_confirmation:
        print(f"Pending confirmation: {requirement.tool_execution.tool_name}"
              f"{requirement.tool_execution.tool_args}")
        if input("Approve? (y/n): ").lower() == "y":
            requirement.confirm()
        else:
            requirement.reject()

# Continue执行 with the approval结果
response = agent.continue_run(
    run_id=run_response.run_id,
    requirements=run_response.requirements,
)
print(response.content)
```

For Toolkit内置工具, use `requires_confirmation_tools=["tool_name"]` to保护指定函数;其余照常自动执行.

## 21.3 Built-in Guardrails: PII and Prompt Injection Protection

Guardrails挂 as **pre_hooks**; executed before输入 reaches the model. Agno内置了 PII detection, prompt injection defense, and OpenAI content moderation三种:

```python
from agno.agent import Agent
from agno.guardrails import PIIDetectionGuardrail, PromptInjectionGuardrail

support_agent = Agent(
    model=model,
    pre_hooks=[
        PIIDetectionGuardrail(),        # Intercept身份证号/手机号 etc. privacy data
        PromptInjectionGuardrail(),     # Detect "ignore all previous instructions" injection attacks
    ],
    markdown=True,
)
# Inputs含手机号 will be直接拦截 and raise InputCheckError
```

## 21.4 Custom Guardrails

Inherit `BaseGuardrail` and implement `check()` / `async_check()` (分别服务同步 `.run()` 和异步 `.arun()`); raise `InputCheckError` when违规 is detected:

```python
import re
from agno.exceptions import CheckTrigger, InputCheckError
from agno.guardrails import BaseGuardrail
from agno.run.agent import RunInput

class SensitiveWordGuardrail(BaseGuardrail):
    """Intercept对外咨询 inputs containing competitor names."""

    def check(self, run_input: RunInput) -> None:
        if isinstance(run_input.input_content, str):
            if re.search(r"某友|某蝶", run_input.input_content):
                raise InputCheckError(
                    "Input contains不允许讨论的内容.",
                    check_trigger=CheckTrigger.INPUT_NOT_ALLOWED,
                )

    async def async_check(self, run_input: RunInput) -> None:
        self.check(run_input)   # When规则简单 the async版 can直接复用同步逻辑

# Usage same as built-in guardrails: pre_hooks=[SensitiveWordGuardrail()]
```

输出侧审查则写 **post_hook**: it拿到生成结果 but尚未返回用户; can do敏感词扫描, compliance改写 or打标.

```python
from datetime import datetime

def audit_log_hook(run_input, run_output):
    """post_hook: persist each输入与输出 for合规审计."""
    with open("tmp/audit.log", "a", encoding="utf-8") as f:
        f.write(f"[{datetime.now():%F %T}] IN: {run_input.input_content}\n")
        f.write(f"[{datetime.now():%F %T}] OUT: {run_output.content}\n")

compliance_agent = Agent(
    model=model,
    pre_hooks=[SensitiveWordGuardrail()],   # 事前拦截
    post_hooks=[audit_log_hook],            # 事后审计 (can also do改写/打标)
)
```

## 21.5 Failure Degradation Strategies

拦截不是终点;生产系统要回答 "拦下之后怎么办":

- **可修复错误** (format issues): auto改写 and retry once in the post_hook;
- **需人工介入**: catch `InputCheckError` and转人工队列; write the原因 into the审计日志;
- **拒绝但不崩溃**:统一返回礼貌的兜底话术 to the外部;保留完整的错误码 internally;
- **灰度上线**:新 guardrail first观察误杀率 in "只记日志不拦截" mode; then逐步切换为强制拦截.

## 21.6 Chapter Summary

- Three-layer防线: tool confirmation (事中); pre_hooks输入防护 (事前); post_hooks输出审查 (事后);
- `@tool(requires_confirmation=True)` + `active_requirements` + `continue_run()`是标准 HITL流程;且必须配置 `db` to持久化运行状态;
- Built-in Guardrails挂 via `pre_hooks=[...]`; custom时继承 `BaseGuardrail` implement `check()/async_check()` and raise `InputCheckError`;
- After拦截要有明确的降级路径: retry,转人工, 兜底话术,灰度观察.
