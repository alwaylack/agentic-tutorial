# Chapter 27 · Capstone 二: Multi-Source Research Assistant Team

> Chapter goals: build a "multi-source retrieval → collaborative writing →逐条核查" research pipeline — Researcher A负责公网搜索, Researcher B负责本地文档库检索; the Writer synthesizes into a report; the Fact-Checker逐条复核关键论断 and标注置信度;最终产出带引用来源的 `research-report.md`.

## 27.1 Requirements and Team Design

Writing a可信的研究报告, the难点不在"写", but in **素材的广度** and **论断的可信度**. We split these两个关注点 to different角色:

```text
Research topic: "The technology landscape of edge AI inference frameworks in 2025"
    │
    ▼
┌──────────────────────────────────────────────┐
│ Research Team (coordinate mode)              │
│                                              │
│  Leader:拆解子任务, 分派, 汇总               │
│   ├── Researcher A: DuckDuckGo公网检索       │
│   │     (news, blogs, official releases)      │
│   └── Researcher B: Local Knowledge检索      │
│         (arXiv paper abstract library, LanceDb vector)
└──────────────────────────────────────────────┘
    │ Material package (with来源标注)
    ▼
Writer Agent ──▶ Report draft
    │
    ▼
Fact-Checker Agent ──▶标注每个关键论断的置信度
    │
    ▼
research-report.md (with cited source list)
```

为什么用 **Team (coordinate) instead of a linear Workflow**?

- The two researchers\' retrievals are**互不依赖**; in coordinate mode the leader dispatches并发; total duration≈the slowest member; a linear Workflow只能串行等待;
- The quality of retrieval results is不可预知; the leader needs to**根据素材情况决定是否追加委派** (e.g., "公网 results are too few; have B search the论文库 again") — this dynamic capability is exactly what coordinate excels at;
- The latter half "write → check" has强顺序依赖; putting them in a Team is反而多余; so split into two独立 Agents串联执行.

## 27.2 Prepare the Model and Local Paper Knowledge Base

统一使用 DeepSeek as the底层模型; Researcher B检索的是预先灌入 LanceDb的 arXiv论文摘要库:

```python
# research_common.py —— shared infrastructure for the team
import os
from agno.knowledge.knowledge import Knowledge
from agno.knowledge.embedder.openai import OpenAIEmbedder
from agno.models.openai import OpenAIChat
from agno.vectordb.lancedb import LanceDb, SearchType

def make_model() -> OpenAIChat:
    """All roles share the same third-party model config,便于统一换模型."""
    return OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
        temperature=0.3,          # Research场景要求克制;降低发散
    )

# Researcher B\'s弹药库: arXiv paper abstract向量库
paper_kb = Knowledge(
    vector_db=LanceDb(
        table_name="arxiv_abstracts",
        uri="tmp/lancedb",
        search_type=SearchType.vector,
        embedder=OpenAIEmbedder(
            id="Qwen/Qwen3-Embedding-8B",
            api_key=os.getenv("EMBEDDING_API_KEY"),
            base_url="https://api.siliconflow.cn/v1",
        ),
    )
)

# On first run, populate the local paper PDF directory (skip_if_exists ensures幂等)
```

## 27.3 Researcher Agents with Structured Output

Both researchers强制输出统一的「发现 + 来源」格式:

```python
from agno.agent import Agent

researcher_a = Agent(
    name="ResearcherA",
    model=make_model(),
    tools=[DuckDuckGoTools()],
    instructions=[
        "Search for the topic online. 每条发现必须以如下格式输出：\n[发现] xxx\n[来源] URL",
        "如果找不到相关信息，输出：[发现] 无公开信息\n[来源] N/A",
    ],
)

researcher_b = Agent(
    name="ResearcherB",
    model=make_model(),
    knowledge=paper_kb,
    instructions=[
        "检索本地论文库。每条发现必须以如下格式输出：\n[发现] xxx\n[来源] 论文标题/链接",
        "如果找不到相关信息，输出：[发现] 无匹配论文\n[来源] N/A",
    ],
)
```

## 27.4 Writer Agent and Fact-Checker Agent

撰写员只管表达,核查员只管验证:

```python
writer = Agent(
    name="Writer",
    model=make_model(),
    instructions=[
        "根据研究员的素材产出研究报告。在每个论断后标注对应的 [Sn] 引用编号。",
        "报告结构：摘要、正文（分主题）、引用来源列表。",
    ],
)

fact_checker = Agent(
    name="FactChecker",
    model=make_model(),
    instructions=[
        "逐条复核报告中的关键论断。对每条论断输出：\n[论断] xxx\n[状态] ✅/⚠️/❌\n[说明] xxx",
        "✅ = 有明确来源支撑；⚠️ = 部分支撑或存疑；❌ = 无依据或矛盾。",
    ],
)
```

## 27.5 Orchestrating with a Team

```python
from agno.team import Team

research_team = Team(
    name="research-team",
    model=make_model(),
    members=[researcher_a, researcher_b],
    mode="coordinate",
    instructions=[
        "协作完成研究：A 负责公网检索，B 负责本地论文库检索。",
        "素材不足时领导者可追加委派。",
    ],
)

# 串联执行：先 Team 检索，再 Writer 撰写，最后 FactChecker 核查
final = research_team.print_response("边缘 AI 推理框架 2025 年的技术格局", markdown=True)
report_draft = writer.print_response(f"基于以下素材撰写报告：{final}", markdown=True)
check_result = fact_checker.print_response(f"请核查以下报告：\n{report_draft}", markdown=True)
```

## 27.6 Saving the Report

落盘 with date归档,便于追溯历史版本:

```python
out_dir = Path("reports"); out_dir.mkdir(exist_ok=True)
today = datetime.date.today().isoformat()
report_path = out_dir / f"research-report-{today}.md"
report_path.write_text(final, encoding="utf-8")
print(f"Report generated: {report_path}")
```

After running, open `reports/research-report-<date>.md`: the `[S1][S2]` numbers in the body can找到出处 in the "Cited Sources" section; the "Verification Log" appendix tells you which assertions were降级为 "待验证".

::: warning Cost Note
This pipeline全程使用 deepseek-chat; the单次完整运行的 token消耗主要来自 Team 的多轮协调与长素材注入. If预算敏感,可把核查员换成更小的模型 —核对类任务对推理能力的要求低于撰写.
:::

## 27.7 Chapter Summary

- **Team 选型**: For互不依赖的多路检索选 `TeamMode.coordinate` (可并发委派,可动态补查);强顺序依赖的后段用独立 Agent串联;
- **结构化中间产物**: Researchers输出统一的「发现 + 来源」格式; this is the关键 for下游撰写与核查能自动衔接;
- **职责分离**: Writer只管表达; Fact-Checker只管验证 — two视角 on the same draft are更可靠 than一个 Agent自查;
- **置信度分级**: ✅/⚠️/❌ three-state核查记录让报告的交付质量可被量化管理.
