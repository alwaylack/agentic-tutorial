# Chapter 5 · 结构化Output output_schema

> Chapter goals：让 Agent 的Output从"自由文本"变成"经过校验的 Pydantic 对象"，Master output_schema 的用法、Principles与设计Techniques。

## 5.1 自由文本的痛点

假设你要做一个"电影推荐 Agent"，让下游代码读取推荐结果。如果Model返回一段散文，你就得写正则或 `json.loads` 去解析——Model偶尔少个引号、多个解释性文字，程序直接崩。**结构化Output**把这个Issue彻底消灭：你定义数据结构，Model负责填充，框架负责校验。

## 5.2 基础用法：output_schema + Pydantic

```python
# structured_basic.py —— 让 Agent 返回 Pydantic 对象
import os
from dotenv import load_dotenv
from pydantic import BaseModel, Field
from agno.agent import Agent
from agno.models.openai import OpenAIChat

load_dotenv()

class MovieScript(BaseModel):
    setting: str = Field(description="故事发生的地点")
    genre: str = Field(description="电影类型")
    storyline: str = Field(description="三句话以内的剧情梗概")

agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    output_schema=MovieScript,     # 关键：声明Output结构
)

response = agent.run("写一个发生在东京的抢劫电影创意")

print(type(response.content))          # <class 'MovieScript'>，不是字符串！
print(response.content.setting)        # 直接用属性访问
print(response.content.genre)
print(response.content.storyline)
```

`response.content` 直接就是 `MovieScript` 实例——字段访问有类型Tip、IDE 自动补全、拼错字段名立刻报错。

## 5.3 底层Principles：schema 注入与校验回退

UnderstandPrinciples才能排查Issue。设置 `output_schema` 后 Agno 做了四件事：

1. 把 Pydantic Model转成 **JSON Schema**；
2. 若Model支持原生结构化Output协议（如 OpenAI 的 JSON Schema 模式），直接下发约束；
3. 不支持时，把 schema 写进Tip词并要求ModelOutput JSON，再解析；
4. 用 Pydantic **校验**解析结果，失败则记录Error——此时 `content` 可能退化为原始字符串。

::: warning 必须做的防御
DeepSeek 等三方Model走的多是"Tip词 + 解析"路径，偶发解析失败。官方文档明确Recommendation：**访问 schema 字段前先检查 `content` 的类型**。

```python
# safe_access.py —— 类型防御
result = agent.run("再写一个太空歌剧创意")
if isinstance(result.content, MovieScript):
    print("结构化成功:", result.content.genre)
else:
    print("解析失败，原始内容:", result.content)   # 降级处理
```
:::

## 5.4 进阶：嵌套Model、列表字段与按次覆盖

真实业务的Output结构往往嵌套。Pydantic 的组合能力在这里完全可用：

```python
# structured_nested.py —— 嵌套结构与Running时覆盖
from pydantic import BaseModel, Field
from agno.agent import Agent
from agno.models.openai import OpenAIChat
import os
from dotenv import load_dotenv

load_dotenv()
model = OpenAIChat(
    id="deepseek-chat",
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    base_url="https://api.deepseek.com/v1",
)

class Ingredient(BaseModel):
    name: str = Field(description="食材名")
    amount: str = Field(description="用量，如 200g")

class Recipe(BaseModel):
    title: str
    difficulty: str = Field(description="简单/中等/困难 三选一")
    ingredients: list[Ingredient] = Field(description="食材清单")   # 嵌套列表
    steps: list[str] = Field(description="步骤列表")

agent = Agent(model=model)   # 构造时不指定 schema

# 同一个 Agent 按次指定不同 schema —— 一个 Agent 服务多种Output格式
recipe = agent.run("设计一道 20 分钟完成的番茄牛腩", output_schema=Recipe).content
print(recipe.title, "共", len(recipe.ingredients), "种食材")
for ing in recipe.ingredients:
    print(f"- {ing.name}: {ing.amount}")
```

按次覆盖（`run(..., output_schema=...)`）非常适合"一个 Agent 多种任务"的场景，避免为每种Output格式克隆一个 Agent。

## 5.5 与手写解析的对比 + 与Tool结合

对比一下旧式手写解析，你就明白结构化Output的价值：

```python
# old_way.py —— 反面教材：手写 JSON 解析
import json

resp = agent.run("以 JSON 格式返回菜谱，字段包括 title、ingredients、steps")
try:
    # Model经常在 JSON 外面套一句"好的，以下是..."，直接炸
    data = json.loads(resp.content)
except json.JSONDecodeError as e:
    print("解析失败，需要手写清洗逻辑：", e)
    # 于是你开始 strip 反引号、正则截取 {...}、retry...
```

结构化Output还支持与Tool共存：Agent 先调Tool取数据，最后按 schema 组织答案。官方示例是股票分析——Tool查实时股价，`StockAnalysis` Model约束最终结论的字段。这个"**过程自由、结论受约束**"的模式是production-grade Agent 的常用架构。

## 5.6 Schema 设计Techniques

结合官方Recommendation，四条Capstone经验：

1. **每个字段都写 `Field(description=...)`**——描述就是给Model的需求说明，越具体越稳定；
2. **用约束表达枚举**：`Field(description="必须为 buy/hold/sell 之一")` 或 `Literal["buy", "hold", "sell"]`；
3. **数值范围用 `ge/le`**：如 `confidence: float = Field(ge=0, le=1)`，校验层自动拦截越界值；
4. **避免过深嵌套**（Recommendation ≤3 层）：层数越深，三方Model的格式Error率越高。

## 5.7 Chapter Summary

- `output_schema` 让 `content` 从字符串变成校验过的 Pydantic 对象；
- Principles是"JSON Schema 下发 → 生成 → Pydantic 校验"，三方Model可能回退为Tip词解析；
- 访问字段前用 `isinstance` 防御解析失败的情况；
- schema 可以构造时不给、Running时按次传入，一个 Agent 适配多种Output；
- 字段描述写得越清楚，Output越稳定。
