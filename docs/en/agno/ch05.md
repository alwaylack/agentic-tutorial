# Chapter 5 · Structured Output with output_schema

> Chapter goals: make the Agent\'s output change from "free-text" to a "validated Pydantic object"; master the usage, principles, and design techniques of output_schema.

## 5.1 The Pain of Free Text

Suppose you are building a "movie recommendation Agent" that feeds results into downstream code. If the model returns a prose paragraph, you need to write regex or `json.loads` to parse it — the model occasionally misses a quote or adds explanatory text, and the programcrashes. **Structured output**彻底消灭 this problem: you define the data structure, the model fills it in, and the framework validates it.

## 5.2 Basic Usage: output_schema + Pydantic

```python
# structured_basic.py —— make the Agent return a Pydantic object
import os
from dotenv import load_dotenv
from pydantic import BaseModel, Field
from agno.agent import Agent
from agno.models.openai import OpenAIChat

load_dotenv()

class MovieScript(BaseModel):
    setting: str = Field(description="Where the story takes place")
    genre: str = Field(description="Movie genre")
    storyline: str = Field(description="Plot synopsis in three sentences or less")

agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    output_schema=MovieScript,     # Key: declare the output structure
)

response = agent.run("Write a heist movie idea set in Tokyo")

print(type(response.content))          # <class 'MovieScript'>, not a string!
print(response.content.setting)        # Access directly via attributes
print(response.content.genre)
print(response.content.storyline)
```

`response.content` is directly a `MovieScript` instance — field access has type hints, IDE auto-completion, and typoed field names报错 immediately.

## 5.3 Underlying Principles: Schema Injection and Validation Fallback

Understanding the principle helps you troubleshoot. After setting `output_schema`, Agno does four things:

1. Convert the Pydantic model to a **JSON Schema**;
2. If the model supports a native structured output protocol (e.g., OpenAI\'s JSON Schema mode),下发 the constraint directly;
3. If not,写 the schema into the prompt and要求 the model output JSON, then parse it;
4. Validate the parsed result with Pydantic **validation**; on failure, log the error — at this point `content` may退化 to the raw string.

::: warning Defensive Programming Required
Third-party models like DeepSeek mostly走 the "prompt + parse" path, with偶发 parsing failures. The official docs明确建议: **check the type of `content` before accessing schema fields**.

```python
# safe_access.py —— type defense
result = agent.run("Write another space opera idea")
if isinstance(result.content, MovieScript):
    print("Structured success:", result.content.genre)
else:
    print("Parse failed, raw content:", result.content)   # Degraded handling
```
:::

## 5.4 Advanced: Nested Models, List Fields, and Per-Call Override

Real business output structures are often nested. Pydantic\'s composition capabilities work fully here:

```python
# structured_nested.py —— nested structures and runtime override
from pydantic import BaseModel, Field
from agno.agent import Agent
from agno.models.openai import OpenAIChat
import os
from dotenv import load_dotenv

load_dotenv()
model = OpenAIChat(
    id="deepseek-chat",
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    base_url="https://api.deepseek.com/v1",
)

class Ingredient(BaseModel):
    name: str = Field(description="Ingredient name")
    amount: str = Field(description="Amount, e.g., 200g")

class Recipe(BaseModel):
    title: str
    difficulty: str = Field(description="Choose one: easy/medium/hard")
    ingredients: list[Ingredient] = Field(description="Ingredient list")   # Nested list
    steps: list[str] = Field(description="Step list")

agent = Agent(model=model)   # Do not specify schema at construction

# Specify different schemas per call with the same Agent — one Agent serves多种输出格式
recipe = agent.run("Design a tomato beef brisket recipe that takes 20 minutes", output_schema=Recipe).content
print(recipe.title, "has", len(recipe.ingredients), "ingredients")
for ing in recipe.ingredients:
    print(f"- {ing.name}: {ing.amount}")
```

Per-call override (`run(..., output_schema=...)`) is ideal for "one Agent, multiple tasks" scenarios, avoiding cloning an Agent for each output format.

## 5.5 Comparison with Hand-Written Parsing + Integration with Tools

Compare with the old hand-written parsing approach, and you will understand the value of structured output:

```python
# old_way.py —— cautionary example: hand-written JSON parsing
import json

resp = agent.run("Return the recipe in JSON format, with fields title, ingredients, steps")
try:
    # The model often wraps the JSON in "OK, here is..." — direct crash
    data = json.loads(resp.content)
except json.JSONDecodeError as e:
    print("Parse failed, need hand-written cleaning logic:", e)
    # Then you start striping backticks, regex-extracting {...}, retrying...
```

Structured output also coexists with tools: the Agent calls tools to fetch data first, then组织 the answer according to the schema. The官方示例 is stock analysis — the tool查实时股价, the `StockAnalysis` model constrains the final conclusion\'s fields. This "**过程自由, 结论受约束**" pattern is a common architecture for production-grade Agents.

## 5.6 Schema Design Techniques

Combining official recommendations, four practical经验:

1. **Write `Field(description=...)` for every field** — the description is the model\'s requirement spec; the more具体 the more稳定;
2. **Express enumerations with constraints**: `Field(description="Must be one of buy/hold/sell")` or `Literal["buy", "hold", "sell"]`;
3. **Use `ge/le` for numeric ranges**: e.g., `confidence: float = Field(ge=0, le=1)`; the validation layer自动拦截越界值;
4. **Avoid overly deep nesting** (建议 ≤3 levels): the deeper the levels, the higher the format error rate from third-party models.

## 5.7 Chapter Summary

- `output_schema` changes `content` from a string to a validated Pydantic object;
- The principle is "JSON Schema下发 → generate → Pydantic validate"; third-party models may fall back to prompt parsing;
- Use `isinstance` checks before accessing fields to defend against parsing failures;
- schema can be omitted at construction and passed per-call at runtime; one Agent适配多种输出;
- The clearer the field descriptions, the more stable the output.
