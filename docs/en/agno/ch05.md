# Chapter 5 · Structured output output_schema

> Chapter goals：让 Agent 的输出从"free-form text"变成"经过validation的 Pydantic objects"，Master output_schema 的用法、原理与design tips。

## 5.1 free-form text的pain points

假设你要做一个"movie recommendation Agent"，让下游代码读取推荐结果。如果模型返回一段prose，你就得写regex或 `json.loads` 去parse——模型偶尔少个引号、多个解释性文字，程序直接崩。**Structured output**把这个问题completely eliminate：你定义data structure，模型负责fill，框架负责validation。

## 5.2 basic usage：output_schema + Pydantic

```python
# structured_basic.py —— 让 Agent 返回 Pydantic objects
import os
from dotenv import load_dotenv
from pydantic import BaseModel, Field
from agno.agent import Agent
from agno.models.openai import OpenAIChat

load_dotenv()

class MovieScript(BaseModel):
    setting: str = Field(description="故事发生的地点")
    genre: str = Field(description="电影类型")
    storyline: str = Field(description="三句话以内的剧情梗概")

agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    output_schema=MovieScript,     # 关键：声明输出结构
)

response = agent.run("写一个发生在东京的抢劫电影创意")

print(type(response.content))          # <class 'MovieScript'>，不是字符串！
print(response.content.setting)        # 直接用属性访问
print(response.content.genre)
print(response.content.storyline)
```

`response.content` 直接就是 `MovieScript` 实例——字段访问有类型提示、IDE 自动补全、拼错字段名立刻报错。

## 5.3 underlying principles：schema injection与validation回退

Understand原理才能排查问题。设置 `output_schema` 后 Agno 做了四件事：

1. 把 Pydantic 模型转成 **JSON Schema**；
2. 若模型支持原生Structured outputprotocol（如 OpenAI 的 JSON Schema 模式），直接deliver constraints；
3. 不支持时，把 schema 写进prompt并要求模型输出 JSON，再parse；
4. 用 Pydantic **validation**parse结果，失败则记录错误——此时 `content` 可能degrade为原始字符串。

::: warning 必须做的defense
DeepSeek 等third-party models走的多是"prompt + parse"路径，偶发parse失败。官方文档明确建议：**访问 schema 字段前先检查 `content` 的类型**。

```python
# safe_access.py —— 类型defense
result = agent.run("再写一个太空歌剧创意")
if isinstance(result.content, MovieScript):
    print("结构化成功:", result.content.genre)
else:
    print("parse失败，原始内容:", result.content)   # 降级处理
```
:::

## 5.4 进阶：nested models、list fields与per-call override

真实业务的输出结构往往嵌套。Pydantic 的composition capability在这里完全可用：

```python
# structured_nested.py —— 嵌套结构与运行时覆盖
from pydantic import BaseModel, Field
from agno.agent import Agent
from agno.models.openai import OpenAIChat
import os
from dotenv import load_dotenv

load_dotenv()
model = OpenAIChat(
    id="deepseek-chat",
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    base_url="https://api.deepseek.com/v1",
)

class Ingredient(BaseModel):
    name: str = Field(description="食材名")
    amount: str = Field(description="用量，如 200g")

class Recipe(BaseModel):
    title: str
    difficulty: str = Field(description="简单/中等/困难 三选一")
    ingredients: list[Ingredient] = Field(description="食材清单")   # nested lists
    steps: list[str] = Field(description="步骤列表")

agent = Agent(model=model)   # 构造时不指定 schema

# 同一个 Agent 按次指定不同 schema —— 一个 Agent 服务多种输出格式
recipe = agent.run("设计一道 20 分钟完成的番茄牛腩", output_schema=Recipe).content
print(recipe.title, "共", len(recipe.ingredients), "种食材")
for ing in recipe.ingredients:
    print(f"- {ing.name}: {ing.amount}")
```

per-call override（`run(..., output_schema=...)`）非常适合"一个 Agent multiple tasks"的场景，避免为每种输出格式clone一个 Agent。

## 5.5 与手写parse的对比 + 与工具结合

对比一下旧式手写parse，你就明白Structured output的value：

```python
# old_way.py —— 反面教材：手写 JSON parse
import json

resp = agent.run("以 JSON 格式返回菜谱，字段包括 title、ingredients、steps")
try:
    # 模型经常在 JSON 外面套一句"好的，以下是..."，直接炸
    data = json.loads(resp.content)
except json.JSONDecodeError as e:
    print("parse失败，需要手写清洗逻辑：", e)
    # 于是你开始 strip 反引号、regex截取 {...}、重试...
```

Structured output还支持与工具coexist：Agent 先调工具取数据，最后按 schema 组织答案。官方示例是股票分析——工具查实时股价，`StockAnalysis` 模型约束最终结论的字段。这个"**free process、constrained conclusions**"的模式是production-grade Agent 的常用架构。

## 5.6 Schema design tips

结合官方建议，四条实战经验：

1. **每个字段都写 `Field(description=...)`**——描述就是给模型的需求说明，越具体越稳定；
2. **用约束表达enumeration**：`Field(description="必须为 buy/hold/sell 之一")` 或 `Literal["buy", "hold", "sell"]`；
3. **numeric range用 `ge/le`**：如 `confidence: float = Field(ge=0, le=1)`，validation层自动intercept越界值；
4. **避免overly deep nesting**（建议 ≤3 层）：层数越深，third-party models的format error rate越高。

## 5.7 本章小结

- `output_schema` 让 `content` 从字符串变成validation过的 Pydantic objects；
- 原理是"JSON Schema 下发 → 生成 → Pydantic validation"，third-party models可能回退为promptparse；
- 访问字段前用 `isinstance` defenseparse失败的情况；
- schema 可以构造时不给、运行时按次传入，一个 Agent 适配多种输出；
- 字段描述写得越清楚，输出越稳定。
