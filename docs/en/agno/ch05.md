# Chapter 5 · Structured Output (output_schema)

> Chapter goals: change the Agent's output from "free text" to "validated Pydantic objects," master the usage, principles and design techniques of output_schema.

## 5.1 The Pain Points of Free Text

Suppose you want to build a "movie recommendation Agent" for downstream code to read recommendation results. If the model returns a prose paragraph, you have to write regex or `json.loads` to parse it — the model occasionally misses a quote or adds explanatory text, and the program crashes directly. **Structured output** completely eliminates this problem: you define the data structure, the model fills it in, and the framework validates it.

## 5.2 Basic Usage: output_schema + Pydantic

```python
# structured_basic.py —— Make the Agent return a Pydantic object
import os
from dotenv import load_dotenv
from pydantic import BaseModel, Field
from agno.agent import Agent
from agno.models.openai import OpenAIChat

load_dotenv()

class MovieScript(BaseModel):
    setting: str = Field(description="Location where the story takes place")
    genre: str = Field(description="Movie genre")
    storyline: str = Field(description="Plot summary in three sentences or less")

agent = Agent(
    model=OpenAIChat(
        id="deepseek-chat",
        api_key=os.getenv("DEEPSEEK_API_KEY"),
        base_url="https://api.deepseek.com/v1",
    ),
    output_schema=MovieScript,     # Key: declare output structure
)

response = agent.run("Write a heist movie idea set in Tokyo")

print(type(response.content))          # <class 'MovieScript'>, not a string!
print(response.content.setting)        # Access directly with attributes
print(response.content.genre)
print(response.content.storyline)
```

`response.content` is directly a `MovieScript` instance — field access has type hints, IDE auto-completion, and typos in field names immediately.

## 5.3 Underlying Principles: Schema Injection and Validation Fallback

Understanding the principle helps troubleshoot. After setting `output_schema`, Agno does four things:

1. Convert the Pydantic model to a **JSON Schema**;
2. If the model supports native structured output protocols (such as OpenAI's JSON Schema mode), send constraints directly;
3. If not supported, write the schema into the prompt and require the model to output JSON, then parse;
4. Use Pydantic to **validate** the parsed result; on failure, log the error — at this point `content` may to the original string.

::: warning Mandatory Defense
Third-party models like DeepSeek mostly the "prompt + parsing" path, with occasional parsing failures. The official documentation explicitly recommends: **check the type of `content` before accessing schema fields**.

```python
# safe_access.py —— Type defense
result = agent.run("Write another space opera idea")
if isinstance(result.content, MovieScript):
    print("Structured success:", result.content.genre)
else:
    print("Parsing failed, raw content:", result.content)   # Degraded handling
```
:::

## 5.4 Advanced: Nested Models, List Fields and Per-call Override

Real business output structures are often nested. Pydantic's composition capabilities are fully available here:

```python
# structured_nested.py —— Nested structure and runtime override
from pydantic import BaseModel, Field
from agno.agent import Agent
from agno.models.openai import OpenAIChat
import os
from dotenv import load_dotenv

load_dotenv()
model = OpenAIChat(
    id="deepseek-chat",
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    base_url="https://api.deepseek.com/v1",
)

class Ingredient(BaseModel):
    name: str = Field(description="Ingredient name")
    amount: str = Field(description="Quantity, e.g., 200g")

class Recipe(BaseModel):
    title: str
    difficulty: str = Field(description="Choose one: easy/medium/hard")
    ingredients: list[Ingredient] = Field(description="Ingredient list")   # Nested list
    steps: list[str] = Field(description="Step list")

agent = Agent(model=model)   # Do not specify schema at construction

# Specify different schemas per call with the same Agent — one Agent serves multiple output formats
recipe = agent.run("Design a tomato beef dish that takes 20 minutes", output_schema=Recipe).content
print(recipe.title, "has", len(recipe.ingredients), "ingredients")
for ing in recipe.ingredients:
    print(f"- {ing.name}: {ing.amount}")
```

Per-call override (`run(..., output_schema=...)`) is very suitable for "one Agent, multiple tasks" scenarios, avoiding cloning an Agent for each output format.

## 5.5 Comparison with Hand-written Parsing + Integration with Tools

Compare with the old hand-written parsing approach, and you will understand the value of structured output:

```python
# old_way.py —— Negative example: hand-written JSON parsing
import json

resp = agent.run("Return the recipe in JSON format, with fields including title, ingredients, steps")
try:
    # The model often wraps a sentence like "Okay, here is..." around the JSON, causing direct炸
    data = json.loads(resp.content)
except json.JSONDecodeError as e:
    print("Parsing failed, need hand-written cleaning logic:", e)
    # So you start strip backticks, regex截取 {...}, retry...
```

Structured output also supports with tools: the Agent first calls tools to fetch data, then organizes the answer according to the schema. The official example is stock analysis — tools real-time stock prices, the `StockAnalysis` model constrains the fields of the final conclusion. This "**free process, constrained conclusion**" pattern is a architecture for production-grade Agents.

## 5.6 Schema Design Techniques

Combining official recommendations, four practical experiences:

1. **Write `Field(description=...)` for every field** — the description is the requirement explanation to the model; the more specific, the more stable;
2. **Use constraints to express enums**: `Field(description="Must be one of buy/hold/sell")` or `Literal["buy", "hold", "sell"]`;
3. **Use `ge/le` for value ranges**: e.g., `confidence: float = Field(ge=0, le=1)`; the validation layer automatically intercepts out-of-bounds values;
4. **Avoid deeply nested structures** (recommended ≤3 layers): the deeper the layers, the higher the format error rate for third-party models.

## 5.7 Chapter Summary

- `output_schema` changes `content` from a string to a validated Pydantic object;
- The principle is "JSON Schema sent → generated → Pydantic validated"; third-party models may to prompt parsing;
- Use `isinstance` todefense against parsing failures before accessing fields;
- Schema can be omitted at construction and passed per-call at runtime; one Agent adapts to multiple outputs;
- The clearer the field descriptions, the more stable the output.
