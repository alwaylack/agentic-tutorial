# Chapter 18 · Asynchronous API and FastAPI Integration Testing

> Chapter goals: master Playwright's async API (`async_api`), learn to write async E2E tests under pytest-asyncio, and combine browser testing with FastAPI apps into a complete end-to-end integration testing solution.

## 18.1 Sync vs Async: Two Parallel APIs

Playwright Python is one of the few automation libraries offering **two complete parallel API sets**:

- **Sync API**: `from playwright.sync_api import sync_playwright`, used throughout Chapters 1-17 of this course;
- **Async API**: `from playwright.async_api import async_playwright`, all methods return coroutines requiring `await`.

Both share the same underlying driver (communicate with browser process via pipe), features map one-to-one; the selection criterion is singular — **whether your app and test stack are sync or async**:

```python
# Sync version (what previous chapters have been using)
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.goto("https://example.com")
    print(page.title())
    browser.close()
```

```python
# Async version: same flow
import asyncio
from playwright.async_api import async_playwright

async def main():
    async with async_playwright() as p:
        browser = await p.chromium.launch()
        page = await browser.new_page()
        await page.goto("https://example.com")
        print(await page.title())
        await browser.close()

asyncio.run(main())
```

::: tip Naming Pattern
Async API class and method names nearly identical to sync API; differences are only three: entry from `sync_playwright()` to `async_playwright()`; every I/O-producing method prefixed with `await`; assertions from `playwright.sync_api.expect` to `playwright.async_api.expect` (async expect accepts coroutines and auto-waits).
:::

## 18.2 async def Tests and pytest-asyncio

pytest itself doesn't support coroutine test functions; need the **pytest-asyncio** plugin. And `pytest-playwright` plugin's default-provided `page` fixture is sync — for async scenarios use Playwright's built-in async fixture system:

```bash
pip install pytest-playwright pytest-asyncio
```

```python
# test_async_demo.py
import pytest
from playwright.async_api import Page, expect

@pytest.mark.asyncio
async def test_title_is_async(page: Page):
    # pytest-playwright provides async page fixture simultaneously;
    # injected under asyncio marker is the async Page version
    await page.goto("https://playwright.dev/")
    await expect(page).to_have_title("Fast and reliable end-to-end testing")
```

Key points:

- Under async fixtures, `page.goto()`, `locator.click()`, etc. **must all be awaited**;
- `expect(page)` from `playwright.async_api`, its `to_have_title` and other assertions are also auto-retrying web-first assertions;
- If you forget await, what you often get isn't an error but **an unconsumed coroutine object** — the operation never executed, subsequent assertions fail with "element not found." This is the most common pitfall in async E2E.

## 18.3 Async API Difference Checklist

Besides "await everywhere," a few easy-to-miss differences:

| Scenario | Sync | Async |
|---|---|---|
| Wait for navigation | `page.click("...")` | `await page.click("...")` |
| Get text | `page.locator("h1").inner_text()` | `await page.locator("h1").inner_text()` |
| Event listener callback | plain `def handler(x)` | `def handler(x)` or `async def` both fine |
| `expect_event` | `with page.expect_event("popup") as pi:` | `async with page.expect_event("popup") as pi:` |
| Multi-task concurrency | N/A | `await asyncio.gather(task1(), task2())` |

```python
import pytest
from playwright.async_api import Page, expect

@pytest.mark.asyncio
async def test_popup_with_expect_event(page: Page):
    await page.goto("https://example.com")  # page has target=_blank links

    # Async context manager: start listening on enter, get result on exit
    async with page.expect_event("popup") as popup_info:
        await page.get_by_role("link", name="open").click()
    popup = await popup_info.value
    await expect(popup.get_by_role("heading")).to_be_visible()
```

## 18.4 Combining httpx.AsyncClient with FastAPI Integration Testing

The greatest value of async stacks: **both browser and API calls in the same event loop**. Typical scenario: "E2E operations on page + direct backend API calls to prepare/verify data":

```python
# conftest.py —— start a real uvicorn service for E2E use
import pytest
import uvicorn
from multiprocessing import Process

@pytest.fixture(scope="session")
def fastapi_server():
    """Start a real FastAPI service in a subprocess"""
    from myapp.main import app  # your FastAPI application

    proc = Process(target=uvicorn.run, args=(app,),
                   kwargs={"host": "127.0.0.1", "port": 8000, "log_level": "warning"},
                   daemon=True)
    proc.start()
    import httpx
    # Poll until service ready
    for _ in range(50):
        try:
            if httpx.get("http://127.0.0.1:8000/healthz").status_code == 200:
                break
        except Exception:
            pass
    yield "http://127.0.0.1:8000"
    proc.terminate()
```

```python
# test_fastapi_e2e.py —— browser + API dual-channel verification
import pytest
from playwright.async_api import Page, expect

BASE = "http://127.0.0.1:8000"

@pytest.mark.asyncio
async def test_create_item_via_ui_verify_via_api(
    page: Page, fastapi_server
):
    from httpx import AsyncClient

    # 1) Create data via UI
    await page.goto(f"{BASE}/items/new")
    await page.get_by_label("Name").fill("Mechanical Keyboard")
    await page.get_by_role("button", name="Submit").click()
    await expect(page.get_by_role("alert")).to_contain_text("Created successfully")

    # 2) Bypass UI, directly verify data actually persisted via API
    async with AsyncClient(base_url=BASE) as client:
        resp = await client.get("/api/items", params={"q": "Mechanical Keyboard"})
        assert resp.status_code == 200
        assert any(i["name"] == "Mechanical Keyboard" for i in resp.json()["items"])
```

This "UI write + API verify" combo is faster and more stable than pure UI assertions — data correctness handed to API assertions, UI only verifies interaction flows.

::: warning Event Loop Conflict Warning
Don't `uvicorn.run()` then `asyncio.run()` test in the same process: uvicorn will try to create its own event loop conflicting with pytest-asyncio. The example above starts the service in a **subprocess** to avoid this — the safest approach.
:::

## 18.5 Chapter Summary

- Playwright provides parallel sync/async dual APIs, method names consistent, async versions everywhere `await`;
- Async tests use `@pytest.mark.asyncio` + `Page`/`expect` from `playwright.async_api`;
- Typical symptom of forgetting `await` is "operation not executed, assertions inexplicably fail" rather than explicit errors;
- Start uvicorn in subprocess to provide E2E backend, pair with `httpx.AsyncClient` for "UI write + API verify" dual-channel testing.
