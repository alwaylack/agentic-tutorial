# Chapter 16 · CI Integration and Docker

> Chapter goals: run E2E suites in GitHub Actions, use official containers for environment consistency, and automatically retain trace diagnostic artifacts on failure.

## 16.1 CI Three-Step Process

The official CI integration summarized in three steps:

1. **Let CI machines run browsers** — on Linux use official Docker images, or install system dependencies via CLI;
2. **Install Playwright** — `pip install playwright && playwright install --with-deps`;
3. **Run tests** — `pytest`.

`--with-deps` installs OS-level dependency libraries (libnss3, etc.) along the way; omitting it is the #1 reason for "works locally, CI reports missing libraries."

## 16.2 GitHub Actions Basic Workflow

Official example workflow (Python version):

```yaml
# .github/workflows/playwright.yml
name: Playwright Tests
on:
  push:
    branches: [main, master]
  pull_request:
    branches: [main, master]

jobs:
  test:
    timeout-minutes: 60
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6

      - name: Set up Python
        uses: actions/setup-python@v6
        with:
          python-version: "3.13"

      - name: Install dependencies
        run: |
          python -m pip install --upgrade pip
          pip install -r requirements.txt

      - name: Ensure browsers are installed
        run: python -m playwright install --with-deps

      - name: Run your tests
        run: pytest --tracing=retain-on-failure   # retain trace on failure

      - name: Upload traces                       # upload artifacts regardless of pass/fail
        uses: actions/upload-artifact@v5
        if: ${{ !cancelled() }}
        with:
          name: playwright-traces
          path: test-results/
```

Two details worth pondering:

- **`--tracing=retain-on-failure`** is a pytest-playwright provided switch: only failed cases persist traces, successful ones don't waste space;
- Upload artifacts' `if: ${{ !cancelled() }}` ensures **even when tests fail and the workflow is marked failed, traces still get uploaded** — otherwise you'd only see red X marks without evidence.

## 16.3 Official Containers for Consistent Environments

Host environment drift (fonts, timezones, dependency versions) causes screenshot assertions to fail inexplicably. Official image `mcr.microsoft.com/playwright/python` has all browsers and system dependencies built in — run the job directly in the container:

```yaml
jobs:
  playwright:
    timeout-minutes: 60
    runs-on: ubuntu-latest
    container:
      image: mcr.microsoft.com/playwright/python:v1.61.0-noble  # version must match installed playwright
      options: --user 1001                                       # non-root is safer
    steps:
      - uses: actions/checkout@v6
      - name: Install dependencies
        run: |
          python -m pip install --upgrade pip
          pip install -r local-requirements.txt
          pip install -e .
      - name: Run your tests
        run: pytest
```

::: warning Version Alignment
The Playwright version in the image tag must match the playwright major version you `pip install` (e.g., both 1.61/1.62); otherwise driver protocol mismatch throws executable not found or protocol errors. Images contain only browsers, not Python packages — `pip install playwright` still required.
:::

### Speed Up: Two-Layer Caching

- **pip cache**: `actions/setup-python` has built-in `cache: pip`;
- **Browser cache**: for non-container solutions, cache `~/.cache/ms-playwright` directory, key including playwright version — hit skips 100+ MB downloads.

## 16.4 Local Docker Run Essentials

For manual debugging in containers (or self-hosted runners), remember three official recommended parameters:

```bash
# E2E tests are trusted code, can run as root (Chromium auto-disables sandbox under root)
docker run -it --rm --init --ipc=host \
  mcr.microsoft.com/playwright/python:v1.61.0-noble /bin/bash

# Crawling untrusted sites: use independent user + seccomp config to enable sandbox
docker run -it --rm --ipc=host \
  --user pwuser \
  --security-opt seccomp=seccomp_profile.json \
  mcr.microsoft.com/playwright/python:v1.61.0-noble /bin/bash
```

- **`--ipc=host`**: Chromium's shared memory demand is large; the default 64MB IPC partition causes random OOM crashes — this is the most classic pitfall running Chromium in Docker;
- **`--init`**: avoids zombie processes from PID=1 process special handling;
- **`--cap-add=SYS_ADMIN`**: add locally during development if encountering strange startup errors to investigate (sandbox permission issues).

## 16.5 Complete Failure Diagnostic Loop

One failed case in CI, the ideal information chain:

```text
JUnit/terminal output(which case failed) → HTML report(step screenshots) → trace.zip(stepwise replay+network+console)
```

pytest-side corresponding outputs:

```bash
pytest \
  --junitxml=results/report.xml \      # CI system aggregates display
  --html=results/report.html \         # pytest-html plugin: static report with per-step screenshots
  --screenshot=only-on-failure \       # pytest-playwright: failure screenshots to test-results/
  --video=retain-on-failure \          # failure video
  --tracing=retain-on-failure          # failure trace (open Trace Viewer from Chapter 11)
```

Distinguish: Node Playwright has a built-in HTML Reporter; the Python/pytest ecosystem's HTML report comes from the third-party `pytest-html` plugin, while `--tracing/--video/--screenshot` are pytest-playwright plugin options — they have different responsibilities and are often used together.

## 16.6 Chapter Summary

- CI three steps: install browser deps → install Playwright → `pytest`; don't skip `install --with-deps`;
- Official container images ensure environment consistency, tag version must align with pip package; inside containers remember `--ipc=host` and `--init`;
- `--tracing=retain-on-failure` + `upload-artifact(if: !cancelled())` form the failure取证闭环;
- Python ecosystem's HTML reports come from pytest-html; trace is the strongest evidence.
