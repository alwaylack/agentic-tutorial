# Chapter 20 · Accessibility Testing and Aria Snapshot

> Chapter goals: understand the data source and YAML syntax of aria snapshots, learn to assert page accessibility structure with `to_match_aria_snapshot()`, and integrate accessibility checks into daily testing and CI.

## 20.1 Why Accessibility Testing Deserves Automation

Accessibility (a11y) is not "icing on the cake": it directly impacts whether screen reader users can use the product, and increasingly is a compliance requirement across more regions. More importantly, **pages friendly to machines are often friendlier to humans too** — a button without correct role and accessible name is equally disastrous for test automation.

Traditional a11y audit tools (like axe) scan for "whether violations exist"; Playwright offers another complementary perspective: **snapshot the page's accessibility tree as a structural contract to assert** — semantics wrong, tests turn red.

## 20.2 Getting to Know Aria Snapshot: YAML-Formed Accessibility Tree

Aria snapshot is Playwright's **YAML representation** of an element/page's accessibility tree, available since v1.49. Each node describes one accessible element:

```text
- role "name" [attribute=value]
```

- `role`: ARIA or HTML implicit role, e.g., `heading`, `button`, `listitem`;
- `"name"`: accessible name (exact string; `/regex/` denotes pattern matching);
- `[attribute=value]`: state attributes like `checked`, `disabled`, `expanded`, `level`, `pressed`, `selected`.

View the current page's snapshot directly in code:

```python
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.goto("https://playwright.dev/python/docs/intro")
    # Print the entire sidebar's accessibility structure (YAML string)
    print(page.get_by_role("navigation").aria_snapshot())
    browser.close()
```

Output looks like:

```yaml
- navigation "Docs":
  - list:
    - listitem:
      - link "Intro"
    - listitem:
      - link "Writing tests"
```

Indentation expresses hierarchical nesting — this is the world screen readers "see."

## 20.3 to_match_aria_snapshot(): Structural Assertions

The core assertion is `expect(page).to_match_aria_snapshot()` (whole page) or `expect(locator).to_match_aria_snapshot()` (local area):

```python
from playwright.sync_api import expect

def test_heading_structure(page):
    page.goto("https://example.com")

    # Whole-page assertion: heading hierarchy correct
    expect(page).to_match_aria_snapshot("""
      - heading "Example Domain"
      - paragraph
    """)

def test_nav_structure(page):
    page.goto("https://example.com")

    # Local assertion: only care about nav area, with [level] attribute validation
    expect(page.get_by_role("contentinfo")).to_match_aria_snapshot("""
      - contentinfo:
        - link /更多/
    """)
```

Four key matching rules, all from official docs:

1. **Case sensitive**, but whitespace collapses (indentation and newlines don't affect comparison);
2. **Order sensitive**: node order in template must match actual tree exactly;
3. **Partial matching supported**: omit names or attributes to only validate cared-about parts;
4. `/pattern/` syntax supports regex names, suitable for dynamic text.

## 20.4 Guarding Document Outlines with level Attribute

Heading hierarchy confusion is one of the most common a11y issues (e.g., jumping from `h1` directly to `h4` for visual effect). Use `[level=N]` to turn it into a hard CI constraint:

```python
def test_article_outline(page):
    page.goto("https://blog.example.com/post/1")

    # Article body's outline must be h2 → h3 two-level structure
    expect(page.get_by_role("article")).to_match_aria_snapshot("""
      - article:
        - heading "Overview" [level=2]
        - paragraph
        - heading "Installation Steps" [level=2]
        - list:
          - listitem: Install Python
          - listitem: Install dependencies
        - heading "FAQ" [level=3]
    """)
```

The moment someone changes `h3` to `div class="title"` or skips to `h4` for styling, this test immediately fails and shows a diff.

## 20.5 Pairing with axe: Structural Assertions + Violation Scanning

`to_match_aria_snapshot` excels at guarding "structural intent," but doesn't check rule-class issues like contrast, duplicate ids —这正是 axe-core's strength. Together they form a complete a11y strategy:

```bash
pip install pytest-playwright axe-playwright-python
```

```python
from axe_playwright_python.sync_playwright import Axe

def test_no_axe_violations(page):
    page.goto("https://example.com")
    results = Axe().run(page)

    # Rule scanning: severe violations must be zero
    assert results.violations_count(0) == 0, results.report()
```

Division of labor recommendation:

| Tool | Excels At | Failure Output |
|---|---|---|
| `to_match_aria_snapshot` | Whether page semantic structure matches design intent | YAML diff, intuitively shows structural differences |
| axe scanning | Rule-library violations (contrast, missing labels, etc.) | Violation list with fix suggestions |

## 20.6 CI Integration Strategy

Running full a11y tests is noisy; recommend分级:

1. **Critical page structural assertions** (homepage, forms, navigation): run with every PR, use this chapter's snapshot assertions;
2. **axe full-site scans**: daily scheduled task runs once, produces trend reports rather than blocking PRs;
3. **Failure handling convention**: snapshot diffs are "destructive changes," must explicitly update templates in PR with rationale — this itself is an a11y review.

## 20.7 Chapter Summary

- Aria snapshot is the YAML representation of the accessibility tree, `locator.aria_snapshot` available since v1.49;
- Node syntax `- role "name" [attr=value]`, supports regex names and partial matching;
- `expect(locator).to_match_aria_snapshot()` case/order sensitive, whitespace collapsed;
- Using `[level=N]` to guard heading outlines is the most practical landing scenario;
- Structural assertions (Playwright) + rule scanning (axe) complementary, tiered execution in CI.
