# Chapter 14 · Page Object Model Design Pattern

> Chapter goals: use Page Object Model to consolidate selectors and page actions in one place, keeping the test suite maintainable even when pages are frequently redesigned.

## 14.1 What Problem POM Solves

Tests without POM look like this:

```python
def test_search_bad(page):
    page.goto("https://example.com")
    page.locator('[aria-label="Enter your search term"]').fill("playwright")
    page.locator('[aria-label="Enter your search term"]').press("Enter")
    assert page.locator(".results h2").first.inner_text() == "playwright"
```

The problem is obvious: selectors scattered across dozens of tests, frontend changes a class name once, and you need to globally search-replace ten places — and you might miss some. POM's answer is to **create a class for each page (or page area)**, encapsulating selectors and actions, so tests face only business semantics.

Official documentation's positioning of POM: *Page objects simplify test authoring by building high-level APIs aligned with the application domain, and simplify maintenance by consolidating element selectors in one place*.

## 14.2 Basic Implementation: Pages as Classes

The official standard pattern:

```python
# models/search.py
from playwright.sync_api import Page


class SearchPage:
    def __init__(self, page: Page):
        self.page = page
        # Selectors declared once in __init__
        self.search_term_input = page.locator('[aria-label="Enter your search term"]')

    def navigate(self):
        self.page.goto("https://bing.com")

    def search(self, text: str):
        self.search_term_input.fill(text)
        self.search_term_input.press("Enter")
```

Tests become immediately clean:

```python
# tests/test_search.py
from models.search import SearchPage


def test_search(page):
    search_page = SearchPage(page)
    search_page.navigate()
    search_page.search("playwright")
```

Three key design points:

1. **Locators lazily created in `__init__`**: `page.locator(...)` only creates a locator description, no DOM query yet; actual querying happens at action/assertion time. So selectors can be safely declared early, even before page navigation completes;
2. **Method names use business language**: `search("playwright")` not two bare `fill + press` operations;
3. **Page classes don't hold assertions**: assertions belong to tests (see 14.4 anti-patterns).

## 14.3 BasePage and Componentization

Multiple pages share navbars, footers, and Toast notifications — consolidate common capabilities with BasePage; reusable independent areas (navbar, cart popup) become **component objects**:

```python
# models/base.py
from playwright.sync_api import Page, expect


class BasePage:
    def __init__(self, page: Page):
        self.page = page

    def goto(self, path: str):
        self.page.goto(f"https://shop.example.com{path}")

    def toast(self):
        return self.page.get_by_role("alert")


class Navbar:  # Component object: not belonging to any one page
    def __init__(self, page: Page):
        self.page = page
        self.cart_badge = page.get_by_test_id("cart-count")

    def open_cart(self):
        self.page.get_by_role("link", name="Cart").click()


# models/home.py — page class composes components
from models.base import BasePage
from models.navbar import Navbar


class HomePage(BasePage):
    def __init__(self, page):
        super().__init__(page)
        self.navbar = Navbar(page)          # compositional reuse
        self.hero_title = page.get_by_role("heading", level=1)

    def open(self):
        self.goto("/")
```

Directory organization convention (works with pytest):

```text
tests/
├── conftest.py
├── models/          # or pages/: page and component objects
│   ├── base.py
│   ├── navbar.py
│   └── home.py
├── data/            # test data from Chapter 13
└── test_home.py
```

## 14.4 POM + pytest Fixture Injection

Let fixtures handle "constructing page objects," so tests skip imports entirely and switching is easier (e.g., changing environment domains):

```python
# conftest.py
import pytest
from playwright.sync_api import Page
from models.home import HomePage


@pytest.fixture
def home_page(page: Page) -> HomePage:
    return HomePage(page)
```

```python
# tests/test_home.py
from playwright.sync_api import expect


def test_hero_visible(home_page):
    home_page.open()
    expect(home_page.hero_title).to_be_visible()
```

## 14.5 Common Anti-Patterns

| Anti-pattern | Problem | Correct Approach |
|---|---|---|
| Writing `expect(...)` assertions in page classes | Assertion semantics buried in encapsulation, tests lose readability and flexibility | Page classes expose only locators/actions; assertions stay in tests |
| Writing `page.wait_for_timeout(3000)` in page classes | Hard waits slow down and are unreliable | Rely on Playwright's auto-wait and Web-First assertion retries |
| Wrapping entire site in one class | Giant class no one dares modify | One page/component per class, common parts lifted to BasePage |
| Page classes returning raw strings for test comparison | Bypasses auto-retry, flaky-prone | Return Locators, let `expect` retry assertions in tests |
| Business decisions in page classes (if logged in then...) | Test logic seeps into encapsulation, reusability collapses | Decisions stay in tests, page classes provide atomic actions |

::: tip One-line Principle
Page classes answer **"how to operate"** this page; tests answer **"what to verify"**.
:::

## 14.6 Chapter Summary

- POM consolidates selectors in one place; page redesigns only require changing one class;
- Locators lazily created in `__init__`, declaration order decoupled from page load order;
- BasePage handles common behavior, component objects handle cross-page reusable areas;
- Fixture-injected page objects keep tests minimal; assertions and waits never enter page classes.
